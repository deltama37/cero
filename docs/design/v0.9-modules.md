# 設計: v0.9 module と標準ライブラリ

## 目的

ADR-0011 のとおり、`import` と `pub`、module ごとの名前の解決、複数ファイルの読み込み、標準ライブラリ（`std/`）を追加する。

対象外にすること:

* 修飾した名前（`list.map`）、別名の import、再公開（re-export）
* 分割コンパイル、module ごとの出力のキャッシュ
* 構築子ごとの公開
* 非公開の型が公開する関数の型に現れることの検査

## 関連する ADR

* ADR-0004: 特殊化（プログラム全体で行う）
* ADR-0007: トップレベルの関数の型推論（module ごとに行う）
* ADR-0010: `List` / `Option` を標準ライブラリにする
* ADR-0011: 本書の決定

## 前提

`docs/design/v0.8-string.md` までが実装済みであること。実装は 2 つの単位に分け、この順に行う。

1. **フロントエンドと型検査**: `token`、`lexer`、`ast`、`parser`、`typecheck`
2. **IR 生成・ドライバ・標準ライブラリ**: `lower`、`driver`、`std`（新規）、`cli`、サンプル、E2E、`README.md`

単位 1 では、既存の `typecheck.Check` と `lower.Lower` と `driver.Compile` の動作を変えない（1 ファイルのプログラムはそのまま動く）。

## 単位 1: フロントエンドと型検査

### `internal/token` / `internal/lexer`

キーワード `import` と `pub` を追加する（`token.Import`、`token.Pub`）。`Kind.String()` は `'import'`、`'pub'`。

### `internal/ast`

```go
type File struct {
	Imports []*Import
	Types   []*TypeDecl
	Funcs   []*FuncDecl
}

// Import is `import "path"`.
type Import struct {
	Pos     diag.Pos // 'import'
	Path    string
	PathPos diag.Pos // the string literal
}

// FuncDecl と TypeDecl に追加:
//   Pub bool // declared with 'pub'
```

表示: `FormatFile` は先頭に各 import を `(import "std/list")` として並べる。`Pub` の関数は `(pub fn ...`、型は `(pub type ...` と表示する。

### `internal/parser`

```text
ParseFile:
    while cur == 'import':
        advance; 文字列リテラルを期待（でなければ "expected string literal, found X"）
        Imports に追加
    while cur != EOF:
        pub = false
        if cur == 'pub': pub = true; advance
        if cur == 'fn': FuncDecl（Pub = pub）
        else if cur == 'type': TypeDecl（Pub = pub）
        else if cur == 'import': error at cur "imports must come before declarations"
        else: 既存のエラー（pub の後なら "expected 'fn' or 'type' after 'pub', found X"）
```

module パスの妥当性は構文解析では検査しない（ドライバが検査する）。

### `internal/typecheck`

#### 公開する型と関数

```go
// Module is one source file of a program.
type Module struct {
	Path    string    // module path ("std/list", "syntax/ast"); the entry module's is its file name without ".cero"
	File    string    // file name used in error messages ("std/list.cero", "examples/app/main.cero")
	Ast     *ast.File
	Imports []*Module // the modules of Ast.Imports, in the same order
}

// CheckProgram type-checks mods, which are in dependency order: every module
// appears after the modules it imports, and the last one is the entry
// module. Errors are *diag.Error with File set to the module's File.
func CheckProgram(mods []*Module) (*Info, error)

// Check type-checks a program made of file alone. Errors have an empty File.
func Check(file *ast.File) (*Info, error) // CheckProgram([]*Module{{Path: "main", Ast: file}}) と同じで、File は空のまま
```

`Info` に追加:

```go
	Main *Symbol // the entry module's 'main'
	// FuncModule maps every top-level function declaration to its module.
	FuncModule map[*ast.FuncDecl]*Module
```

#### checker の構造の変更

module ごとに新しい `checker` を作る。`info` は全体で共有する。

```go
type checker struct {
	// ... 既存のフィールド（globals, datas, ctors は「この module の宣言と組み込み関数」だけを持つ）
	importedValues map[string]importedValue // 公開された関数と構築子
	importedDatas  map[string]importedData  // 公開された型
}

type importedValue struct {
	sym  *Symbol
	from *Module
}

type importedData struct {
	data *types.Data
	from *Module
}

// exports is what a module makes visible to its importers.
type exports struct {
	values map[string]*Symbol     // pub functions and the constructors of pub types
	datas  map[string]*types.Data // pub types
}
```

名前を引く場所はすべて次のメソッドを通す（既存の `c.globals[...]` / `c.datas[...]` / `c.ctors[...]` の読み出しを置き換える。書き込みと「この module の中の重複」の検査は今のまま自分の表だけを見る）。

```go
// lookupGlobal returns the module's own declaration or built-in named name,
// or else the imported one.
func (c *checker) lookupGlobal(name string) *Symbol
func (c *checker) lookupData(name string) *types.Data
func (c *checker) lookupCtor(name string) *types.Ctor // lookupGlobal が SymCtor ならその Ctor
```

置き換える箇所: 局所的な名前の後の `lookup`、`resolveType` の型名、`declareTypeParams` の「型と衝突」の検査、`checkBindable`、パターンの構築子、`inferScrutinee` / `solveMeta` の構築子。
`funcRefs`（ADR-0007）の `isFunc` は、この module の `SymFunc` だけを真にする（import した関数は型が決まっているので依存グラフに入れない）。

#### `CheckProgram` の流れ

```text
CheckProgram(mods):
    info = 新しい Info
    exp = map[*Module]*exports
    for each mod in mods:
        c = newChecker(info)            // globals に組み込み関数を登録（v0.8 と同じ）
        for i, imp in mod.Ast.Imports:
            dep = mod.Imports[i]
            if dep が同じ mod の前の import と同じ: error at imp.Pos "duplicate import '<imp.Path>'"
            for name, sym in exp[dep].values:
                if c.importedValues[name] exists with from != dep:
                    error at imp.Pos "'<name>' is imported from both '<prev.Path>' and '<dep.Path>'"
                c.importedValues[name] = {sym, dep}
            for name, data in exp[dep].datas: 同じ（型の名前について）
        err = c.checkModule(mod.Ast, isEntry = mod is the last)   // v0.8 の Check の本体
        if err: err.File = mod.File（Check から呼ばれたときは空のまま）; return
        exp[mod] = mod の Pub の関数の Symbol、Pub の型の Data とその構築子の Symbol
        info.FuncModule[d] = mod（mod のすべての FuncDecl）
        c.resolveInfo()
    info.Main = 最後の module の "main"
```

* `checkModule` は v0.8 の `Check` の本体（型の登録、構築子、関数のシグネチャ、推論、本体の検査）。`main` の検査（存在と型）は `isEntry` のときだけ行う。エントリ以外の module に `main` があってもよい（普通の関数）。
* 自分の宣言は import した名前を隠す。自分の宣言と import した名前の衝突はエラーにしない。組み込み関数との衝突は v0.8 のままエラー。
* import した値の名前を使ったとき、`Info.Uses` にはその Symbol（エクスポートした module の Symbol そのもの）を記録する。多相な関数・構築子なら v0.3 と同じくインスタンス化する。

* `lexer_test.go`: `import` と `pub` がキーワード。
* `parser_test.go`: import の列、`pub fn`、`pub type`、import が宣言の後（エラー）、`import` の後が文字列でない（エラー）、`pub` の後が `fn` / `type` でない（エラー）。`FormatFile` の期待値で確認する。
* `typecheck_test.go`（`TestCheckProgram`、新規）: テストの中で複数の module をソースから組み立てる小さなヘルパー（`parser.ParseFile` して `Module` を作り、`Imports` をつなぐ）を作る。
  * 成功: 公開した関数を呼ぶ、公開した型と構築子をパターンと型注釈で使う、多相な公開関数を 2 つの型で使う、型推論した公開関数（ADR-0007）を使う、2 段の import（`a` → `b` → `c` で、`a` は `b` だけを import して `b` の公開関数を使う）、自分の宣言が import した同名の関数を隠す（`Uses` が自分の Symbol）、2 つの import が同じ module を経由しても衝突しない（`a` が `b` と `c` を import し、`b` と `c` が `d` を import する）、エントリ以外の module の `main`。

## 単位 2: IR 生成・ドライバ・標準ライブラリ

### `internal/lower`

```go
// LowerProgram converts a type-checked program into an IR module. mods is
// the same slice passed to typecheck.CheckProgram.
func LowerProgram(mods []*typecheck.Module, info *typecheck.Info) *ir.Module

// Lower は LowerProgram([]*typecheck.Module{{Path: "main", Ast: file}}, info) と同じ（既存のテストのため残す）
```

* エントリ module（最後の要素）の型パラメータのない関数は、v0.8 と同じく宣言順にすべて出力する（既存のゴールデンが変わらないように、エントリ module だけのプログラムの関数の番号と順序は今と同じ）。
* エントリ以外の module の型パラメータのない関数は、最初に参照されたときに `ir.Func` を作り、本体の変換を特殊化と同じキューに入れる（`env` は nil）。参照されなければ出力しない。
* IR の関数の名前: エントリ module の関数は今のまま。それ以外の module の関数は `<module パス>.<名前>`（例: `std/list.length`、特殊化は `std/list.map[Int,Ptr]` のように今の規則の前に付ける）。
* `main` は `info.Main`。

### `std`（新規パッケージ、リポジトリの `std/`）

```go
// Package std embeds the Cero standard library (ADR-0011).
package std

import "embed"

// FS holds list.cero, option.cero, pair.cero and string.cero.
//
//go:embed *.cero
var FS embed.FS
```

module パス `std/X` は `FS` の `X.cero`。表示するファイル名は `std/X.cero`。

各ファイルの内容（すべての公開関数に型注釈を付ける。深いリストでもスタックを使い切らないように、リストをたどる関数は末尾再帰で書く。順序を保つ必要がある関数は、逆順に作ってから `reverse` する。非公開の補助関数は自由に置いてよい）:

`std/list.cero`

```text
pub type List[T] = | Nil | Cons(T, List[T])
pub fn length[T](xs: List[T]) -> Int
pub fn reverse[T](xs: List[T]) -> List[T]
pub fn map[T, U](xs: List[T], f: T -> U) -> List[U]
pub fn filter[T](xs: List[T], keep: T -> Bool) -> List[T]
pub fn foldl[T, A](xs: List[T], acc: A, f: (A, T) -> A) -> A
pub fn foldr[T, A](xs: List[T], acc: A, f: (T, A) -> A) -> A
pub fn append[T](xs: List[T], ys: List[T]) -> List[T]
pub fn concat[T](xss: List[List[T]]) -> List[T]
pub fn any[T](xs: List[T], p: T -> Bool) -> Bool
pub fn all[T](xs: List[T], p: T -> Bool) -> Bool
pub fn range(start: Int, end: Int) -> List[Int]        // [start, end)。start >= end なら Nil
pub fn sum(xs: List[Int]) -> Int
pub fn take[T](xs: List[T], n: Int) -> List[T]         // n <= 0 なら Nil、長さより大きければ全体
pub fn drop[T](xs: List[T], n: Int) -> List[T]
```

`std/option.cero`

```text
pub type Option[T] = | None | Some(T)
pub fn withDefault[T](o: Option[T], d: T) -> T
pub fn mapOption[T, U](o: Option[T], f: T -> U) -> Option[U]
pub fn andThen[T, U](o: Option[T], f: T -> Option[U]) -> Option[U]
pub fn isSome[T](o: Option[T]) -> Bool
pub fn isNone[T](o: Option[T]) -> Bool
```

`std/pair.cero`

```text
pub type Pair[A, B] = | Pair(A, B)
pub fn fst[A, B](p: Pair[A, B]) -> A
pub fn snd[A, B](p: Pair[A, B]) -> B
```

`std/string.cero`

```text
import "std/list"
pub fn join(xs: List[String], sep: String) -> String     // 空リストなら ""
pub fn startsWith(s: String, prefix: String) -> Bool
pub fn endsWith(s: String, suffix: String) -> Bool
pub fn isDigit(b: Int) -> Bool                          // '0'..'9'
pub fn isAlpha(b: Int) -> Bool                          // 'A'..'Z', 'a'..'z'
pub fn isSpace(b: Int) -> Bool                          // ' ', '\t', '\n', '\r'
```

型名と構築子名が同じ（`Pair`）でも、型の名前と値の名前は別の表なので衝突しない。型検査がこれを拒むなら報告する。

### `internal/driver`

```go
// Compile compiles the program whose entry module is filename with source
// src. Non-standard imports are read from disk relative to the directory of
// filename.
func Compile(filename string, src []byte) ([]byte, error) // CompileWith(filename, src, os.ReadFile)

// CompileWith is Compile with read used to read non-standard modules by
// file name.
func CompileWith(
	filename string,
	src []byte,
	read func(name string) ([]byte, error),
) ([]byte, error)
```

```text
CompileWith:
    mods, err = load(filename, src, read)
    info, err = typecheck.CheckProgram(mods)
    return wasm.Encode(lower.LowerProgram(mods, info))

load(filename, src, read):
    root = filepath.Dir(filename)
    entry = parse(src) → Module{Path: base(filename) から ".cero" を除いたもの, File: filename}
    byFile = map[file name]*Module; state = map[*Module]{visiting, done}; order = []
    visit(m):
        state[m] = visiting
        for each imp in m.Ast.Imports:
            p = imp.Path
            if !validPath(p): error at imp.PathPos "invalid module path '<p>'"（File = m.File）
            if p starts with "std/": file = p + ".cero"; bytes = std.FS.ReadFile(p の "std/" を除いた部分 + ".cero")
            else: file = filepath.Join(root, p + ".cero"); bytes = read(file)
            読めない: error at imp.PathPos "cannot find module '<p>'"（File = m.File）
            dep = byFile[file]（なければ parse して作る。構文エラーは File = file）
            file == filename（エントリ自身）も byFile にエントリを入れておくことで同じ module になる
            if state[dep] == visiting: error at imp.PathPos "import cycle: <循環する module パスを ' -> ' でつないだもの>"（File = m.File）
            if state[dep] 未訪問: visit(dep)
            m.Imports に dep を追加
        state[m] = done; order = append(order, m)
    visit(entry)
    return order        // 後順なので依存順で、最後がエントリ
validPath(p): "/" で区切った各要素が空でなく、[A-Za-z0-9_] だけからなる
```

循環のメッセージの例: `a` → `b` → `a` なら `import cycle: a -> b -> a`（エントリの module パスは `Path`）。

型検査のエラーは `CheckProgram` が `File` を付けるので、ドライバは付け直さない。構文エラーとドライバのエラーは上のとおり付ける。
