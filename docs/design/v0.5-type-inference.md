# 設計: v0.5 トップレベル関数の型推論

## 目的

ADR-0007 のとおり、トップレベルの関数の引数と戻り値の型注釈を省略できるようにし、
省略した型を、推論する関数の強連結成分ごとに単一化と一般化で決める。

対象外にすること:

* 推論した型を利用者に表示する手段
* 推論する関数の多相再帰（ADR-0007 で許さない）
* クロージャ、defaulting、明示的な型引数、type class
* IR 生成・WebAssembly バックエンドの変更（型検査が記録する情報で足りる）
* 複数エラーの報告

## 関連する ADR

* ADR-0004: 硬い型変数と単一化変数、特殊化、決まらない型引数のエラー
* ADR-0006: 型注釈の省略、一般化、単一化変数の名前
* ADR-0007: 本書の決定

## 前提

`docs/design/v0.4-*.md` が実装済みであること。本書は差分だけを書く。
1 つの実装単位（1 つのサブエージェント）で、構文解析・型検査・サンプル・E2E をまとめて実装する。

## `internal/ast`

* `FuncDecl.Result` のコメントを `// nil when omitted` にする。
* `Param.Type` のコメントを `// nil when omitted` にする（「FuncLit だけ」を消す）。
* `FormatFunc` は、`FormatType(d.Result)` の代わりに `formatOptType(d.Result)` を使う。
  例: `fn identity(x) { x }` は `(fn identity ((x _)) _ (block x))` になる（ブロックの表示は既存のまま）。

## `internal/parser`

`parseFuncDecl` を次のように変える。

```text
params = parseParamList(allowUntyped = true)
result = nil
if cur == '->':
    advance
    result = parseType()
body = parseBlock()
```

型パラメータと注釈の整合（`[T]` を宣言したのに注釈を省略した）は型検査で報告する（構文解析では報告しない）。

## `internal/typecheck`

### 用語

* 関数が**注釈つき**: `d.Result != nil` かつ、すべての `p.Type != nil`。
* それ以外は**推論する関数**。

### `deps.go`（新規）

```go
// funcRefs returns the names of top-level functions that body (with
// parameters params) refers to, in order of first occurrence and without
// duplicates. A name bound by a parameter, a let, a variable pattern, or a
// parameter of an anonymous function is local while it is in scope and is
// not reported. isFunc reports whether a name is a top-level function.
func funcRefs(
	params []*ast.Param,
	body *ast.BlockExpr,
	isFunc func(string) bool,
) []string

// sccs returns the strongly connected components of the graph whose nodes
// are 0..n-1 and whose edges are edges[i], using Tarjan's algorithm. Nodes
// are visited in increasing order and edges in slice order. A component is
// listed after every component it has an edge to, and the nodes in a
// component are sorted in increasing order.
func sccs(n int, edges [][]int) [][]int
```

`funcRefs` のスコープの規則は型検査と同じにする。

```text
walk(e, scope):        // scope は名前の集合のスタック
    Ident:      if name が scope にない and isFunc(name): 追加
    Unary/Binary/Call/If: 子を walk
    Block:      push; 各 let について Value を walk してから Name を追加; Result を walk; pop
    FuncLit:    push; 各 Param.Name を追加; Body を walk; pop
    Match:      Scrutinee を walk; 各アームについて push; パターンの変数（VarPat の名前）を追加; Body を walk; pop
funcRefs: push; params の名前を追加; walk(body)
```

`let` の右辺は、その `let` の名前を追加する前に walk する（`let f = f` の右辺の `f` は外側を指す）。
構築子の名前は `isFunc` が偽を返すので数えない。

### `Check` の流れ（変更後）

```text
Check(file):

    // 1. シグネチャの登録（宣言順）
    for each d in file.Funcs:
        (構築子との衝突・重複の検査は v0.4 のまま)
        annotated = isAnnotated(d)

            error at d.TypeParams[0].Pos:

        if annotated:

    for each comp in sccs(len(inferred), edges):

    // 3. 注釈つきの関数の本体を宣言順に検査する（v0.4 のループと同じ）
    for each annotated d: (v0.4 と同じ)

    (main の検査は v0.4 のまま)
    c.resolveInfo()
```

### `checkComponent`

checker に次の状態を足す。

```go
type checker struct {
	// ... v0.4 のフィールド
	// comp holds the symbols of the inferred functions being checked
	// together, while checkComponent runs; nil otherwise. A reference to
	// one of them is not instantiated, and generalize leaves the metas in
	// their types alone.
	comp map[*Symbol]bool
	// compRefs records the references to symbols in comp, with the
	// function whose body contains each one.
	compRefs []compRef
}

type compRef struct {
	id    *ast.Ident
	sym   *Symbol // the referenced function
	owner *Symbol // the function whose body contains id
}
```

`pendingMeta` に `owner *Symbol`（その単一化変数を作ったときに本体を検査していたトップレベルの関数）を足す。
`newMeta` は `c.current`（検査中のトップレベルの関数の Symbol。checker に足す）を `owner` に入れる。

```text
checkComponent(decls):
    c.metas = nil; c.fresh = 0; c.comp = {}; c.compRefs = nil
    for each d in decls:
        sym = c.info.Funcs[d]
        sig = &types.Func{Params: len(d.Params)}
        c.current = sym
        for i, p in d.Params:
            if p.Type != nil: sig.Params[i] = resolveType(p.Type)   // c.tparams は nil
            else: sig.Params[i] = newMeta(freshName(), p.Pos,
                    "cannot infer the type of parameter '<p.Name>'; add a type annotation")
        if d.Result != nil: sig.Result = resolveType(d.Result)
        else: sig.Result = newMeta(freshName(), d.NamePos,
                    "cannot infer the result type of '<d.Name>'; add a type annotation")
        if d.Name == "main":
            if len(d.Params) > 0: error at sym.Pos "function 'main' must have type () -> Int, found <sig>"
            unify(sig.Result, Int) が失敗したら同じエラー
        sym.Type = sig
        c.comp[sym] = true
    for each d in decls:
        c.current = c.info.Funcs[d]
        checkFunc(&funcCtx{}, d.Params, sym.Type.(*types.Func), d.Body)
        // sig.Result は nil ではないので、checkFunc は expect を使う
    // 一般化（宣言順）
    for each d in decls:
        sym = c.info.Funcs[d]
        t, tps = generalizeTop(sym.Type)   // 下記
        sym.Type = t; sym.TypeParams = tps
    // 成分の中の参照の型引数
    for each r in c.compRefs:
        c.info.TypeArgs[r.id] = r.sym.TypeParams を []types.Type にしたもの（len 0 なら記録しない）
        for each tp in r.sym.TypeParams:
            if tp not in r.owner.TypeParams:
                error at r.id.Pos "cannot infer type argument '<tp.Name>' of '<r.sym.Name>'; add a type annotation"
    // 未解決・他の関数の型パラメータの検査
    for each pm in c.metas (作った順):
        if Prune(pm.meta) is *Meta: error at pm.pos pm.msg
        if Resolve(pm.meta) mentions a TypeParam of some sym in comp that is not in pm.owner.TypeParams:
            error at pm.pos pm.msg
    c.comp = nil; c.compRefs = nil; c.current = nil
```

`generalizeTop(t)` は、`types.Metas(t)` のすべてを、作った順ではなく `t` の中で最初に現れる順に `TypeParam{Name: m.Name}` へ解き、`(types.Resolve(t), tps)` を返す。メタがなければ `(types.Resolve(t), nil)`。
成分の中の別の関数と共有している単一化変数は、先に一般化した関数の型パラメータに解かれる。
後の関数の型にその型パラメータが現れるので、後の関数の `tps` には、`Metas` の代わりに「`t` に現れる、この成分で作った型パラメータ」も最初に現れる順で含める（重複なし）。
こうして、相互再帰する `f : t1 -> t1` と `g : t1 -> Int` は同じ `TypeParam` オブジェクトを共有する。

注釈つきの関数の検査（手順 3）でも、`c.current` をその関数の Symbol にし、`c.metas` の `owner` を埋める（エラーの判定には使わないが、値を一貫させる）。

### 参照（`inferIdent`）の変更

```text
inferIdent:
    (v0.4 のまま lookup、捕捉の検査、構築子の検査、c.info.Uses への記録)
    if c.comp[sym]:
        c.compRefs = append(c.compRefs, compRef{id: e, sym: sym, owner: c.current})
        return sym.Type          // インスタンス化しない
    return c.instantiate(sym, e)
```

推論する関数の `sym.Type` は、手順 2 で成分を検査する前は nil である。
依存順に検査するので、成分の外の推論する関数を参照するときには、その関数はすでに一般化済みで `sym.Type` は nil ではない。
`sym.Type == nil` の参照に出会ったら、型検査のバグとして `panic` する。

### let の一般化（`generalize`）の変更

`inEnv` に、`c.comp` のすべての Symbol の `types.Metas(sym.Type)` を加える。それ以外は v0.4 のまま。

### `resolveInfo` の変更

`c.info.Funcs` のすべての Symbol の `Type` を `types.Resolve` する。

### エラーの一覧（追加分）

| 条件 | 位置 | メッセージ |
| --- | --- | --- |
| 型パラメータを宣言した推論する関数 | 最初の型パラメータ | `function 'f' declares type parameters, so every parameter and its result need a type annotation` |
| 省略した引数の型が決まらない | 引数の名前 | `cannot infer the type of parameter 'x'; add a type annotation`（v0.4 と同じ文言） |
| 省略した戻り値の型が決まらない | 関数の名前 | `cannot infer the result type of 'f'; add a type annotation` |
| 成分の別の関数の型パラメータが参照から決まらない | 参照の位置 | `cannot infer type argument 't2' of 'g'; add a type annotation` |
| 推論する `main` に引数がある、または戻り値が `Int` と単一化できない | `main` の名前 | `function 'main' must have type () -> Int, found ...`（v0.1 と同じ文言） |

関数の引数と戻り値は一般化されるので、「決まらない」エラーは、本体の中でだけ使われる単一化変数に対して起きる。
上の 2 行目と 3 行目は、型が別の成分の関数の型パラメータに解かれた場合（他の関数の型パラメータの検査）で起きる。

| ケース | ソース（要約） | 期待 |
| --- | --- | --- |
| identity | `fn identity(x) { x }`、`main` で `identity(1)` | `identity : t1 -> t1`、TypeParams `[t1]` |
| 2 つの型で使う | `if identity(true) { identity(1) } else { 0 }` | 成功 |
| 引数の使い方から Int | `fn inc(x) { x + 1 }` | `(Int) -> Int`、TypeParams なし |
| 一部の注釈 | `fn f(x: Int, y) { y }` | `(Int, t1) -> t1` |
| 注釈つきの関数を呼ぶ | 推論する関数が `fn add(a: Int, b: Int) -> Int` を呼ぶ | 成功 |
| 注釈つきの関数から推論する関数を呼ぶ | 注釈つきの `main` から `identity` | 成功 |
| 宣言より前の関数を参照 | `main` が先、`identity` が後 | 成功 |
| 自己再帰 | `fn length(xs) { match xs { Nil => 0, Cons(_, r) => 1 + length(r) } }` | `(List[T]) -> Int`、TypeParams `[T]`、再帰の参照の `TypeArgs` が自身の型パラメータ |
| 相互再帰 | `isEven(n)` / `isOdd(n)` | 両方 `(Int) -> Bool` |
| 相互再帰で型パラメータを共有 | `fn f(x) { g(x) }`、`fn g(y) { f(y) }` | 片方を呼ぶ `main` で成功、`f` と `g` の TypeParams が同じオブジェクト |
| 高階関数 | `fn twice(f, x) { f(f(x)) }` | 型の形が `((a) -> a, a) -> a` |
| 成分の外の推論する関数を多相に使う | `fn pair(x) { identity(x) }` と `identity` を別の型で使う | 成功 |
| `main` の推論 | `fn main() { 42 }` | `() -> Int` |
| let の一般化が成分の型を一般化しない | `fn f(x) { let g = f; g(x) }` | 成功（`g` は単相） |

エラーケース（メッセージと位置）:

| ケース | 期待 |
| --- | --- |
| 型パラメータと省略 | `fn f[T](x) -> T { x }` → 型パラメータの位置で `declares type parameters` |
| 多相再帰 | `fn f(x) { if true { x } else { f(Cons(x, Nil)) ... } }` のように自身を別の型で呼ぶ → 単一化の失敗（`expected ..., found ...`） |
| 本体だけの未解決 | `fn f(x) { let n = length(Nil); x }`（`length` は注釈つきの多相関数）→ `cannot infer type argument 'T' of 'Nil'` |
| 他の関数の型パラメータ | ADR-0007 の `f` / `g` と `None` の例 → `cannot infer type argument 'T' of 'None'` |
| `main` に引数 | `fn main(x) { 1 }` → `function 'main' must have type () -> Int` |
| `main` の戻り値 | `fn main() { true }` → `expected Int, found Bool` または `main must have type` のどちらか（実装した結果を報告し、テストはそれに合わせる） |
| 引数の型の不一致 | `fn inc(x) { x + 1 }` を `inc(true)` で呼ぶ → `expected Int, found Bool` |

既存のテストは、トップレベルの型注釈の省略を構文エラーとして期待しているものがあれば、上と同じ方針で直す。
