# 設計: v0.2 フロントエンド（字句解析・AST・構文解析）

## 目的

ADR-0003 の `type` 宣言と `match` 式を、字句解析・AST・構文解析に追加する。

対象外にすること:

* 名前解決と型検査（`docs/design/v0.2-typecheck.md`）
* 構築子や型の名前の重複検査（型検査で行う）
* 構築子パターンの入れ子、負の整数パターン、型パラメータ（ADR-0003 で v0.2 の対象外）
* エラー回復（v0.1 と同じく最初のエラーで止まる）

## 関連する ADR

* ADR-0002: 具体構文、エラー報告の方針
* ADR-0003: `type` 宣言、`match` 式、パターン、予約語

## 前提

`docs/design/v0.1-frontend.md` の内容が実装済みであること。本書は v0.1 からの差分だけを書く。書いていない点は v0.1 の設計のままとする。

## `internal/token`

`Kind` の定数を次のように追加する。既存の定数の順序は変えず、各グループの末尾に足す。

```go
	// Keywords
	Fn    // fn
	Let   // let
	If    // if
	Else  // else
	True  // true
	False // false
	Type       // type
	Match      // match
	Underscore // _

	// Punctuation
	LParen   // (
	RParen   // )
	LBrace   // {
	RBrace   // }
	Comma    // ,
	Colon    // :
	Arrow    // ->
	Assign   // =
	FatArrow // =>
	Bar      // |
```

* `Kind.String()` は、追加した種類について `'type'`、`'match'`、`'_'`、`'=>'`、`'|'` を返す。
* `Keywords` に `"type": Type`、`"match": Match`、`"_": Underscore` を追加する。
  字句解析は識別子の文字列全体でキーワードを引くので、`_` 単独だけが `Underscore` になり、`_bar` や `__` は `Ident` のままになる。

## `internal/lexer`

* 2 文字の記号に `=>`（`FatArrow`）を追加する。`==` と同じく、1 文字の `=` より優先する。
* 1 文字の記号に `|`（`Bar`）を追加する。`||` は 2 文字の記号として先に読むので、`||` の扱いは変わらない。
* v0.1 の「単独の `|` は `unexpected character`」という規則はなくなる。単独の `&` はこれまでどおりエラーとする。

## `internal/ast`

### 追加する型

```go
// File is a Cero source file. Types and Funcs each keep source order.
type File struct {
	Types []*TypeDecl
	Funcs []*FuncDecl
}

// TypeDecl is a top-level algebraic data type declaration.
type TypeDecl struct {
	Pos     diag.Pos // 'type'
	Name    string
	NamePos diag.Pos
	Ctors   []*CtorDecl // at least one
}

// CtorDecl is one constructor of a TypeDecl. Fields is empty for a
// constructor written without parentheses.
type CtorDecl struct {
	Pos    diag.Pos // name
	Name   string
	Fields []TypeExpr
}

// MatchExpr is a match expression.
type MatchExpr struct {
	Pos       diag.Pos // 'match'
	Scrutinee Expr
	Arms      []*MatchArm // at least one
}

// MatchArm is one "pattern => body" arm.
type MatchArm struct {
	Pattern Pattern
	Body    Expr
}

// Pattern is a pattern in a match arm.
type Pattern interface {
	Position() diag.Pos
	pattern()
}

// WildcardPat is '_'.
type WildcardPat struct {
	Pos diag.Pos
}

// VarPat binds the matched value to Name. Name does not start with an
// uppercase ASCII letter.
type VarPat struct {
	Pos  diag.Pos
	Name string
}

// CtorPat matches values built with constructor Name. Name starts with an
// uppercase ASCII letter. Args is empty when written without parentheses;
// each element is a *VarPat or *WildcardPat.
type CtorPat struct {
	Pos  diag.Pos // name
	Name string
	Args []Pattern
}

// IntPat matches one non-negative integer.
type IntPat struct {
	Pos   diag.Pos
	Value int64
}

// BoolPat matches true or false.
type BoolPat struct {
	Pos   diag.Pos
	Value bool
}
```

* `MatchExpr` は `Expr` を実装する（`Position()` は `Pos`、マーカー `expr()`）。
* 5 つのパターン型は `Pattern` を実装する（`Position()` は `Pos`、マーカー `pattern()`）。すべてポインタレシーバとする。
* `MatchArm` と `TypeDecl`、`CtorDecl` は `Expr` でも `Pattern` でもない。
* `ast.go` 末尾のインターフェース実装の確認（`var _ Expr = ...`）に、追加した型を加える。

### S 式表示（`print.go`）

追加する関数:

```go
func FormatTypeDecl(d *TypeDecl) string
func FormatPattern(p Pattern) string
```

`FormatFile` は、`Types` の各要素を `FormatTypeDecl` で、続けて `Funcs` の各要素を `FormatFunc` で表示し、すべてを `"\n"` で連結する。

| ノード | 形式 | 例 |
| --- | --- | --- |
| `TypeDecl` | `(type NAME CTOR...)` | `(type IntList (Nil) (Cons Int IntList))` |
| `CtorDecl` | `(NAME FIELD...)` | `(Nil)`、`(Cons Int IntList)`、`(Box (-> (Int) Int))` |
| `MatchExpr` | `(match SCRUTINEE ARM...)` | `(match xs (=> Nil 0) (=> (Cons x _) x))` |
| `MatchArm` | `(=> PATTERN BODY)` | `(=> _ 0)` |
| `WildcardPat` | `_` | `_` |
| `VarPat` | 名前 | `x` |
| `CtorPat`（`Args` が空） | 名前 | `Nil` |
| `CtorPat`（`Args` あり） | `(NAME ARG...)` | `(Cons x _)` |
| `IntPat` | 10 進数 | `42` |
| `BoolPat` | `true` / `false` | `true` |

## `internal/parser`

公開 API（`ParseFile`、`ParseExpr`）のシグネチャは変えない。

### 文法

v0.1 の文法からの変更点だけを書く。

```text
file      = { typeDecl | funcDecl } EOF
typeDecl  = "type" IDENT "=" [ "|" ] ctorDecl { "|" ctorDecl }
ctorDecl  = IDENT [ "(" type { "," type } ")" ]
primary   = INT | "true" | "false" | IDENT | "(" expr ")"
          | ifExpr | block | funcLit | matchExpr
matchExpr = "match" expr "{" arm { "," arm } [ "," ] "}"
arm       = pattern "=>" expr
pattern   = "_" | INT | "true" | "false"
          | IDENT [ "(" subPat { "," subPat } ")" ]
subPat    = "_" | IDENT
```

`type` 宣言と `fn` 宣言は、任意の順に並べられる。それぞれ出現順に `File.Types` と `File.Funcs` に追加する。

### 大文字の判定

名前の先頭のバイトが `'A'` から `'Z'` のとき「大文字で始まる」とする（識別子は ASCII だけなので、先頭バイトで判定できる）。

```go
func isUpperName(name string) bool
```

### `type` 宣言

```text
parseTypeDecl():
    typeTok = expect "type"
    name = expect IDENT
    if !isUpperName(name): error at name.Pos "type name 'NAME' must start with an uppercase letter"
    expect "="
    if cur is "|": advance
    ctors = [parseCtorDecl()]
    while cur is "|": advance; ctors.append(parseCtorDecl())
    return TypeDecl{typeTok.Pos, name, name.Pos, ctors}

parseCtorDecl():
    name = expect IDENT
    if !isUpperName(name): error at name.Pos "constructor name 'NAME' must start with an uppercase letter"
    fields = []
    if cur is "(":
        advance
        fields.append(parseType())
        while cur is ",": advance; fields.append(parseType())
        expect ")"
    return CtorDecl{name.Pos, name, fields}
```

* `expect IDENT` が失敗したときは、v0.1 と同じ `expected identifier, found D` とする。
* `Nil()` のように空の括弧を書くと、`parseType` が `expected type, found ')'` を返す。
* 構築子のない `type T =` は、`parseCtorDecl` の `expect IDENT` で `expected identifier, found D` になる。

### `match` 式

```text
parseMatch():
    matchTok = expect "match"
    scrutinee = parseExpr()
    expect "{"
    arms = []
    loop:
        arms.append(parseArm())
        if cur is ",":
            advance
            if cur is "}": break
            continue
        if cur is "}": break
        error at cur "expected ',' or '}', found D"
    expect "}"
    return MatchExpr{matchTok.Pos, scrutinee, arms}

parseArm():
    pattern = parsePattern()
    expect "=>"
    body = parseExpr()
    return MatchArm{pattern, body}
```

* 照合対象は `parseExpr` で読む。`if` の条件式と同じく、式の直後の `{` はブロックの開始として扱われる。
* アームが 1 つもない `match x { }` は、`parsePattern` が `expected pattern, found '}'` を返す。

### パターン

```text
parsePattern():
    switch cur:
    case "_":     advance; return WildcardPat
    case INT:     advance; return IntPat (value by strconv.ParseInt)
    case "true":  advance; return BoolPat{true}
    case "false": advance; return BoolPat{false}
    case IDENT:
        name = cur; advance
        if !isUpperName(name): return VarPat
        args = []
        if cur is "(":
            advance
            args.append(parseSubPattern())
            while cur is ",": advance; args.append(parseSubPattern())
            expect ")"
        return CtorPat{name.Pos, name, args}
    default: error at cur "expected pattern, found D"

parseSubPattern():
    switch cur:
    case "_": advance; return WildcardPat
    case IDENT:
        if isUpperName(cur): error at cur "nested patterns are not supported in v0.2"
        advance; return VarPat
    case INT, "true", "false":
        error at cur "nested patterns are not supported in v0.2"
    default: error at cur "expected pattern, found D"
```

* `-1` のような負の整数は、`-` が `expected pattern, found '-'` になる。
* `Nil()` は、`parseSubPattern` が `expected pattern, found ')'` を返す。
* 小文字の名前の後に `(` が続く `x(y) => ...` は、`VarPat` を返した後の `expect "=>"` が `expected '=>', found '('` になる。

### トップレベル

```text
ParseFile:
    while cur is not EOF:
        if cur is "type": types.append(parseTypeDecl())
        else if cur is "fn": funcs.append(parseFuncDecl())
        else: error at cur "expected 'fn' or 'type', found D"
```

v0.1 の `expected 'fn', found D` は、このメッセージに置き換わる。

### エラーメッセージ（追加分）

| 状況 | メッセージ | 位置 |
| --- | --- | --- |
| トップレベルが `fn` でも `type` でもない | `expected 'fn' or 'type', found D` | 現在のトークン |
| 型名が大文字で始まらない | `type name 'NAME' must start with an uppercase letter` | 名前 |
| 構築子名が大文字で始まらない | `constructor name 'NAME' must start with an uppercase letter` | 名前 |
| アームの後が `,` でも `}` でもない | `expected ',' or '}', found D` | 現在のトークン |
| パターンが始まらない | `expected pattern, found D` | 現在のトークン |
| 構築子パターンの引数に構築子やリテラルを書いた | `nested patterns are not supported in v0.2` | そのトークン |

`D` は v0.1 の `describe(tok)` とする。

## テスト観点

すべてテーブル駆動で、各テストとサブテストで `t.Parallel()` を呼ぶ。既存のテストケースは、下に書いた変更を除いてそのまま通ること。

### `token`

* `Kind.String()`: `Type` → `'type'`、`Match` → `'match'`、`Underscore` → `'_'`、`FatArrow` → `'=>'`、`Bar` → `'|'`

### `lexer`

* 既存の「キーワードと識別子」のケースを `fn let if else true false type match _ foo _bar __ x1` に変える（`_` だけが `Underscore`、`_bar` と `__` は `Ident`）。
* 記号: `=> | = == || ->` が `FatArrow`、`Bar`、`Assign`、`Eq`、`OrOr`、`Arrow` になる。
* `a=>b` が `a`、`=>`、`b` になる。`a|b` が `a`、`|`、`b` になる。
* 既存の「lone bar」のエラーケース（`a | b` → `unexpected character '|'`）は削除し、`a | b` が `Ident`、`Bar`、`Ident` になる成功ケースに置き換える。
* 単独の `&` のエラーケースは残す。

### `ast`

* `FormatTypeDecl`、`FormatPattern`、`MatchExpr` の `FormatExpr` を、手組みの AST で確認する（表の各行）。
* `FormatFile` が型宣言を先に、関数を後に表示する。

### `parser`

`ParseExpr` と `ast.FormatExpr` を使う。

* `match x { 0 => 1, _ => 2 }` → `(match x (=> 0 1) (=> _ 2))`
* 末尾の `,` あり・なしが同じ結果になる
* アーム 1 つ: `match x { y => y }` → `(match x (=> y y))`
* 構築子パターン: `match xs { Nil => 0, Cons(x, _) => x }` → `(match xs (=> Nil 0) (=> (Cons x _) x))`
* 真偽値パターン: `match b { true => 1, false => 0 }`
* アームの本体が `match`、`if`、ブロック、二項演算の式
* 照合対象が関数呼び出し: `match f(x) { _ => 0 }` → `(match (call f x) (=> _ 0))`
* `match` が式の一部になる: `1 + match x { _ => 2 }` → `(+ 1 (match x (=> _ 2)))`
* 構築子の値: `Cons(1, Nil)` → `(call Cons 1 Nil)`（v0.1 と同じ呼び出しとして読む）

`ParseFile` と `ast.FormatFile` を使う。

* `type IntList = | Nil | Cons(Int, IntList)` → `(type IntList (Nil) (Cons Int IntList))`
* 先頭の `|` を省略: `type Shape = Circle(Int) | Rect(Int, Int)` → `(type Shape (Circle Int) (Rect Int Int))`
* 構築子 1 つ: `type Unit = Unit` → `(type Unit (Unit))`
* 関数型のフィールド: `type Box = Box(Int -> Int)` → `(type Box (Box (-> (Int) Int)))`
* 型宣言と関数宣言が混在する（`fn` → `type` → `fn` の順）: `Types` と `Funcs` がそれぞれ出現順になる
* 複数行にまたがる `type` 宣言と `match` 式（ADR-0003 の `area` と `sum` の例）

エラー（メッセージと位置を完全一致で比較）:

* 既存の `let x = 1`（トップレベル）→ `1:1: expected 'fn' or 'type', found 'let'` に変える
* 既存の `fn f() -> Int { 1 } }` → `1:21: expected 'fn' or 'type', found '}'` に変える
* `type shape = Circle` → `type name 'shape' must start with an uppercase letter`（`shape` の位置）
* `type Shape = circle` → `constructor name 'circle' must start with an uppercase letter`
* `type T =` → `expected identifier, found end of file`
* `type T = A()` → `expected type, found ')'`
* `type T = A | ` → `expected identifier, found end of file`
* `match x { }` → `expected pattern, found '}'`
* `match x { 0 => 1 1 => 2 }` → `expected ',' or '}', found integer literal 1`（2 つ目の `1` の位置）
* `match x { 0 1 }` → `expected '=>', found integer literal 1`
* `match x { -1 => 0 }` → `expected pattern, found '-'`
* `match x { Cons(Nil, _) => 0 }` → `nested patterns are not supported in v0.2`（`Nil` の位置）
* `match x { Cons(1, _) => 0 }` → `nested patterns are not supported in v0.2`（`1` の位置）
* `match x { Nil() => 0 }` → `expected pattern, found ')'`
* `match x { f(y) => 0 }` → `expected '=>', found '('`
* `match x { _ => 0 ,, }` → `expected pattern, found ','`
* `_` を式に書く: `_ + 1` → `expected expression, found '_'`
* `let _ = 1` を含むブロック → `expected identifier, found '_'`

## 完了条件

* 上記の変更とテストが存在し、`make check` が通る。
* 型検査・IR・WASM バックエンドのパッケージは変更しない。
  ただし、`ast.File` にフィールドを足したことでコンパイルが通らなくなる箇所があれば、その箇所だけを最小限に直す（`ast.File{Funcs: ...}` のような複合リテラルはそのままコンパイルできるはずである）。
* このフェーズの終了時点では、`type` や `match` を含むプログラムは型検査で `unhandled expression` などのエラーになってよい。
