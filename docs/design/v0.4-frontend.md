# 設計: v0.4 フロントエンド（匿名関数の型注釈の省略）

## 目的

ADR-0006 のとおり、匿名関数の引数の型注釈（`: 型`）と戻り値の型注釈（`-> 型`）を省略できるようにする。
トップレベルの関数の構文は変えない。

対象外にすること:

* 省略した型の推論（`docs/design/v0.4-typecheck.md`）
* トップレベルの関数の型注釈の省略（ADR-0006 で v0.5 に先送りした。構文エラーのまま）
* 字句解析とトークンの変更（不要）
* エラー回復（これまでと同じく最初のエラーで止まる）

## 関連する ADR

* ADR-0002: 具体構文、エラー報告の方針
* ADR-0006: 匿名関数の型注釈の省略

## 前提

`docs/design/v0.3-frontend.md` までの内容が実装済みであること。本書は差分だけを書く。

## 変更するパッケージとファイル

| パッケージ | ファイル | 内容 |
| --- | --- | --- |
| `internal/ast` | `ast.go`, `print.go`, `print_test.go` | 省略した型注釈を `nil` で表し、`_` と表示する |
| `internal/parser` | `parser.go`, `parser_test.go` | 匿名関数の引数と戻り値の型注釈を省略可能にする |

`internal/token`、`internal/lexer` は変更しない。外部依存は追加しない。

## `internal/ast`

### 型の変更

フィールドは増やさない。コメントだけを変える。

```go
// Param is a function parameter.
type Param struct {
	Pos  diag.Pos // name
	Name string
	Type TypeExpr // nil when omitted; only parameters of a FuncLit can omit it
}

// FuncLit is an anonymous function.
type FuncLit struct {
	Pos    diag.Pos // 'fn'
	Params []*Param
	Result TypeExpr // nil when omitted
	Body   *BlockExpr
}
```

`FuncDecl` の `Params[i].Type` と `Result` は、構文解析の結果としては必ず `nil` でない（構文解析がそう保証する）。

### 表示（`print.go`）

省略した型注釈は `_` と表示する。

| 対象 | v0.3 の表示 | v0.4 の表示（型注釈を省略したとき） |
| --- | --- | --- |
| 引数（`formatParam`） | `(x Int)` | `(x _)` |
| 匿名関数（`FormatExpr` の `*FuncLit`） | `(fn ((x Int)) Int (block x))` | `(fn ((x _)) _ (block x))` |

実装:

```go
func formatParam(param *Param) string {
	return "(" + param.Name + " " + formatOptType(param.Type) + ")"
}

// formatOptType formats t, or "_" when t is nil (an omitted annotation).
func formatOptType(t TypeExpr) string
```

* `formatOptType` は `t == nil` なら `"_"`、そうでなければ `FormatType(t)` を返す。
* `FormatExpr` の `*FuncLit` は、`FormatType(e.Result)` の代わりに `formatOptType(e.Result)` を使う。
* `FormatFunc` の結果の型は `FormatType(d.Result)` のままとする（`FuncDecl` の型注釈は省略されない）。
  `FormatFunc` が引数の表示に使う `formatParams` → `formatParam` は上記の変更を受けるが、`FuncDecl` の引数は型注釈を持つので表示は変わらない。
* `FormatType` 自体は変えない（`nil` を受け付けない）。

## `internal/parser`

### 文法の変更

```text
FuncLit    = "fn" LitParams [ "->" Type ] Block .
LitParams  = "(" [ LitParam { "," LitParam } ] ")" .
LitParam   = ident [ ":" Type ] .
```

`FuncDecl` の文法（`"fn" ident [TypeParams] Params "->" Type Block`、`Param = ident ":" Type`）は変えない。

### 実装

```go
func (p *parser) parseParamList(allowUntyped bool) ([]*ast.Param, error)

func (p *parser) parseParam(allowUntyped bool) (*ast.Param, error)
```

* `parseFuncDecl` は `parseParamList(false)`、`parseFuncLit` は `parseParamList(true)` を呼ぶ。`parseParamList` は受け取った値をそのまま `parseParam` に渡す。
* `parseParamList` のそれ以外の処理（空のリスト、`)` が来ないときのエラーなど）は変えない。

```text
parseParam(allowUntyped):
    cur が Ident でなければ v0.3 と同じエラー
    nameTok = cur; advance
    if allowUntyped and cur.Kind != Colon:
        return &Param{Pos: nameTok.Pos, Name: nameTok.Text, Type: nil}
    expect(Colon)              // v0.3 と同じエラー
    typ = parseType()
    return &Param{Pos: nameTok.Pos, Name: nameTok.Text, Type: typ}
```

```text
parseFuncLit():
    fnTok = cur; expect(Fn)
    params = parseParamList(true)
    var result ast.TypeExpr      // nil
    if cur.Kind == Arrow:
        advance
        result = parseType()
    body = parseBlock()          // '{' がなければ parseBlock の既存のエラー
    return &FuncLit{Pos: fnTok.Pos, Params: params, Result: result, Body: body}
```

* `allowUntyped` のとき、引数名の直後が `:` 以外（`,`、`)`、その他）なら型注釈の省略とみなす。
  `,` と `)` 以外のトークンが続く場合のエラーは、`parseParamList` の既存の処理（`)` を期待するエラー）に任せる。
* `-> 型` を省略した匿名関数で、`)` の後に `{` も `->` もなければ、`parseBlock` の `expected '{', found X` になる（v0.3 は `expected '->', found X` だった）。

## エラーの一覧（変更分）

| 入力 | v0.3 | v0.4 |
| --- | --- | --- |
| `fn(x) { x }`（式） | `expected ':', found ')'` | エラーにならない |
| `fn(x: Int) { x }`（式） | `expected '->', found '{'` | エラーにならない |
| `fn f() -> Int { fn(x) x }` | `expected ':', found ')'` | `1:23: expected '{', found identifier "x"` |
| `fn f(x) -> Int { x }`（トップレベル） | `1:7: expected ':', found ')'` | 変わらない |
| `fn f() { 1 }`（トップレベル） | `1:8: expected '->', found '{'` | 変わらない |

## テスト観点

テーブル駆動。各テストとサブテストで `t.Parallel()`。既存のテストはすべてそのまま通ること。

### `ast`（`print_test.go` の `TestFormat` にケースを追加）

| ケース | 入力 | 期待する表示 |
| --- | --- | --- |
| 型注釈のない引数と戻り値 | `FormatExpr(&FuncLit{Params: []*Param{{Name: "x"}}, Body: block(ident("x"))})` | `(fn ((x _)) _ (block x))` |
| 一部だけ型注釈のある引数 | `FormatExpr(&FuncLit{Params: []*Param{{Name: "x", Type: intType}, {Name: "y"}}, Result: intType, Body: block(ident("x"))})` | `(fn ((x Int) (y _)) Int (block x))` |

### `parser`

`TestParseExpr` に追加:

| ケース | 入力 | 期待する表示 |
| --- | --- | --- |
| func lit without annotations | `fn(x, y) { x }` | `(fn ((x _) (y _)) _ (block x))` |
| func lit partially annotated | `fn(x: Int, y) -> Int { x }` | `(fn ((x Int) (y _)) Int (block x))` |
| func lit without result type | `fn(x: Int) { x }` | `(fn ((x Int)) _ (block x))` |
| func lit without params or result type | `fn() { 1 }` | `(fn () _ (block 1))` |
| call an unannotated func lit argument | `f(fn(x) { x + 1 }, 2)` | `(call f (fn ((x _)) _ (block (+ x 1))) 2)` |

`TestParseError` に追加（メッセージと位置を完全一致で比較する）:

| ケース | 入力 | 期待するエラー |
| --- | --- | --- |
| func decl param without type | `fn f(x) -> Int { x }` | `1:7: expected ':', found ')'` |
| func decl without result type | `fn f() { 1 }` | `1:8: expected '->', found '{'` |
| func lit without body | `fn f() -> Int { fn(x) x }` | `1:23: expected '{', found identifier "x"` |
| func lit param followed by a type | `fn f() -> Int { fn(x Int) { x } }` | `1:22: expected ')', found identifier "Int"` |

最後のケースの位置は、`x` の直後の `Int`（22 列目）である。`parseParam` が型注釈の省略とみなして戻った後、`parseParamList` が `)` を期待して失敗する。

新しいテスト関数 `TestFuncLitOmittedTypes` を追加し、`FuncLit` の `Param.Type` と `Result` が `nil` であることを AST で直接確かめる。
既存の `TestTypeParamsAbsent` と同じく、1 つのソースを `ParseFile` で構文解析して中身を調べる形でよい（`t.Parallel()` は呼ぶ）。

* ソース: `fn main() -> Int { let f = fn(x, y: Int) { y } 0 }`
* `let` の値の `*ast.FuncLit` について:
  * `Params[0].Name == "x"`、`Params[0].Type == nil`、`Params[0].Pos == diag.Pos{Line: 1, Col: 31}`
  * `Params[1].Type` が `*ast.NamedType` で、`Name == "Int"`
  * `Result == nil`
* `main` の `FuncDecl` の `Result` が `nil` でない。

## 完了条件

* 上記の変更とテストが存在し、`make check` が通る。
* `internal/typecheck` 以降のパッケージは変更しない。
  このフェーズの終了時点では、型注釈を省略した匿名関数を含むプログラムの型検査は `panic` してよい（既存のテストは型注釈を省略しない）。
