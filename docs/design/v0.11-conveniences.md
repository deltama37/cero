# 設計: v0.11 コンパイラを書くための小さな拡張

## 目的

ADR-0013 のとおり、`%`、文字リテラル、ビット演算の組み込み関数、`let! x = e`、組み込み関数を隠すトップレベルの宣言、`let` のパターン、引数の `_` を追加する。

対象外にすること:

* ビット演算の演算子、文字の型
* `let! P = e`（パターンと `bind`）、`let` のパターンの一般化
* 汎用のモナドの仕組み（type class）

## 関連する ADR

* ADR-0009: パターン、usefulness
* ADR-0010: 組み込み関数、エスケープ
* ADR-0011: 名前の解決の優先順位
* ADR-0012: `bind`
* ADR-0013: 本書の決定

## 前提

`docs/design/v0.10-io.md` までが実装済みであること。1 つの実装単位で実装する。

## `internal/token` / `internal/lexer`

* `%` は `token.Percent`（表示 `'%'`）。
* 文字リテラル `'...'` は `token.Char`。`Token.Text` にはデコードした 1 バイトを入れる。`Token.Pos` は開きの `'`。
  エスケープは文字列リテラルと同じ（`\n`、`\t`、`\r`、`\\`、`\"`、`\0`、`\xHH`）に `\'` を加える。文字列リテラルでも `\'` を受け付ける。

| 条件 | 位置 | メッセージ |
| --- | --- | --- |
| 閉じの `'` の前に改行かファイルの終わり | 開きの `'` | `unterminated character literal` |
| デコードした結果が 0 バイト（`''`） | 開きの `'` | `empty character literal` |
| デコードした結果が 2 バイト以上（`'ab'`、`'é'`） | 開きの `'` | `character literal must be a single byte` |
| 未知のエスケープ | `\` | 文字列リテラルと同じ `invalid escape sequence '\q'` |

## `internal/parser`

### 式とパターン

* `%` は `*` / `/` と同じ優先順位: `parseLeft(p.parseUnary, token.Star, token.Slash, token.Percent)`。`BinaryExpr.Op` は `token.Percent`。
* 一次式の `token.Char` は `IntLit{Pos, Value: int64(Text[0])}`。パターンの `token.Char` は `IntPat{Pos, Value: int64(Text[0])}`。

### 引数の `_`

`parseParam` は、名前の位置の `token.Underscore` を受け付け、`Param{Name: "_"}` にする（型注釈の規則は名前のときと同じ）。トップレベルの関数と匿名関数の両方。

### ブロック

```text
parseBlock:
    '{'
    lets, result = parseBlockRest()
    '}'
    return BlockExpr{Pos: '{' の位置, Lets: lets, Result: result}

parseBlockRest():                      // '}' の直前まで読み、(lets, result) を返す
    lets = []
    while cur == 'let':
        letTok = cur; advance
        if cur == '!':                   // let! x = e / let! x: T = e / let! _ = e
            advance
            if cur が大文字で始まる識別子（構築子のパターン）: error at cur "patterns are not supported in 'let!'"
            name, namePos = 小文字で始まる識別子か '_'（どちらでもなければ "expected identifier, found X"）
            typ = ':' があれば parseType
            expect '='; value = parseExpr()
            restLets, restResult = parseBlockRest()
            body = BlockExpr{Pos: letTok.Pos, Lets: restLets, Result: restResult}
            lit = FuncLit{Pos: letTok.Pos, Params: [Param{Pos: namePos, Name: name, Type: typ}], Result: nil, Body: body}
            call = CallExpr{Pos: letTok.Pos, Fn: Ident{Pos: letTok.Pos, Name: "bind"}, LParen: letTok.Pos, Args: [value, lit]}
            return lets, call
        if cur is 小文字の識別子:        // v0.10 までの let
            lets = append(lets, 既存の parseLet の続き)
            continue
        // let のパターン
        pat = parsePattern()             // '_' / 構築子 / リテラル
        expect '='; value = parseExpr()
        restLets, restResult = parseBlockRest()
        body = BlockExpr{Pos: letTok.Pos, Lets: restLets, Result: restResult}（restLets が空なら restResult をそのまま本体にする）
        m = MatchExpr{Pos: letTok.Pos, Scrutinee: value, Arms: [MatchArm{Pattern: pat, Body: body}], Let: true}
        return lets, m
    result = parseExpr()
    return lets, result
```

* `let!` の本体のブロックは、後ろの `let` が 1 つもなくても `BlockExpr`（`Lets` は空）にする（匿名関数の本体はブロックである必要があるため）。
* `let` のパターンで `restLets` が空のときは、アームの本体を `restResult` にする（余分なブロックを作らない）。
* 既存の `parseLet` は、`let` の後が小文字の識別子の場合の処理として残す（エラーメッセージは変えない）。

## `internal/typecheck`

### 名前の解決と組み込み関数

* 組み込み関数を `c.globals` から別の表 `c.builtins` に移す。`lookupGlobal(name)` は、自分の宣言（`c.globals`）→ import した名前 → `c.builtins` の順に引く。
* v0.8 の「`function 'NAME' conflicts with built-in function 'NAME'`」と「`constructor ...`」のエラーを削除する。
* 組み込み関数に次を足す（`Builtin` の定数も同じ順に足す）。

| 名前 | 型 | `ir.PrimOp` |
| --- | --- | --- |
| `bitAnd` | `(Int, Int) -> Int` | `BitAnd` |
| `bitOr` | `(Int, Int) -> Int` | `BitOr` |
| `bitXor` | `(Int, Int) -> Int` | `BitXor` |
| `shiftLeft` | `(Int, Int) -> Int` | `ShiftLeft` |
| `shiftRight` | `(Int, Int) -> Int` | `ShiftRight` |
| `shiftRightUnsigned` | `(Int, Int) -> Int` | `ShiftRightUnsigned` |

### `%`

`+` などと同じく、両方のオペランドを `Int` として検査し、結果は `Int`。

### `let` のパターン

`inferMatch` で `m.Let` が真のとき、網羅性のエラーのメッセージを `refutable pattern in let: missing ...`（`missing` の後は v0.7 と同じ形式）にする。位置は `m.Pos`（`let` の位置）。到達不能なアームは起きない（アームが 1 つ）。

### 引数の `_`

`checkFunc` で、名前が `_` の引数は、Symbol を作って `Info.Params` に記録するが、スコープには入れず、重複の検査もしない。`checkBindable` も呼ばない。

### `funcRefs`（ADR-0007）と捕捉の解析（ADR-0008）

`_` の引数はスコープに入らないので、`deps.go` の名前の集合にも入れない（入れても参照されないので結果は同じ）。捕捉の解析は Symbol で行うので変更しない。

## `internal/ir` / `internal/lower` / `internal/wasm`

* `ir.BinOp` に `Rem`（`Int, Int -> Int`、表示 `rem`）。`lower` は `token.Percent` を `Rem` にする。`wasm` は `i64.rem_s`（`0x81`）。
* `ir.PrimOp` に `BitAnd`、`BitOr`、`BitXor`、`ShiftLeft`、`ShiftRight`、`ShiftRightUnsigned`（すべて `(Int, Int) -> Int`、表示 `int.and`、`int.or`、`int.xor`、`int.shl`、`int.shr_s`、`int.shr_u`）。
  `lower` は組み込み関数の呼び出しと `$ref` ラッパーを v0.8 と同じ規則で作る。`wasm` は補助関数を使わず、2 つの引数を積んでから `i64.and`（`0x83`）、`i64.or`（`0x84`）、`i64.xor`（`0x85`）、`i64.shl`（`0x86`）、`i64.shr_s`（`0x87`）、`i64.shr_u`（`0x88`）を出力する。

## `std/string.cero`

`isDigit`、`isAlpha`、`isSpace` の中のバイトの値を、文字リテラル（`'0'`、`'9'`、`' '`、`'\t'` など）で書き直す。公開する関数と動作は変えない。

## エラーケース

上の表の字句エラー、`let!` のエラー、`refutable pattern in let` 以外は、既存のエラーと同じ。
`let!` の右辺の型が `bind` の第 1 引数の型と合わない場合などは、書き換えた後の `bind` の呼び出しの型エラーとして、`let` の位置に報告される。

  * エラー: `let! Pair(a, b) = e`、`let!` の後に名前がない、`let!` の `=` がない。
* `typecheck_test.go`（`TestCheckConveniencesSuccess` / `TestCheckConveniencesError`）:
