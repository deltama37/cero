# 設計: v0.10 IO

## 目的

ADR-0012 のとおり、`Unit` と `()`、組み込みの型 `IO[T]`、IO の組み込み関数、`main: () -> IO[Unit]` の WASI コマンド、`std/io` を追加する。

対象外にすること:

* `bind` の糖衣構文
* ファイル操作の失敗を値で返す API、ディレクトリの操作、時刻、乱数、環境変数
* 出力のバッファリング（`print` 1 回が `fd_write` 1 回以上）
* Effect system

## 関連する ADR

* ADR-0001: 副作用、WASI
* ADR-0008: 関数値の表現（`IO[T]` の表現に使う）
* ADR-0010: 組み込み関数、String の表現
* ADR-0011: 標準ライブラリ
* ADR-0012: 本書の決定

## 前提

`docs/design/v0.9-modules.md` までが実装済みであること。実装は 2 つの単位に分け、この順に行う。

1. **フロントエンド**: `ast`、`parser`、`types`、`typecheck`
2. **バックエンドと実行**: `ir`、`lower`、`wasm`、`driver`、`cli`、`cmd/ceroc`、`std/io.cero`、サンプル、E2E、`README.md`

単位 1 の時点では、IO や `()` を使うプログラムを `lower` に渡すと `panic` してよい。

## 単位 1: フロントエンド

### `internal/ast` / `internal/parser`

```go
// UnitLit is `()`.
type UnitLit struct{ Pos diag.Pos } // '('
```

* 一次式で `(` の直後が `)` なら `UnitLit`（それ以外は今までどおり括弧の式）。表示は `()`。
* 型の `Unit` と `IO[T]` は既存の名前つきの型の構文（`NamedType`）で書ける。構文解析の変更は要らない。

### `internal/types`

```go
// UnitType is the built-in Unit type.
type UnitType struct{}

var Unit Type = UnitType{} // String() は "Unit"。Int と同じく葉として扱う

// IO is the built-in data type IO[T] (ADR-0012). It has no constructors.
var IO = &Data{Name: "IO", Params: []*TypeParam{{Name: "T"}}}

// IOOf returns IO[t].
func IOOf(t Type) Type

// IsIO reports whether t (after Prune) is IO applied to an argument.
func IsIO(t Type) bool
```

`unify` は `UnitType` 同士を等しいとする（`StringType` と同じ分岐を足す）。

### `internal/typecheck`

#### 型の名前

* `Unit` と `IO` を組み込みの型名に加える（`Int` / `Bool` / `String` と同じく、`type` 宣言・型パラメータの名前にできない）。
* `resolveType`: `Unit` は `types.Unit`（型引数があればエラー）。`IO` は型引数がちょうど 1 つ（でなければ既存の `wrong number of type arguments for 'IO': expected 1, found N`）で、`Named{Data: types.IO, Args: [arg]}`。

#### 式

* `UnitLit` の型は `Unit`。
* `==` / `!=` で比較できる型は `Int`、`Bool`、`String` のまま（`Unit` と `IO` は比較できない）。
* `match` の照合対象の型が `IO[...]` なら、関数と同じ `cannot match on values of type IO[...]` のエラーにする。

#### 組み込み関数

v0.8 の `Builtin` に次を足す。表の順に定数を並べ、`Check` の最初に登録する。

| 定数 | 名前 | 型 | 型パラメータ |
| --- | --- | --- | --- |
| `BuiltinPure` | `pure` | `(T) -> IO[T]` | `[T]` |
| `BuiltinBind` | `bind` | `(IO[A], A -> IO[B]) -> IO[B]` | `[A, B]` |
| `BuiltinPrint` | `print` | `(String) -> IO[Unit]` | |
| `BuiltinEPrint` | `eprint` | `(String) -> IO[Unit]` | |
| `BuiltinReadStdin` | `readStdin` | `() -> IO[String]` | |
| `BuiltinReadFile` | `readFile` | `(String) -> IO[String]` | |
| `BuiltinFileExists` | `fileExists` | `(String) -> IO[Bool]` | |
| `BuiltinWriteFile` | `writeFile` | `(String, String) -> IO[Unit]` | |
| `BuiltinArgCount` | `argCount` | `() -> IO[Int]` | |
| `BuiltinArgAt` | `argAt` | `(Int) -> IO[String]` | |
| `BuiltinExit` | `exit` | `(Int) -> IO[Unit]` | |

型パラメータのある組み込み関数は、`Symbol.TypeParams` にそれを入れる。参照は多相な関数と同じくインスタンス化し、`Info.TypeArgs` に型引数を記録する（既存の `instantiate` がそのまま使える）。

#### `main`

* エントリ module の `main` は、型パラメータを持たず、型が `() -> Int` か `() -> IO[Unit]` でなければならない。
  そうでなければ `function 'main' must have type () -> Int or () -> IO[Unit], found <型>`（既存の 2 つのメッセージを置き換える）。
* 推論する `main`（ADR-0007）は、本体の前に戻り値を `Int` と単一化する処理をやめる。代わりに、成分の一般化の後で上の規則を検査する。
  引数がある推論する `main` は、本体の検査の前に同じメッセージでエラーにする（今と同じ位置）。
* `Info` に `MainIO bool`（`main` の型が `() -> IO[Unit]`）を足す。

### 単位 1 のテスト観点

* `parser_test.go` / `print_test.go`: `()` の式、`f(())`、`(1)` は括弧の式のまま、`fn(u: Unit) -> Unit { u }`、`IO[List[Int]]` の型。
* `types_test.go`: `Unit` の表示、`IOOf(Int).String()` が `IO[Int]`、`IsIO`。
* `typecheck_test.go`（`TestCheckIOSuccess` / `TestCheckIOError`）:
  * 成功: `()` の型、`pure(1)` が `IO[Int]`、`bind(readStdin(), fn(s) { print(s) })`（`s` が `String` に決まる）、11 個の組み込み関数の呼び出し、`pure` を値として使う（`let p = pure` を 2 つの型で）、`main: () -> IO[Unit]` の注釈あり・推論（`fn main() { print("hi") }`）、`MainIO` の値、`IO` を返す再帰関数（`fn loop(n: Int) -> IO[Unit]`）。
  * エラー: `IO` の型引数の個数、`Unit[Int]`、`type IO = ...`、`type Unit = ...`、`() == ()`、`pure(1) == pure(1)`、`IO` の `match`、`main: () -> IO[Int]`、`main: () -> Bool`、推論する `main` が `Bool`、`bind(1, f)`、`print(1)`。
* 既存の `main` の型のエラーを期待するテストのメッセージを新しい文言に直す（`fn main() { true }` は新しい規則で `function 'main' must have type () -> Int or () -> IO[Unit], found () -> Bool` になる）。

### 単位 1 の完了条件

* `make check` が通る。既存の E2E が変わらない。

## 単位 2: バックエンドと実行

### `internal/ir`

```go
// PrimOp に追加（WASI を使う。IO の動作のクロージャの本体の中にだけ現れる）:
IOPrint      // (Ptr) -> Bool      標準出力へ書く。結果は Unit（Bool の偽）
IOEPrint     // (Ptr) -> Bool      標準エラー出力へ書く
IOReadStdin  // () -> Ptr
IOReadFile   // (Ptr) -> Ptr
IOFileExists // (Ptr) -> Bool
IOWriteFile  // (Ptr, Ptr) -> Bool
IOArgCount   // () -> Int
IOArgAt      // (Int) -> Ptr
IOExit       // (Int) -> Bool      戻らない

// Module に追加:
//   Command bool // main returns an IO[Unit] closure; export _start (ADR-0012)
```

表示名は `io.print`、`io.eprint`、`io.read_stdin`、`io.read_file`、`io.file_exists`、`io.write_file`、`io.arg_count`、`io.arg_at`、`io.exit`。

### `internal/lower`

* `valType`: `Unit` は `ir.Bool`。`IO[T]` は `ir.FuncRef`。
* `UnitLit` は `BoolConst{false}`。
* `Module.Command = info.MainIO`。

#### IO の組み込み関数

```go
// ioAction returns the lifted function that performs builtin b with the
// representations reps of its type arguments (nil for the monomorphic
// ones), creating it on first use. Its signature is (env Ptr) -> result,
// where result is the representation of T in IO[T].
func (l *lowerer) ioAction(b typecheck.Builtin, reps []ir.ValType) ir.FuncID

// lowerIOCall returns the FuncRef value of the IO action for b applied to
// args: a FuncValue of ioAction(b, reps), whose environment holds args in
// order (no environment when args is empty).
func (l *lowerer) lowerIOCall(b typecheck.Builtin, reps []ir.ValType, args []ir.Expr) ir.Expr
```

* 動作の関数は、`(builtin, repKey(reps))` ごとに 1 つ作り、テーブルに入れる。名前は `io.<名前>`、型引数があれば `io.pure[Int]`、`io.bind[Int,Bool]` のように付ける。
* 動作の関数の局所変数 0 は環境（`Ptr`）。本体（`env` は局所変数 0、`f(i, t)` は `Field{Local: 0, Index: i, T: t}`）:

| 組み込み関数 | 本体 | 結果の値型 |
| --- | --- | --- |
| `pure[r]` | `f(0, r)` | `r` |
| `bind[a, b]` | 下記 | `b` |
| `print` | `Prim{IOPrint, [f(0, Ptr)]}` | `Bool` |
| `eprint` | `Prim{IOEPrint, [f(0, Ptr)]}` | `Bool` |
| `readStdin` | `Prim{IOReadStdin, []}` | `Ptr` |
| `readFile` | `Prim{IOReadFile, [f(0, Ptr)]}` | `Ptr` |
| `fileExists` | `Prim{IOFileExists, [f(0, Ptr)]}` | `Bool` |
| `writeFile` | `Prim{IOWriteFile, [f(0, Ptr), f(1, Ptr)]}` | `Bool` |
| `argCount` | `Prim{IOArgCount, []}` | `Int` |
| `argAt` | `Prim{IOArgAt, [f(0, Int)]}` | `Ptr` |
| `exit` | `Prim{IOExit, [f(0, Int)]}` | `Bool` |

```text
bind[a, b] の本体（局所変数 1 は a）:
    Block{
        Lets: [Let{1, CallIndirect{Callee: f(0, FuncRef), Sig: {[], a}, Args: []}}],
        Result: CallIndirect{
            Callee: CallIndirect{Callee: f(1, FuncRef), Sig: {[a], FuncRef}, Args: [LocalGet{1, a}]},
            Sig: {[], b}, Args: [], Tail: true,
        },
    }
```

本体を作ったら `markTailCalls` を適用する（`bind` の最後の呼び出しが `return_call_indirect` になる）。

* 呼び出し（`lowerCall` の `SymBuiltin`）: IO の組み込み関数なら、引数を変換して `lowerIOCall(b, reps, args)`。`reps` は `Info.TypeArgs[id]` の各型の `valType`（型パラメータのない組み込み関数は nil）。
* 値としての使用（`lowerIdent` の `SymBuiltin`）: `$ref` ラッパー（v0.8）の本体を `lowerIOCall(b, reps, 引数の LocalGet)` にする。ラッパーは `(builtin, repKey(reps))` ごとに 1 つ。

### `internal/wasm`

#### import と関数の番号

* モジュールが IO の `Prim` を含むか `Command` のとき、`wasi_snapshot_preview1` の次の 7 つの関数を、この順に import する（import セクション、id 2。型は型セクションに足す）。

| 名前 | 型 |
| --- | --- |
| `fd_write` | `(i32, i32, i32, i32) -> i32` |
| `fd_read` | `(i32, i32, i32, i32) -> i32` |
| `path_open` | `(i32, i32, i32, i32, i32, i64, i64, i32, i32) -> i32` |
| `fd_close` | `(i32) -> i32` |
| `args_sizes_get` | `(i32, i32) -> i32` |
| `args_get` | `(i32, i32) -> i32` |
| `proc_exit` | `(i32) -> ()` |

* import した関数は関数の番号の先頭を占めるので、それ以外のすべての関数の番号（`call`、`return_call`、要素セグメント、エクスポート、補助関数の番号）に import の数を足す。import がなければ、出力は v0.9 と同じバイト列になる。
* `Command` のとき:
  * 最後の補助関数の後に `_start`（型 `() -> ()`）を足す。本体は `call main` で関数値を得て、v0.6 の `CallIndirect` と同じ手順（作業用の `i64` の局所変数）で、型 `(i32 env) -> i32` の関数として呼び、結果を `drop` する。
  * エクスポートは `_start`（関数）と `memory`（メモリ 0）にする。`main` はエクスポートしない。
  * メモリを常に持つ（`usesMemory` を真にする）。

#### IO の補助関数

文字列の補助関数（v0.8）の後に、使われたものだけを次の順で追加する。WASI の作業領域（iovec、戻り値の書き込み先）は、呼ぶたびに `alloc` で確保してよい（回収しない方針、ADR-0010）。

| 補助関数 | 型 | 動作 |
| --- | --- | --- |
| `io_write` | `(i32 fd, i32 s) -> i32` | `s` のバイト列を、全部書けるまで `fd_write` を繰り返す。結果は 0（Unit） |
| `io_print` / `io_eprint` | `(i32 s) -> i32` | `io_write(1, s)` / `io_write(2, s)` |
| `io_read_fd` | `(i32 fd) -> i32` | `fd` を終わり（`nread == 0`）まで読み、String のブロックにして返す。バッファが足りなくなったら 2 倍の大きさのブロックを確保してコピーする（初期 4096 バイト） |
| `io_read_stdin` | `() -> i32` | `io_read_fd(0)` |
| `io_open` | `(i32 path, i32 oflags, i64 rights) -> i32` | `path_open(3, 0, path+8, len, oflags, rights, rights, 0, &fd)`。成功なら fd、失敗なら -1 |
| `io_read_file` | `(i32 path) -> i32` | `io_open(path, 0, FD_READ=0x2)`。失敗なら `io_write(2, "error: cannot read file " ++ path ++ "\n")` の後 `proc_exit(1)`。成功なら `io_read_fd`、`fd_close` |
| `io_file_exists` | `(i32 path) -> i32` | `io_open(path, 0, 0x2)` が成功すれば `fd_close` して 1、失敗なら 0 |
| `io_write_file` | `(i32 path, i32 s) -> i32` | `io_open(path, O_CREAT\|O_TRUNC = 0x9, FD_WRITE=0x40)`。失敗なら `cannot write file` で終了。成功なら `io_write(fd, s)`、`fd_close`、0 |
| `io_arg_count` | `() -> i64` | `args_sizes_get` の argc - 1 |
| `io_arg_at` | `(i64 i) -> i32` | `0 <= i < argc - 1` でなければ `unreachable`。`args_get` で全体を取り、`argv[i + 1]` の NUL 終端の文字列を String のブロックにコピーする |
| `io_exit` | `(i64 code) -> i32` | `proc_exit(wrap(code))` の後 `unreachable` |

エラーメッセージの固定の部分（`error: cannot read file `、`error: cannot write file `、`\n`）は、v0.8 の文字列リテラルと同じくデータセグメントに置く。

### `internal/driver`

```go
// Output is a compiled program.
type Output struct {
	Wasm    []byte
	Command bool // a WASI command (main: () -> IO[Unit]); run without --invoke
}

// CompileProgram is CompileWith that also reports how to run the result.
func CompileProgram(
	filename string,
	src []byte,
	read func(name string) ([]byte, error),
) (*Output, error)
```

`Compile` と `CompileWith` は、`CompileProgram` の `Wasm` を返すように書き直す（動作は変わらない）。

### `internal/cli` と `cmd/ceroc`

* `Run(args []string, stdin io.Reader, stdout, stderr io.Writer) int` に変え、`cmd/ceroc/main.go` は `os.Stdin` を渡す。テストも合わせる。
* `ceroc run FILE [ARGS...]`: 最初の引数がファイル、残りはプログラムに渡す引数（`-` で始まる引数も、ファイルの後ならそのまま渡す）。ファイルより前の `-` で始まる引数は今までどおりエラー。
* `Command` でない: 今までどおり `wasmtime run --invoke main X.wasm`（`ARGS` があれば、使い方のエラー `ceroc run: arguments are only passed to programs whose main returns IO[Unit]`）。
* `Command`: `wasmtime run --dir=. X.wasm ARGS...` を、標準入力・標準出力・標準エラー出力をそのままつないで実行する。プログラムの終了コードが 0 でなければ、`ceroc` もその終了コードで終わる（`runtime failed` のメッセージは出さない）。wasmtime 自体が起動できなかった場合は今までどおり。
* `usage` の `run` の行を `ceroc run <file.cero> [args...]` にする。

### `std/io.cero`（新規）

```text
import "std/list"
pub fn then[A, B](m: IO[A], next: IO[B]) -> IO[B]
pub fn mapIO[A, B](m: IO[A], f: A -> B) -> IO[B]
pub fn println(s: String) -> IO[Unit]
pub fn eprintln(s: String) -> IO[Unit]
pub fn forEach[T](xs: List[T], f: T -> IO[Unit]) -> IO[Unit]
pub fn args() -> IO[List[String]]
pub fn unit() -> IO[Unit]                // pure(())
```

`forEach` は、右に入れ子にした `bind` で書く（要素数に比例するスタックを使わない）。
