# 設計: v0.2 型検査（代数的データ型と `match`）

## 目的

`docs/design/v0.2-frontend.md` で追加した `type` 宣言と `match` 式について、名前解決・型検査・網羅性と到達不能なアームの検査を行う。
結果は IR 生成（`docs/design/v0.2-backend.md`）が使う。

対象外にすること:

* 型パラメータ、入れ子のパターン（ADR-0003 で v0.2 の対象外）
* データ型の値の `==` / `!=`（v0.1 の規則のまま `cannot compare values of type T` になる）
* 複数エラーの報告と警告

## 関連する ADR

* ADR-0002: 比較できる型、クロージャ禁止、エラー報告
* ADR-0003: 型宣言、構築子、`match`、パターン、網羅性、到達不能なアーム

## 前提

`docs/design/v0.1-typecheck.md` と `docs/design/v0.2-frontend.md` の内容が実装済みであること。本書は差分だけを書く。

## `internal/types`

```go
// Data is a declared algebraic data type. Each type declaration has exactly
// one *Data, and two data types are equal only when they are the same pointer.
type Data struct {
	Name  string
	Ctors []*Ctor // declaration order
}

// Ctor is one constructor of a Data type.
type Ctor struct {
	Name   string
	Index  int    // position in Data.Ctors; used as the runtime tag
	Fields []Type
	Data   *Data
}
```

* `*Data` はポインタレシーバで `Type` を実装する。`String()` は `Name` を返す。
* `*Ctor` は `Type` を実装しない。
* `Equal` に `case *Data:` を追加し、`b` が同じポインタのときだけ `true` を返す。
  再帰型でも構造をたどらないので、無限再帰にならない。
* パッケージのコメントを `the monomorphic types of Cero`（バージョン番号なし）に変える。

## `internal/typecheck`

### 追加する公開要素

```go
const (
	SymFunc  SymbolKind = iota // top-level function
	SymParam                   // parameter of a FuncDecl or FuncLit
	SymLocal                   // let binding or variable pattern
	SymCtor                    // constructor
)

type Symbol struct {
	Kind SymbolKind
	Name string
	Type types.Type
	Pos  diag.Pos
	Decl *ast.FuncDecl // set only for SymFunc
	Ctor *types.Ctor   // set only for SymCtor
}

type Info struct {
	// ... v0.1 fields unchanged ...
	Datas    map[*ast.TypeDecl]*types.Data // every type declaration
	CtorPats map[*ast.CtorPat]*types.Ctor  // constructor of every constructor pattern
	PatVars  map[*ast.VarPat]*Symbol       // symbol declared by every variable pattern
}
```

* `SymCtor` のシンボルの `Type` は、フィールドがなければ `*types.Data`、あれば `&types.Func{Params: Fields, Result: Data}` とする。
* `Check` は `Datas`、`CtorPats`、`PatVars` も必ず割り当てる（空の map）。
* 変数パターンが束縛する名前は `SymLocal` とする。IR 生成では `let` と同じくローカル変数として扱う。

### 処理の流れ（`Check`）

v0.1 の手順 1（関数のシグネチャの収集）の前に、型と構築子を集める。

```text
Check(file):
    info, globals = ... (v0.1)
    datas = map[string]*types.Data
    ctors = map[string]*types.Ctor

    // 0a. type names, in source order
    for d in file.Types:
        if d.Name is "Int" or "Bool": error at d.NamePos "cannot redefine built-in type 'NAME'"
        if d.Name in datas: error at d.NamePos "duplicate type 'NAME'"
        datas[d.Name] = &types.Data{Name: d.Name}
        info.Datas[d] = datas[d.Name]

    // 0b. constructors, in source order (type by type, then constructor by constructor)
    for d in file.Types:
        data = datas[d.Name]
        for i, cd in d.Ctors:
            if cd.Name in ctors: error at cd.Pos "duplicate constructor 'NAME'"
            fields = resolveType(f) for f in cd.Fields   // may refer to any declared type
            ctor = &types.Ctor{cd.Name, i, fields, data}
            data.Ctors = append(data.Ctors, ctor)
            ctors[cd.Name] = ctor
            globals[cd.Name] = &Symbol{Kind: SymCtor, Name: cd.Name, Type: ctorType(ctor), Pos: cd.Pos, Ctor: ctor}

    // 1. function signatures (v0.1), with one extra check
    for d in file.Funcs:
        if globals[d.Name] is SymCtor: error at d.NamePos "function 'NAME' conflicts with constructor 'NAME'"
        if globals[d.Name] is SymFunc: error at d.NamePos "duplicate function 'NAME'"
        ... (v0.1)

    // 2. bodies, 3. main: v0.1 のまま
```

* `resolveType` の `NamedType` は、`Int`、`Bool`、`datas` の順に引く。どれでもなければ v0.1 の `unknown type 'NAME'`。
* 手順 0b では全型の名前が登録済みなので、後方の型や自分自身を参照するフィールドも解決できる。
* 構築子の名前は大文字で始まり、関数名との衝突は手順 1 で検出する。

### 変数を束縛するときの検査

引数（`FuncDecl` と `FuncLit`）、`let`、変数パターンで名前を束縛する前に、次を確認する。

```text
checkBindable(name, pos):
    if globals[name] is SymCtor: error at pos "cannot use constructor name 'NAME' as a variable"
```

呼ぶ位置は次のとおり。

* 引数: 各引数について、重複検査（`duplicate parameter`）より先に呼ぶ。
* `let`: 値の式を検査した後、名前をスコープに入れる直前に呼ぶ。
* 変数パターン: 後述の `checkPattern` の中で呼ぶ。

### 名前の参照

`Ident` の解決順は v0.1 と同じ（現在の関数のスコープ → 外側の関数のスコープ → `globals`）。構築子は束縛できないので、構築子の名前は必ず `globals` の `SymCtor` に解決される。

`inferIdent` で `SymCtor` が見つかった場合:

```text
if len(ctor.Fields) == 0: record Uses; type = ctor.Data
else: error at e.Pos "constructor 'NAME' cannot be used as a value; call it with its fields"
```

### 構築子の呼び出し

`inferCall` の先頭で、`e.Fn` が `*ast.Ident` かつ、その名前が `SymCtor` に解決される場合は、次の処理を行い、v0.1 の処理には進まない。

```text
ctor = sym.Ctor
record Uses[e.Fn] = sym; Types[e.Fn] = sym.Type
if len(ctor.Fields) == 0: error at e.LParen "constructor 'NAME' has no fields; write it without parentheses"
if len(e.Args) != len(ctor.Fields): error at e.LParen "wrong number of arguments: expected N, found M"
for i: expect(e.Args[i], ctor.Fields[i])
type = ctor.Data
```

`Types[e.Fn]` に記録するのは、`Info.Types` がすべての式ノードの型を持つという v0.1 の約束を保つためである。

### `match` 式

`inferExpr` の型スイッチに `case *ast.MatchExpr:` を追加し、`inferMatch` を呼ぶ。

```text
inferMatch(ctx, m):
    st = infer(m.Scrutinee)
    if st is *types.Func: error at resultPos(m.Scrutinee) "cannot match on values of type T"
    cov = new coverage(st)
    var result types.Type
    for arm in m.Arms:
        pushScope(ctx)
        checkPattern(ctx, arm.Pattern, st)
        if cov.covers(arm.Pattern): error at arm.Pattern.Position() "unreachable match arm"
        cov.add(arm.Pattern)
        t = infer(arm.Body)
        popScope(ctx)
        if result == nil: result = t
        else if !Equal(result, t): error at resultPos(arm.Body) "match arms have different types: RESULT and T"
    if missing = cov.missing(); missing != "": error at m.Pos "non-exhaustive match: MISSING"
    type = result
```

* エラーは、アームごとに「パターン → 到達不能 → 本体 → 型の一致」の順に調べ、最後に網羅性を調べる。
* パターンの変数のスコープは、そのアームの本体だけとする。

### パターンの検査

```text
checkPattern(ctx, p, st):
    switch p:
    case *WildcardPat: ok
    case *VarPat:
        checkBindable(p.Name, p.Pos)
        bind p.Name as SymLocal of type st; info.PatVars[p] = sym
    case *IntPat:  if st != Int:  error at p.Pos "expected ST, found Int"
    case *BoolPat: if st != Bool: error at p.Pos "expected ST, found Bool"
    case *CtorPat:
        ctor = ctors[p.Name]; if nil: error at p.Pos "unknown constructor 'NAME'"
        if !Equal(st, ctor.Data): error at p.Pos "expected ST, found DATA"
        if len(p.Args) != len(ctor.Fields):
            error at p.Pos "wrong number of fields in pattern 'NAME': expected N, found M"
        seen = set of names
        for i, a in p.Args:
            if a is *VarPat:
                if a.Name in seen: error at a.Pos "duplicate variable 'NAME' in pattern"
                seen.add(a.Name)
                checkBindable(a.Name, a.Pos)
                bind a.Name as SymLocal of type ctor.Fields[i]; info.PatVars[a] = sym
        info.CtorPats[p] = ctor
```

* 束縛は `pushScope` した、そのアーム用のスコープに入れる。外側の同じ名前の変数を隠してよい。
* v0.2 の構文では変数パターンは小文字始まりなので、`checkBindable` が失敗するのは、構築子と同じ名前の小文字の変数だけである（実際には起こらないが、規則として置いておく）。

### 網羅性と到達不能の判定（`coverage`）

構築子パターンの引数は変数か `_` だけなので、構築子パターンは「その構築子で作られたすべての値」に一致する。
そのため、各アームのパターンを次のどれかに分類するだけで判定できる。

| 分類 | 対象 |
| --- | --- |
| 全体 | `WildcardPat`、`VarPat` |
| 構築子 k | 構築子の `Index` が k の `CtorPat` |
| 整数 v | `IntPat` |
| 真偽値 v | `BoolPat` |

```go
// coverage is internal to the typecheck package.
type coverage struct {
	scrutinee types.Type
	all       bool           // a catch-all arm has been seen
	ctors     map[int]bool   // constructor indices seen
	ints      map[int64]bool // integer literals seen
	bools     map[bool]bool  // boolean literals seen
}
```

`covers(p)`（それまでのアームで、`p` に一致する値がすべて捕まるか）:

* `all` が真なら真。
* 構築子 k: `ctors[k]`。
* 整数 v: `ints[v]`。
* 真偽値 v: `bools[v]`。
* 全体: 照合対象が `Bool` で `bools` に両方ある、または照合対象がデータ型で `ctors` にすべての構築子がある場合に真。それ以外は偽。

`add(p)` は分類に応じて `all`、`ctors`、`ints`、`bools` を更新する。

`missing()`（足りない値の説明。網羅していれば `""`）:

* `all` が真なら `""`。
* データ型: `ctors` にない構築子の名前を宣言順に `", "` で連結する。すべてあれば `""`。
* `Bool`: `true`、`false` のうち `bools` にないものを、この順に `", "` で連結する。
* `Int`: `"Int values need a '_' or variable pattern"`。

エラーメッセージは `non-exhaustive match: ` の後に `missing()` の結果を付ける（例: `non-exhaustive match: Cons`、`non-exhaustive match: Circle, Rect`、`non-exhaustive match: false`、`non-exhaustive match: Int values need a '_' or variable pattern`）。

### エラーの一覧（追加分）

| メッセージ | 位置 |
| --- | --- |
| `cannot redefine built-in type 'NAME'` | 型宣言の `NamePos` |
| `duplicate type 'NAME'` | 2 つ目の型宣言の `NamePos` |
| `duplicate constructor 'NAME'` | 2 つ目の構築子の `Pos` |
| `function 'NAME' conflicts with constructor 'NAME'` | 関数の `NamePos` |
| `cannot use constructor name 'NAME' as a variable` | 束縛する名前の位置 |
| `constructor 'NAME' cannot be used as a value; call it with its fields` | `Ident.Pos` |
| `constructor 'NAME' has no fields; write it without parentheses` | `CallExpr.LParen` |
| `wrong number of arguments: expected N, found M`（構築子の呼び出し） | `CallExpr.LParen` |
| `cannot match on values of type T` | `resultPos(Scrutinee)` |
| `expected T, found U`（パターンの型の不一致） | パターンの位置 |
| `unknown constructor 'NAME'` | `CtorPat.Pos` |
| `wrong number of fields in pattern 'NAME': expected N, found M` | `CtorPat.Pos` |
| `duplicate variable 'NAME' in pattern` | 2 つ目の変数の位置 |
| `unreachable match arm` | そのアームのパターンの位置 |
| `match arms have different types: T and U` | `resultPos(そのアームの本体)` |
| `non-exhaustive match: MISSING` | `MatchExpr.Pos` |

## テスト観点

テーブル駆動。ソースを `parser.ParseFile` で解析してから `Check` を呼ぶ。各テストとサブテストで `t.Parallel()`。既存のテストはそのまま通ること。

### `types`

* `String()`: `&Data{Name: "IntList"}` → `IntList`。関数型の中のデータ型 `IntList -> Int`
* `Equal`: 同じ `*Data` は真、同じ名前でも別のポインタは偽、`*Data` と `Int` は偽
* 自分自身をフィールドに持つ `*Data`（再帰型）どうしの `Equal` が停止する

### `typecheck` の成功ケース

各ケースで `Check` がエラーを返さないこと。指定があるケースでは、式の型を `Info.Types` から取り出して `String()` で比較する。

* ADR-0003 の `Shape` と `area`、`IntList` と `sum`（`main` から呼ぶ）
* 型宣言が、それを使う関数より後にある
* 相互再帰の型（`type A = | A0 | A1(B)` と `type B = | B0(A)`）
* 関数型のフィールドを持つ構築子と、そのフィールドを取り出して呼ぶ `match`
* フィールドのない構築子 `Nil` の式の型が `IntList`
* `Cons(1, Nil)` の式の型が `IntList`、`Info.Types` に `Cons`（`Ident`）の型 `(Int, IntList) -> IntList` が記録される
* `match` の式の型がアームの本体の型になる（`Bool` を返す `match`）
* 整数パターンと `_`: `match n { 0 => 1, 1 => 1, _ => 2 }`
* 真偽値パターンで網羅: `match b { true => 1, false => 0 }`
* 変数パターンで網羅: `match xs { Nil => 0, other => 1 }`
* パターンの変数が外側の同名の変数を隠す。アームの外では外側の変数に戻る（`Info.Uses` で確認）
* 匿名関数の中の `match` で、パターンの変数を参照する（捕捉にならない）
* `Info.CtorPats` と `Info.PatVars` が記録される
* データ型を引数・結果・`let` の型注釈に書ける

### `typecheck` のエラーケース

メッセージと位置（`err.Error()` の文字列）を完全一致で比較する。

* `type Int = A` → `cannot redefine built-in type 'Int'`
* 同じ名前の型 2 つ → `duplicate type 'T'`（2 つ目）
* 別の型にまたがる同じ構築子名 → `duplicate constructor 'A'`（2 つ目）
* `fn Nil() -> Int { 1 }` と `type L = Nil` → `function 'Nil' conflicts with constructor 'Nil'`
* フィールドに未知の型 → `unknown type 'Foo'`
* `fn f(Nil: Int) -> Int { 1 }` → `cannot use constructor name 'Nil' as a variable`
* `let Nil = 1` → 同上
* `let f = Cons` → `constructor 'Cons' cannot be used as a value; call it with its fields`
* `Nil()` → `constructor 'Nil' has no fields; write it without parentheses`（`(` の位置）
* `Cons(1)` → `wrong number of arguments: expected 2, found 1`
* `Cons(true, Nil)` → `expected Int, found Bool`（`true` の位置）
* データ型どうしの `==` → `cannot compare values of type IntList`
* 関数を照合: `match f { _ => 0 }`（`f: Int -> Int`）→ `cannot match on values of type Int -> Int`
* `match xs { 0 => 1, _ => 2 }`（`xs: IntList`）→ `expected IntList, found Int`（`0` の位置）
* `match n { true => 1, _ => 2 }`（`n: Int`）→ `expected Int, found Bool`
* `match n { Nil => 1, _ => 2 }`（`n: Int`）→ `expected Int, found IntList`
* 別の型の構築子: `match s { Nil => 1, _ => 2 }`（`s: Shape`）→ `expected Shape, found IntList`
* `match xs { Foo => 1, _ => 2 }` → `unknown constructor 'Foo'`
* `match xs { Nil(x) => 1, _ => 2 }` → `wrong number of fields in pattern 'Nil': expected 0, found 1`
* `match xs { Cons(x) => 1, _ => 2 }` → `wrong number of fields in pattern 'Cons': expected 2, found 1`
* `match p { Pair(x, x) => x, }` → `duplicate variable 'x' in pattern`（2 つ目の `x` の位置）
* `match xs { _ => 0, Nil => 1 }` → `unreachable match arm`（`Nil` の位置）
* `match xs { y => 0, _ => 1 }` → `unreachable match arm`（`_` の位置）
* `match xs { Nil => 0, Nil => 1, _ => 2 }` → `unreachable match arm`（2 つ目の `Nil` の位置）
* `match xs { Nil => 0, Cons(x, r) => 1, _ => 2 }` → `unreachable match arm`（`_` の位置）
* `match b { true => 0, false => 1, _ => 2 }` → `unreachable match arm`（`_` の位置）
* `match n { 1 => 0, 1 => 1, _ => 2 }` → `unreachable match arm`（2 つ目の `1` の位置）
* `match xs { Nil => 0 }` → `non-exhaustive match: Cons`（`match` の位置）
* `match s { Circle(r) => r }`（3 構築子の型で 2 つ足りない）→ `non-exhaustive match: Rect, Tri`（宣言順）
* `match b { true => 1 }` → `non-exhaustive match: false`
* `match n { 0 => 1 }` → `non-exhaustive match: Int values need a '_' or variable pattern`
* `match xs { Nil => 0, Cons(x, r) => true }` → `match arms have different types: Int and Bool`（`true` の位置）
* パターンのエラーが、同じアームの本体のエラーより先に報告される
* 到達不能のエラーが、網羅性のエラーより先に報告される（`match b { _ => 0, true => 1 }` は `unreachable`）
* 匿名関数の中の `match` の本体から、外側の関数のパターン変数を参照 → v0.1 の `cannot capture 'x' ...`

## 完了条件

* 上記の変更とテストが存在し、`make check` が通る。
* フロントエンドのパッケージは変更しない（バグを見つけた場合は報告する）。
* IR 生成・WASM バックエンドのパッケージは変更しない。
  このフェーズの終了時点では、データ型を使うプログラムの IR 生成が `panic` してよい（`driver` の既存テストは v0.1 のプログラムだけを使うので影響しない）。
