# 設計: v0.8 String

## 目的

ADR-0010 のとおり、組み込みの `String` 型、文字列リテラル、`++`、`String` の `==` / `!=`、組み込み関数、文字列リテラルのパターンを追加する。

対象外にすること:

* 文字（コードポイント）の型、UTF-8 の解釈
* 組み込みの `List` / `Option`、標準ライブラリ（v0.9 の module で扱う）
* 文字列の出力（IO の段階で扱う）
* メモリの回収
* 文字列の順序比較の演算子（`<` など。`stringCompare` を使う）

## 関連する ADR

* ADR-0002: 比較できる型、組み込みの演算子
* ADR-0003: ヒープのブロック、バンプアロケータ、上限
* ADR-0008: 関数値（`$ref` ラッパー）
* ADR-0009: パターン、usefulness
* ADR-0010: 本書の決定

## 前提

`docs/design/v0.7-nested-patterns.md` までが実装済みであること。
実装は 2 つの単位に分け、この順に行う。

1. **フロントエンド**: `token`、`lexer`、`ast`、`parser`、`types`、`typecheck`（型検査のテストまで。IR 生成は触らない）
2. **バックエンド**: `ir`、`lower`、`wasm`、サンプル、E2E、`README.md`

単位 1 の時点では、文字列を使うプログラムを `lower` に渡すと `panic` してよい（E2E では文字列を使わない）。

## 単位 1: フロントエンド

### `internal/token`

```go
String   // string literal; Token.Text holds the decoded bytes
PlusPlus // ++
```

`Kind.String()` は `string literal` と `'++'` を返す（既存の書式に合わせる）。

### `internal/lexer`

* `"` で始まり `"` で終わる文字列リテラルを読む。`Token.Text` には、エスケープを解いた後のバイト列を入れる。`Token.Pos` は開きの `"` の位置。
* エスケープ: `\n` → 0x0A、`\t` → 0x09、`\r` → 0x0D、`\\`、`\"`、`\0` → 0x00、`\xHH`（`H` は 16 進の 1 文字、大文字小文字どちらも可）→ そのバイト。
* エラー（位置とメッセージ）:

| 条件 | 位置 | メッセージ |
| --- | --- | --- |
| 閉じの `"` の前にファイルが終わる | 開きの `"` | `unterminated string literal` |
| リテラルの中の改行（LF） | 開きの `"` | `newline in string literal` |
| 未知のエスケープ `\q` | `\` | `invalid escape sequence '\q'` |
| `\x` の後が 16 進 2 桁でない | `\` | `invalid escape sequence '\x'` |

* `++` は 1 つのトークン。`+ +`（空白あり）は `+` 2 つ。

### `internal/ast`

```go
// StringLit is a string literal. Value holds the decoded bytes.
type StringLit struct {
	Pos   diag.Pos
	Value string
}

// StrPat matches one string.
type StrPat struct {
	Pos   diag.Pos
	Value string
}
```

表示（`FormatExpr` / パターンの表示）は `strconv.Quote(Value)` を使う（例: `"a\n"`）。

### `internal/parser`

* 一次式に `token.String` → `StringLit`。
* パターンに `token.String` → `StrPat`（構築子の引数の中でも書ける）。
* `++` は加法と同じ優先順位・左結合: `p.parseLeft(p.parseMul, token.Plus, token.Minus, token.PlusPlus)`（`parseLeft` が可変長でなければ同じ意味になるように直す）。`BinaryExpr.Op` は `token.PlusPlus`。

### `internal/types`

```go
// StringType is the built-in String type.
type StringType struct{}

var String Type = StringType{} // 既存の Int / Bool と同じ形で定義する
```

`String()` は `"String"`。`Equal`、`Resolve`、`Subst`、`Metas`、`Mentions` は `Int` と同じく葉として扱う。

### `internal/typecheck`

#### 型の名前

* `String` は `Int` / `Bool` と同じく組み込みの型名。`type String = ...` と型パラメータ `String` はエラー（既存のメッセージの `'Int'` の部分が `'String'` になる）。
* `resolveType` は `String` を `types.String` にする（型引数があれば既存と同じエラー）。

#### 組み込み関数

```go
const SymBuiltin SymbolKind = ... // 既存の SymCtor の後に追加

// Symbol に追加:
//   Builtin Builtin // set only for SymBuiltin

// Builtin identifies a built-in function (ADR-0010).
type Builtin int

const (
	BuiltinStringLength Builtin = iota
	BuiltinStringByteAt
	BuiltinStringSlice
	BuiltinStringFromByte
	BuiltinStringCompare
	BuiltinIntToString
)
```

`Check` の最初（型宣言の登録より前）に、ADR-0010 の表の 6 つを `c.globals` に `SymBuiltin` として登録する（`Pos` はゼロ値、`Type` は表の型）。

* トップレベルの関数の名前が組み込み関数と同じ: `function 'NAME' conflicts with built-in function 'NAME'`（関数の名前の位置）
* 構築子の名前が組み込み関数と同じ: `constructor 'NAME' conflicts with built-in function 'NAME'`（構築子の位置）
* 局所的な名前は隠せる（`checkBindable` は構築子だけを禁止するまま）。
* `inferIdent` / `inferCall` は `SymBuiltin` を、型パラメータのない `SymFunc` と同じように扱う（インスタンス化しない、`Uses` に記録）。
* `funcRefs`（v0.5）の `isFunc` は `SymFunc` だけを真にする（組み込み関数は依存グラフに入らない）。

#### 式

* `StringLit` の型は `String`。
* `++`: 両方のオペランドを `String` として `expect` し、結果は `String`。エラーは `+` と同じ形式（`expected String, found Int`）。
* `==` / `!=`: 比較できる型に `String` を加える。v0.4 の「左辺が未解決なら右辺と単一化してから比較できるか確かめる」規則はそのまま。比較できない型のメッセージの列挙（あれば）に `String` を足す。

#### パターン

* `StrPat`: `unify(st, String)` が失敗したら `expected %s, found String`。照合対象が未解決の単一化変数なら `String` に解く（`IntPat` と同じ）。
* `exhaust.go`: `spStr` を足す（`sval string`）。完全にならない、引数 0 個、値が等しいときに同じ頭、不足の頭は `_`、表示は `strconv.Quote`。

* `parser_test.go`: 文字列リテラルの式、`"a" ++ "b" ++ c` の左結合、`a + b ++ c` の優先順位、文字列のパターン（入れ子を含む）。
* `print_test.go`: `StringLit`、`StrPat` の表示。

## 単位 2: バックエンド

### `internal/ir`

```go
// StrConst is a string literal. It yields the address (Ptr) of a static
// block laid out as in ADR-0010.
type StrConst struct{ Value string }

// PrimOp is a built-in operation on strings (ADR-0010).
type PrimOp int

const (
	StrLength   PrimOp = iota // (Ptr) -> Int
	StrByteAt                 // (Ptr, Int) -> Int
	StrSlice                  // (Ptr, Int, Int) -> Ptr
	StrFromByte               // (Int) -> Ptr
	StrCompare                // (Ptr, Ptr) -> Int
	IntToString               // (Int) -> Ptr
	StrConcat                 // (Ptr, Ptr) -> Ptr
	StrEq                     // (Ptr, Ptr) -> Bool
)

// Prim applies a built-in operation to Args.
type Prim struct {
	Op   PrimOp
	Args []Expr
}
```

`Type()`: `StrConst` は `Ptr`、`Prim` は上のコメントの結果の型。
表示: `(str "a\n")`（`strconv.Quote`）、`(prim string.length X)` の形で、名前は `string.length`、`string.byte_at`、`string.slice`、`string.from_byte`、`string.compare`、`int.to_string`、`string.concat`、`string.eq`。

### `internal/lower`

* `valType`: `types.String` は `ir.Ptr`。
* `StringLit` → `StrConst`。
* `++` → `Prim{StrConcat, [x, y]}`。`String` の `==` → `Prim{StrEq}`、`!=` → `Unary{Not, Prim{StrEq}}`。`Int` / `Bool` の比較は変えない（型検査の型でどちらかを決める）。
* 組み込み関数の呼び出し → `Prim{対応する Op, 引数}`（`Builtin` と `PrimOp` の対応は表の順）。
* 組み込み関数を値として使う → `$ref` ラッパー（ADR-0008）。ラッパーは `Name: "<builtin name>$ref"`、引数は表の型の値型と環境の `Ptr`、本体は `Prim{Op, 引数の LocalGet}`。組み込み関数ごとに 1 つだけ作る（`refs` とは別の `map[typecheck.Builtin]ir.FuncID`）。
* 文字列のパターン:
  * 照合対象が `String` の `match`（常に平ら）は、`lowerValueMatch` と同じ連鎖で、比較を `Prim{StrEq, [LocalGet s, StrConst]}` にする。
  * 入れ子の `StrPat` は `patTest` で同じ比較を作る。`patValType(StrPat)` は `Ptr`。

### `internal/wasm`

#### メモリとデータセグメント

* `usesMemory` は、`StrConst` と `Prim` も対象にする。
* 文字列リテラルの配置: すべての関数の本体を前順でたどり、`StrConst` の値を最初に現れた順に並べる（同じ値は 1 回）。アドレス 8 から順に、各リテラルを `[長さ: i32 LE][0: i32][バイト列][0 埋めで 8 の倍数]` で置く。
* `heap` グローバルの初期値は、リテラルの直後のアドレス（8 の倍数。リテラルがなければ 8）。
* メモリの最小ページ数は `max(1, ceil(初期値 / 65536))`。最大は既存の `memoryMaxPages`。
* データセクション（id 11）を、コードセクションの後に出力する。リテラルがあるときだけ、アクティブなセグメント 1 つ（`0x00`、`i32.const 8; end`、バイト列）。
* `StrConst` の符号化は `i32.const アドレス`。

#### 補助関数

`alloc` と `new` の後に、使われた補助関数だけを次の順で追加する: `str_alloc`（下の 5 つのどれかが使われたとき）、`str_byte_at`、`str_slice`、`str_from_byte`、`str_compare`、`int_to_string`、`str_concat`、`str_eq`。
`StrLength` は補助関数を使わず、`i32.load offset=0` の後に `i64.extend_i32_u` をその場で出力する。
`Prim` の符号化は、引数を順に積んでから対応する補助関数を `call` する。

| 補助関数 | 型（wasm） | 動作 |
| --- | --- | --- |
| `str_alloc` | `(i32 n) -> i32` | `p = alloc((n + 15) & ~7)`、`i32.store(p, n)`、`i32.store offset=4 (p, 0)`、`p` を返す |
| `str_byte_at` | `(i32 s, i64 i) -> i64` | `i` が `0 <= i < 長さ` でなければ `unreachable`（`i64.ge_u(i, extend_u(長さ))` で両方を判定できる）。`i64.load8_u(s + 8 + wrap(i))` |
| `str_slice` | `(i32 s, i64 a, i64 b) -> i32` | `0 <= a`、`a <= b`、`b <= 長さ` でなければ `unreachable`（符号つき比較）。`n = b - a`、`p = str_alloc(n)`、`memory.copy(p + 8, s + 8 + a, n)` |
| `str_from_byte` | `(i64 b) -> i32` | `b` が `0..255`（`i64.gt_u(b, 255)` で判定）でなければ `unreachable`。`p = str_alloc(1)`、`i32.store8 offset=8 (p, b)` |
| `str_compare` | `(i32 a, i32 b) -> i64` | 短い方の長さまで符号なしのバイトを比べ、最初に異なるバイトの大小で -1 / 1。同じなら長さを比べて -1 / 0 / 1 |
| `int_to_string` | `(i64 n) -> i32` | 負なら `-` を付ける。絶対値は `u = 0 - n` を符号なしで扱う（`i64.div_u` / `i64.rem_u`）ので最小値も正しく出る。桁数を数えてから確保し、後ろから埋める |
| `str_concat` | `(i32 a, i32 b) -> i32` | `p = str_alloc(la + lb)`、`memory.copy` を 2 回 |
| `str_eq` | `(i32 a, i32 b) -> i32` | アドレスが同じなら 1。長さが違えば 0。バイトを順に比べる |

* `memory.copy` は `0xFC 0x0A 0x00 0x00`。新しい opcode（`i32.load8_u`、`i64.load8_u`、`i32.store8`、`i64.div_u`、`i64.rem_u`、`i32.and`、`loop`、`br_if`、`br` など）は定数として追加する。
* 補助関数の型は `collectTypes` の補助関数の型の列（`auxiliarySigs`）の後ろに足す。
