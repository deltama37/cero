# 設計: v0.1 型検査

## 目的

構文解析済みの AST（`*ast.File`）に対して、名前解決と単相の静的型検査を行う。
結果は後段の IR 生成（`docs/design/v0.1-ir.md`）が使う。

対象外にすること:

* 型推論（ローカル変数の型を右辺から決める以外）
* 多相、代数的データ型
* 複数エラーの報告（最初の 1 件で止まる。ADR-0002）

## 関連する ADR

* ADR-0001: 基本型、型注釈、型エラーの例
* ADR-0002: 比較できる型、クロージャ禁止、相互再帰、エラー報告

## 前提

`docs/design/v0.1-frontend.md` の `internal/diag`、`internal/token`、`internal/ast`、`internal/parser` が実装済みであること。

## `internal/types`

```go
package types

type Type interface {
	String() string
	isType()
}

type IntType struct{}
type BoolType struct{}

type Func struct {
	Params []Type
	Result Type
}

var (
	Int  Type = IntType{}
	Bool Type = BoolType{}
)

// Equal reports structural equality.
func Equal(a, b Type) bool
```

`IntType` と `BoolType` は値レシーバ、`*Func` はポインタレシーバで `Type` を実装する（関数型は常に `*Func`）。

`String()`:

* `Int`、`Bool`
* 引数 1 個の関数型: `P -> R`。ただし `P` が関数型なら `(P) -> R`
  * 例: `Int -> Int`、`(Int -> Int) -> Int`、`Int -> Int -> Int`（結果の関数型には括弧を付けない）
* 引数 0 個: `() -> R`
* 引数 2 個以上: `(P1, P2) -> R`

## `internal/typecheck`

```go
package typecheck

type SymbolKind int

const (
	SymFunc  SymbolKind = iota // top-level function
	SymParam                   // parameter of a FuncDecl or FuncLit
	SymLocal                   // let binding
)

// Symbol is one declared name. Each declaration (every let, even when
// shadowing) gets its own *Symbol.
type Symbol struct {
	Kind SymbolKind
	Name string
	Type types.Type
	Pos  diag.Pos      // position of the declaring name
	Decl *ast.FuncDecl // set only for SymFunc
}

type Info struct {
	Types    map[ast.Expr]types.Type     // type of every expression node
	Uses     map[*ast.Ident]*Symbol      // symbol referenced by every Ident expression
	Defs     map[*ast.LetStmt]*Symbol    // symbol declared by every let
	Params   map[*ast.Param]*Symbol      // symbol declared by every parameter
	Funcs    map[*ast.FuncDecl]*Symbol   // symbol of every top-level function
	FuncLits map[*ast.FuncLit]*types.Func // signature of every anonymous function
}

// Check resolves names and type-checks file. On error it returns (nil, *diag.Error).
func Check(file *ast.File) (*Info, error)
```

### 処理の流れ

```text
Check(file):
    info = new Info with all maps allocated
    globals = map[string]*Symbol

    // 1. collect signatures in source order
    for d in file.Funcs:
        if d.Name in globals: error at d.NamePos "duplicate function 'NAME'"
        sig = &types.Func{Params: resolveType(p.Type) for p, Result: resolveType(d.Result)}
        globals[d.Name] = &Symbol{SymFunc, d.Name, sig, d.NamePos, d}
        info.Funcs[d] = that symbol

    // 2. check bodies in source order
    for d in file.Funcs:
        checkFunc(ctx for d, d.Params, sig, d.Body)

    // 3. entry point
    main = globals["main"]
    if main == nil: error at 1:1 "missing function 'main'"
    if !Equal(main.Type, () -> Int):
        error at main.Pos "function 'main' must have type () -> Int, found T"
    return info
```

`resolveType(t)`:

* `NamedType` の `Int` / `Bool` → `types.Int` / `types.Bool`
* それ以外の `NamedType` → `unknown type 'NAME'`（位置は `NamedType.Pos`）
* `FuncType` → 引数と結果を再帰的に解決した `*types.Func`
* 左から順に解決し、最初のエラーを返す。

### 関数の検査

関数ごとに「関数コンテキスト」を作る（`FuncDecl` と `FuncLit` の両方）。コンテキストはスコープのスタックを持つ。

```text
checkFunc(ctx, params, sig, body):
    scope = new scope owned by ctx
    for i, p in params:
        if p.Name already in this params scope: error at p.Pos "duplicate parameter 'NAME'"
        sym = &Symbol{SymParam, p.Name, sig.Params[i], p.Pos, nil}
        info.Params[p] = sym; scope[p.Name] = sym
    expect(body, sig.Result)
```

`FuncDecl` の引数型は手順 1 で解決済みの `sig` を使う。`FuncLit` は検査時に引数型と結果型を解決する。

### 名前の参照

`Ident` の解決順:

1. 現在の関数コンテキストのスコープを内側から外側へ
2. 外側の関数コンテキスト（匿名関数を囲む関数）のスコープを内側から外側へ
3. `globals`

2 で見つかった場合は `cannot capture 'NAME' in anonymous function: closures are not supported in v0.1` とする。
どこにもなければ `undefined name 'NAME'`。位置はどちらも `Ident.Pos`。

見つかった `Symbol` を `info.Uses` に記録し、その型を式の型とする。

### 式の型付け

`infer(e) (types.Type, error)` は式の型を求め、`info.Types[e]` に記録する。
`expect(e, want)` は `infer(e)` の結果が `want` と `Equal` でなければ `expected WANT, found GOT` を返す。

エラー位置には `resultPos(e)` を使う:

* `*ast.BlockExpr` → `resultPos(Result)`
* それ以外 → `e.Position()`

| 式 | 規則 | 型 |
| --- | --- | --- |
| `IntLit` | | `Int` |
| `BoolLit` | | `Bool` |
| `Ident` | 名前の参照 | シンボルの型 |
| `-X` | `expect(X, Int)` | `Int` |
| `!X` | `expect(X, Bool)` | `Bool` |
| `X + - * / Y` | `expect(X, Int)`、`expect(Y, Int)` | `Int` |
| `X < <= > >= Y` | `expect(X, Int)`、`expect(Y, Int)` | `Bool` |
| `X == != Y` | `t = infer(X)`。`t` が `Int` でも `Bool` でもなければ `cannot compare values of type T`（位置 `resultPos(X)`）。`expect(Y, t)` | `Bool` |
| `X && \|\| Y` | `expect(X, Bool)`、`expect(Y, Bool)` | `Bool` |
| `F(A...)` | 下記 | 関数型の結果 |
| `if C {T} else E` | 下記 | 分岐の型 |
| `{ lets; R }` | 下記 | `R` の型 |
| `fn(P...) -> R {B}` | 下記 | `*types.Func` |

呼び出し:

```text
ft = infer(F)
if ft is not *types.Func: error at resultPos(F) "cannot call non-function value of type T"
if len(Args) != len(ft.Params):
    error at LParen "wrong number of arguments: expected N, found M"
for i: expect(Args[i], ft.Params[i])
type = ft.Result
```

`if`:

```text
expect(Cond, Bool)
tt = infer(Then)
et = infer(Else)
if !Equal(tt, et): error at resultPos(Else) "if branches have different types: TT and ET"
type = tt
```

ブロック:

```text
push scope
for l in Lets:
    if l.Type != nil: want = resolveType(l.Type); expect(l.Value, want); t = want
    else: t = infer(l.Value)
    sym = &Symbol{SymLocal, l.Name, t, l.NamePos, nil}
    info.Defs[l] = sym; scope[l.Name] = sym   // same-scope shadowing overwrites
type = infer(Result)
pop scope
```

`let` の値は、その `let` が宣言する名前が見える前に検査する（`let x = x + 1` の右辺の `x` は外側の `x`）。

匿名関数:

```text
sig = &types.Func{resolveType(p.Type) for p, resolveType(Result)}
info.FuncLits[lit] = sig
checkFunc(new ctx whose parent is the current ctx, lit.Params, sig, lit.Body)
type = sig
```

## エラーの一覧

| メッセージ | 位置 |
| --- | --- |
| `duplicate function 'NAME'` | 2 つ目の宣言の `NamePos` |
| `duplicate parameter 'NAME'` | 2 つ目の引数の `Pos` |
| `unknown type 'NAME'` | `NamedType.Pos` |
| `undefined name 'NAME'` | `Ident.Pos` |
| `cannot capture 'NAME' in anonymous function: closures are not supported in v0.1` | `Ident.Pos` |
| `expected T, found U` | `resultPos(式)` |
| `cannot compare values of type T` | `resultPos(X)` |
| `cannot call non-function value of type T` | `resultPos(F)` |
| `wrong number of arguments: expected N, found M` | `CallExpr.LParen` |
| `if branches have different types: T and U` | `resultPos(Else)` |
| `missing function 'main'` | `1:1` |
| `function 'main' must have type () -> Int, found T` | `main` の `NamePos` |

## テスト観点

テーブル駆動。ソースを `parser.ParseFile` で解析してから `Check` を呼ぶ。各テストとサブテストで `t.Parallel()`。

### `types`

* `String()`: `Int`、`Bool`、`Int -> Int`、`(Int, Bool) -> Int`、`() -> Int`、`(Int -> Int) -> Int`、`Int -> Int -> Int`
* `Equal`: 同じ構造の関数型、引数の数が違う、結果が違う、`Int` と `Bool`

### `typecheck` の成功ケース

各ケースで `Check` がエラーを返さないこと。いくつかのケースでは、指定した式の型を `Info.Types` から取り出して `String()` で比較する（例: `main` の本体の最後の式）。

* ADR-0001 の `add`、`abs`、`fib` + `main`、`calc`、`apply`、`let double = fn(x: Int) -> Int { x * 2 }`
* 相互再帰（`isEven` / `isOdd` が後方の関数を参照）
* シャドーイング: `let x = 1 let x = x == 1 x` の最後の `x` が `Bool`
* 外側のスコープの参照: ネストしたブロックから外の `let` を参照
* 関数を返す関数: `fn pick(b: Bool) -> Int -> Int { if b { inc } else { fn(x: Int) -> Int { x - 1 } } }`
* 匿名関数からトップレベル関数を参照
* `let f: Int -> Int = inc`
* `Bool` 同士の `==`
* ローカル変数が関数名をシャドーイングする（`let fib = 1 fib + 1`）
* `Info.Uses`: 同じ名前の 2 つの `let` で、参照がそれぞれ正しい `Symbol` を指す

### `typecheck` のエラーケース

メッセージと位置（`err.Error()` の文字列）を完全一致で比較する。

* `let x: Int = true` → `expected Int, found Bool`（`true` の位置）
* `1 + false` → `expected Int, found Bool`（`false` の位置）
* `if` の分岐型の不一致（ADR-0001 の例）→ `if branches have different types: Int and Bool`（`false` の位置）
* `if 1 { 1 } else { 2 }` → `expected Bool, found Int`
* `!1`、`-true`、`1 && true`、`1 < true`
* `1 == true` → `expected Int, found Bool`
* 関数同士の `==` → `cannot compare values of type Int -> Int`
* 未定義の名前、未知の型（引数・結果・`let`・関数型の内側）
* 重複した関数、重複した引数
* 引数の数の誤り、引数の型の誤り、関数でない値の呼び出し（`1(2)`）
* 関数本体の型の誤り（本体がネストしたブロックのとき、位置が最も内側の結果の式になる）
* 匿名関数が外側の引数を捕捉 → `cannot capture 'x' ...`
* 匿名関数が外側の `let` を捕捉
* `main` がない（ほかにエラーがないとき）、`main` の型が違う（`fn main(x: Int) -> Int` → `found Int -> Int`、`fn main() -> Bool`）
* 本体のエラーが `main` がないエラーより先に報告される
