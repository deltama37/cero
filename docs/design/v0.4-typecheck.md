# 設計: v0.4 型検査（let の一般化と匿名関数の型推論）

## 目的

ADR-0006 のとおり、次を型検査に追加する。

* 型注釈を省略した匿名関数の引数と戻り値の型を、単一化で決める。
* 型が未解決の値の呼び出し、`match`、`==` / `!=` を、使い方から型付けする。
* 右辺が匿名関数か名前の `let` を一般化し、参照ごとにインスタンス化する。

その結果を、IR 生成（`docs/design/v0.4-backend.md`）が使えるように `Info` に記録する。

対象外にすること:

* トップレベルの関数の型推論（ADR-0006 で v0.5 に先送りした。構文解析が型注釈を保証する）
* クロージャ（捕捉は v0.1 と同じくエラー）
* 引数とパターン変数の一般化、defaulting、明示的な型引数、type class
* IR 生成の変更（`docs/design/v0.4-backend.md`）
* 複数エラーの報告と警告

## 関連する ADR

* ADR-0002: 比較できる型、クロージャ禁止、エラー報告
* ADR-0003: `match`、パターン、網羅性
* ADR-0004: 硬い型変数と単一化変数、単一化、インスタンス化、決まらない型引数のエラー
* ADR-0006: 型注釈の省略、呼び出し・`match`・`==` の型付け、let の一般化、単一化変数の名前

## 前提

`docs/design/v0.3-typecheck.md` と `docs/design/v0.4-frontend.md` の内容が実装済みであること。本書は差分だけを書く。

**このフェーズは `docs/design/v0.4-backend.md` と同じ実装単位で行う。**
一般化により、既存の E2E テスト（`internal/driver` の `let bound to a generic function`）の `let f = identity` が一般化される。
IR 生成の対応（`v0.4-backend.md`）がないと、そのテストが `panic` するためである。

## `internal/types`

### 公開する関数

```go
// Metas returns the unsolved metas that occur in t, following solved metas.
// They are listed once each, in order of first occurrence in a depth-first,
// left-to-right walk: a function's parameters before its result, and a named
// type's arguments in order. It returns nil when there are none.
func Metas(t Type) []*Meta
```

```text
Metas(t):
    out = nil; seen = set
    walk(t):
        t = Prune(t)
        switch t:
        case *Meta:  if t not in seen: seen.add(t); out.append(t)   // unsolved here
        case *Func:  walk(p) for p in Params; walk(Result)
        case *Named: walk(a) for a in Args
        default:     nothing
    walk(t)
    return out
```

## `internal/typecheck`

### 公開要素の変更

`Symbol.TypeParams` と `Info.TypeArgs` のコメントだけを変える。フィールドは増やさない。

```go
type Symbol struct {
	// ... unchanged ...

	// TypeParams are the type parameters Type is generic over: the function's
	// own for a generic SymFunc, Ctor.Data.Params for a SymCtor, the ones
	// created by generalization for a generalized let (SymLocal), and nil
	// otherwise.
	TypeParams []*types.TypeParam
}

type Info struct {
	// ... unchanged ...

	// TypeArgs holds, for every Ident whose symbol has TypeParams (including
	// a generalized let), the type arguments of that use in TypeParams order.
	TypeArgs map[*ast.Ident][]types.Type
}
```

* 一般化した `let` の `Symbol` は `Kind: SymLocal` で、`TypeParams` が空でない。`Type` はその `TypeParams` を含む型である。
* 一般化した `let` の右辺の中の式の型（`Types`、`FuncLits`、`Params`、`Defs`、`PatVars`、`TypeArgs`）は、その `let` の `TypeParams` を含みうる。
* **`Check` が返す `Info` に `*types.Meta` が 1 つも現れないこと（v0.3）は変わらない。** 対象に、`Params` のシンボルの `Type` と `FuncLits` の値も含む（v0.4 では型注釈から作らない引数があるため）。

### checker の状態

```go
type checker struct {
	info    *Info
	globals map[string]*Symbol
	datas   map[string]*types.Data
	ctors   map[string]*types.Ctor
	tparams map[string]*types.TypeParam
	metas   []*pendingMeta // created while checking the current top-level function, in creation order
	fresh   int            // number of t1, t2, ... names used in the current top-level function
}

// pendingMeta remembers where a unification variable was created so that an
// unsolved one can be reported.
type pendingMeta struct {
	meta *types.Meta
	pos  diag.Pos
	msg  string // the error message reported when meta is still unsolved
}
```

* `pendingMeta` の `owner` フィールドを削除し、報告するメッセージを作成時に `msg` へ入れておく。
* `Check` の手順 2（本体の検査）で、トップレベルの関数ごとに `c.metas = nil` に加えて `c.fresh = 0` にする。

単一化変数を作る処理を 1 か所にまとめる。

```go
// newMeta creates a unification variable named name and remembers it so
// that checkSolved can report msg at pos if it stays unsolved.
func (c *checker) newMeta(name string, pos diag.Pos, msg string) *types.Meta

// freshName returns the next of "t1", "t2", ... for the current top-level function.
func (c *checker) freshName() string
```

```text
newMeta(name, pos, msg):
    m = &types.Meta{Name: name}
    c.metas.append(&pendingMeta{meta: m, pos: pos, msg: msg})
    return m

freshName():
    c.fresh++
    return "t" + strconv.Itoa(c.fresh)   // fmt.Sprintf("t%d", c.fresh) でもよい
```

単一化変数を作る場所と、`newMeta` に渡す引数は次のとおり。

| 場所 | `name` | `pos` | `msg` |
| --- | --- | --- | --- |
| `instantiate`（v0.3） | `tp.Name` | `id.Pos` | `cannot infer type argument 'TP' of 'SYM'; add a type annotation`（`TP` = `tp.Name`、`SYM` = `sym.Name`） |
| 型注釈を省略した匿名関数の引数 | `freshName()` | `p.Pos` | `cannot infer the type of parameter 'NAME'; add a type annotation`（`NAME` = `p.Name`） |
| 型が未解決の値の呼び出しの結果 | `freshName()` | `e.LParen` | `cannot infer the result type of this call; add a type annotation` |
| `match` の照合対象の型引数 | `tp.Name`（データ型の型パラメータ） | 構築子のパターンの `p.Pos` | `cannot infer type argument 'TP' of 'CTOR'; add a type annotation`（`CTOR` = 構築子の名前） |

`instantiate` は、`&types.Meta{...}` を直接作って `c.metas` に追加していた処理を、`c.newMeta(tp.Name, id.Pos, msg)` に置き換える。ほかは v0.3 のまま。

### 未解決の単一化変数の検査（`checkSolved`）

```text
checkSolved():
    for pm in c.metas (creation order):
        if types.Prune(pm.meta) is *types.Meta:
            error at pm.pos pm.msg
```

* v0.3 と同じく、作成順で最初の未解決の変数を報告する。
* 一般化した変数は、解が `*types.TypeParam` になっている（後述）ので、解決済みとして扱われる。

### 匿名関数（`inferFuncLit`）

```text
inferFuncLit(ctx, e):
    sig = &types.Func{Params: make([]types.Type, len(e.Params))}
    for i, p in e.Params:                       // left to right
        if p.Type == nil:
            sig.Params[i] = c.newMeta(c.freshName(), p.Pos, "cannot infer the type of parameter 'NAME'; add a type annotation")
        else:
            sig.Params[i] = resolveType(p.Type)  // error → return
    if e.Result != nil:
        sig.Result = resolveType(e.Result)       // error → return
    // else sig.Result stays nil until the body has been checked
    info.FuncLits[e] = sig
    child = &funcCtx{parent: ctx}
    checkFunc(child, e.Params, sig, e.Body)      // error → return
    return sig
```

* 型注釈がすべて書かれた匿名関数の処理（`resolveType` の順序とエラー）は v0.3 と同じになる。
  v0.3 の `resolveFuncType(e.Params, e.Result)` の呼び出しは、上の処理に置き換える。`resolveFuncType` はトップレベルの関数のシグネチャで引き続き使う。
* `checkFunc` は次のように変える。`sig.Result` が `nil` のときだけ処理が変わる。

```text
checkFunc(ctx, params, sig, body):
    ... parameters (v0.3) ...
    if sig.Result == nil:
        t = infer(ctx, body)          // error → return
        sig.Result = t
        return nil
    return expect(ctx, body, sig.Result)
```

* 戻り値の型を省略した匿名関数は自分自身を名前で参照できないので、本体を検査する前に戻り値の型が要ることはない。そのため、戻り値には単一化変数を作らない。

### 呼び出し（`inferCall`）

構築子の呼び出しへの振り分けと、`ft = infer(e.Fn)` までは v0.3 のまま。その後を次のように変える。

```text
switch callee = types.Prune(ft):
case *types.Func:
    ... v0.3 のまま（引数の個数、expect(arg, callee.Params[i])、callee.Result を返す）...
case *types.Meta:
    argTypes = []
    for arg in e.Args: argTypes.append(infer(ctx, arg))   // left to right; error → return
    res = c.newMeta(c.freshName(), e.LParen, "cannot infer the result type of this call; add a type annotation")
    want = &types.Func{Params: argTypes, Result: res}
    if !unify(want, callee):
        error at resultPos(e.Fn) "expected WANT, found FT"     // WANT = want, FT = ft (String() after unify)
    return res
default:
    error at resultPos(e.Fn) "cannot call non-function value of type FT"   (v0.3)
```

* `callee` は `switch` の時点で未解決だが、引数の推論の途中で解が決まることがある（`fn(f, x) { f(f(x)) }` の外側の `f` は、内側の `f(x)` を検査した時点で関数型になる）。
  `unify` は両辺を `Prune` するので、そのまま `unify(want, callee)` を呼べばよい。その場合は通常の関数型どうしの単一化になる。
* `callee` が未解決のままなら、`unify` が失敗するのは出現検査に引っかかるとき（`f(f)` など）だけである。
* 引数が 0 個なら `want` は `() -> ?r` になる。

### 等値比較（`inferBinary` の `==` / `!=`）

```text
case token.Eq, token.NotEq:
    t = infer(ctx, e.X)                                  // error → return
    if types.Prune(t) is *types.Meta:
        expect(ctx, e.Y, t)                              // error → return
        if !types.Equal(t, Int) && !types.Equal(t, Bool):
            error at resultPos(e.X) "cannot compare values of type T"   // T = t (String() at this point)
        return Bool
    ... v0.3 のまま（比較できる型かを確かめてから expect(ctx, e.Y, t)）...
```

* 左辺の型が決まっている場合の検査の順序とメッセージは v0.3 と同じである。

### `match` 式（`inferMatch`）

照合対象の型の検査の前に、照合対象が未解決の単一化変数なら、アームのパターンから型を決める処理を入れる。

```text
st = infer(m.Scrutinee)                                  // error → return
if mv, ok = types.Prune(st).(*types.Meta); ok:
    inferScrutinee(mv, m.Arms)                           // error → return
switch types.Prune(st):                                  // v0.3 のまま
case *types.Func:      "cannot match on values of type T"
case *types.TypeParam: "cannot match on values of type T"
case *types.Meta:      "cannot infer the type of the matched value; add a type annotation"
... (v0.3 のまま)
```

```go
// inferScrutinee solves mv, the unsolved type of a matched value, from the
// first arm whose pattern is a constructor, integer or boolean pattern. It
// leaves mv unsolved when every pattern is '_' or a variable.
func (c *checker) inferScrutinee(mv *types.Meta, arms []*ast.MatchArm) *diag.Error
```

```text
inferScrutinee(mv, arms):
    for arm in arms:
        switch p = arm.Pattern:
        case *ast.CtorPat:
            ctor = c.ctors[p.Name]
            if ctor == nil: error at p.Pos "unknown constructor 'NAME'"      // checkPattern と同じメッセージ
            var args []types.Type                                         // nil when the data type has no parameters
            for tp in ctor.Data.Params:
                args.append(c.newMeta(tp.Name, p.Pos, "cannot infer type argument 'TP' of 'CTOR'; add a type annotation"))
            mv.Solution = &types.Named{Data: ctor.Data, Args: args}
            return nil
        case *ast.IntPat:
            mv.Solution = types.Int; return nil
        case *ast.BoolPat:
            mv.Solution = types.Bool; return nil
        // *ast.WildcardPat, *ast.VarPat: look at the next arm
    return nil
```

* `mv` は未解決なので、`unify` を使わずに直接 `Solution` を設定してよい（新しい型は `mv` を含まないので出現検査は不要）。
* 型を決めた後の処理（各アームの `checkPattern`、網羅性、アームの型の単一化）は v0.3 のまま。
  型を決めたパターン以外のパターンがその型に合わなければ、v0.3 の `checkPattern` のエラーになる。

### let の一般化（`inferBlock`）

`inferBlock` の `let` の処理の最後（`checkBindable` の後、シンボルを作るところ）を次のように変える。
右辺の検査（型注釈の有無で `expect` か `infer`）と `checkBindable` は v0.3 のまま。

```text
var tps []*types.TypeParam
if generalizable(l.Value):
    t, tps = c.generalize(ctx, t)
sym = &Symbol{Kind: SymLocal, Name: l.Name, Type: t, Pos: l.NamePos, TypeParams: tps}
info.Defs[l] = sym
ctx.scope.names[l.Name] = sym
```

```go
// generalizable reports whether a let whose value is e may be generalized:
// e is an anonymous function or a name (ADR-0006).
func generalizable(e ast.Expr) bool

// generalize turns the unsolved metas of t that do not occur in the type of
// any local symbol in scope into new type parameters, by solving each such
// meta to its type parameter. It returns t resolved and the type parameters
// in order of first occurrence in t, or (t, nil) when there are none.
func (c *checker) generalize(ctx *funcCtx, t types.Type) (types.Type, []*types.TypeParam)
```

```text
generalizable(e):
    return e is *ast.FuncLit or *ast.Ident

generalize(ctx, t):
    cand = types.Metas(t)
    if len(cand) == 0: return t, nil
    inEnv = set
    for f = ctx; f != nil; f = f.parent:            // the current function and the enclosing ones
        for s = f.scope; s != nil; s = s.parent:
            for _, sym in s.names:
                for m in types.Metas(sym.Type): inEnv.add(m)
    var tps []*types.TypeParam
    for m in cand:
        if m in inEnv: continue
        tp = &types.TypeParam{Name: m.Name}
        m.Solution = tp
        tps.append(tp)
    if len(tps) == 0: return t, nil
    return types.Resolve(t), tps
```

* スコープにあるのは、局所的な名前（引数、`let`、パターン変数）だけである。グローバルな名前（関数、構築子）の型は単一化変数を含まないので、たどらない。
* 束縛しようとしている `let` 自身は、まだスコープにない（シンボルを登録する前に一般化する）。
* 一般化した単一化変数は、解が型パラメータになるので、右辺の中の式の型も `resolveInfo` でその型パラメータに置き換わる。
* 外側の関数の型パラメータ（`*types.TypeParam`）は単一化変数ではないので、一般化の対象にならない。
* 右辺の型に現れない未解決の単一化変数（`fn(x) { length(Nil) }` の `length` の型引数など）は一般化しない。`checkSolved` でエラーになる。

一般化した `let` の名前の参照（`inferIdent`）は変えない。
`sym.TypeParams` が空でないので、v0.3 の `instantiate` がそのまま新しい単一化変数を作り、`Info.TypeArgs` に記録する。

### `Info` からの単一化変数の除去（`resolveInfo`）

v0.3 の処理に、次の 2 つを加える。

```text
for _, sym in info.Params: sym.Type = types.Resolve(sym.Type)
for lit, sig in info.FuncLits: info.FuncLits[lit] = types.Resolve(sig).(*types.Func)
```

* `Resolve` は `*types.Func` に対して `*types.Func` を返すので、型アサーションは失敗しない。

## エラーの一覧（追加・変更分）

| メッセージ | 位置 |
| --- | --- |
| `cannot infer the type of parameter 'NAME'; add a type annotation` | 匿名関数の引数の `Param.Pos` |
| `cannot infer the result type of this call; add a type annotation` | 呼び出しの `LParen` |
| `expected WANT, found FT`（型が未解決の値の呼び出し） | `resultPos(e.Fn)` |
| `unknown constructor 'NAME'`（`match` の照合対象の型を決めるとき） | 構築子のパターンの `Pos` |

既存のメッセージは変えない。v0.3 で `cannot call non-function value of type ?T` や `cannot infer type argument 'T' of 'None'` だったプログラムの一部は、v0.4 ではエラーにならない（テストの変更を参照）。

## テスト観点

テーブル駆動。各テストとサブテストで `t.Parallel()`。既存のテストは、下に書いた変更を除いてそのまま通ること。

### `types`（`TestMetas`、新規）

各ケースで型を新しく組み立てる。`?a`、`?b`、`?c` は `&Meta{Name: "a"}` などである。

| 入力 | 期待する結果 |
| --- | --- |
| `Int` | `nil` |
| `T`（`TypeParam`） | `nil` |
| `?a` | `[?a]` |
| `?a -> List[?b]` | `[?a, ?b]` |
| `(?a, ?a) -> ?b` | `[?a, ?b]`（重複しない） |
| `?b -> ?a` | `[?b, ?a]`（出現順） |
| `?c`（解 `?a`）`-> Int` | `[?a]`（解をたどる。`?c` は含まない） |
| `?c`（解 `Int`） | `nil` |
| `Pair[?a, Option[?b]]` | `[?a, ?b]` |

比較はポインタで行う（`len` と各要素の `==`）。

### 既存の `typecheck` テストの変更

`TestCheckGenericSuccess`:

* **`later use determines None`**: 名前を `later use instantiates a generalized None` に変え、`check` を次に置き換える。ソースは変えない。
  * `o` の `Defs` のシンボルの型が `Option[T]` で、`TypeParams` の長さが 1、`TypeParams[0].Name == "T"`。
  * `match` の照合対象の `o`（`*ast.Ident`）の `TypeArgs` が `Int`（`wantTypeArgs`）。
  * パターン変数 `n` の型が `Int`（v0.3 のまま）。
* **`let is monomorphic`**: 名前を `let generalizes a generic function` に変え、`check` を次に置き換える。ソースは変えない。
  * `f` の `Defs` のシンボルの型が `T -> T` で、`TypeParams` の長さが 1。
  * `f(5)` の `f`（`*ast.Ident`）の `TypeArgs` が `Int`。

`TestCheckGenericError`:

* **`unsolved None`**: ソースと期待値を次に置き換える（`let x = None` は一般化されてエラーにならなくなったため、一般化しない右辺に変える）。
  * ソース: `"type Option[T] = | None | Some(T)\nfn identity[T](x: T) -> T { x }\nfn main() -> Int { let x = identity(None) 0 }\n"`
  * 期待値: `"3:37: cannot infer type argument 'T' of 'None'; add a type annotation"`
* **`call an unsolved meta`**: このケースを削除する。同じソースは `TestCheckInferSuccess` の `call an unsolved meta makes it a function` に移す。
* **`occurs check on a let binding`**: ソースと期待値を次に置き換える（`let f = identity` は一般化されるため、一般化しない右辺に変える）。
  * ソース: `"fn identity[T](x: T) -> T { x }\nfn main() -> Int { let f = identity(identity) f(f) }\n"`
  * 期待値: `"2:49: expected ?T, found ?T -> ?T"`

### `typecheck` の成功ケース（`TestCheckInferSuccess`、新規）

`TestCheckGenericSuccess` と同じ形のテーブル（`name`、`src`、`wantMain`、`check`）にし、各ケースで `mustCheck` の後に `assertComplete` を呼ぶ。
`P` は既存の `genericPrelude`（`Option`、`List`、`Pair`、`identity`）で、`P` を使うケースはソースの先頭に連結する。

一般化した `let` のシンボルを確かめるヘルパーを追加する。

```go
// wantScheme checks that the let's symbol has type want and type parameters
// named names, in order. names is empty for a monomorphic let.
func wantScheme(t *testing.T, info *Info, l *ast.LetStmt, want string, names ...string)
```

* `info.Defs[l]` がなければ `t.Fatalf`。`Type.String()` が `want` でなければ `t.Errorf`。
* `TypeParams` の長さと各要素の `Name` が `names` と一致しなければ `t.Errorf`。

以下の「`lets[i]`」は `main`（または指定した関数）の本体の `Body.Lets[i]`、「`f` の参照 1、2」は `findIdents(本体, "f")` のうち `let` の右辺以外を出現順に並べたものとする。

| ケース | ソース | 確認すること |
| --- | --- | --- |
| let generalizes a generic function at two types | `P` + `fn main() -> Int { let f = identity if f(true) { f(1) } else { 0 } }` | `wantScheme(lets[0], "T -> T", "T")`。`lets[0]` のシンボルの `Type` の `Params[0]` が `TypeParams[0]` と同じポインタ。`f` の参照 1、2 の `TypeArgs` が `Bool`、`Int` |

### `typecheck` のエラーケース（`TestCheckInferError`、新規）

メッセージと位置（`err.Error()` の文字列）を完全一致で比較する。ソースはケースごとに独立させる（`genericPrelude` は使わない）。

| ケース | ソース | 期待するエラー |
| --- | --- | --- |
| generalized function called with a wrong arity | `fn main() -> Int { let id = fn(x) { x } id(1, 2) }\n` | `1:43: wrong number of arguments: expected 1, found 2` |
| monomorphic let used at two types | `fn identity[T](x: T) -> T { x }\nfn main() -> Int { let g = identity(fn(x) { x }) if g(true) { g(1) } else { 0 } }\n` | `2:65: expected Bool, found Int` |
| unsolved parameter | `fn main() -> Int { let g = if true { fn(x) { 0 } } else { fn(y) { 1 } } 0 }\n` | `1:41: cannot infer the type of parameter 'x'; add a type annotation` |
| unsolved call result | `fn main() -> Int { let g = if true { fn(f) { f(1) } } else { fn(h) { h(2) } } 0 }\n` | `1:47: cannot infer the result type of this call; add a type annotation` |
| occurs check when calling a parameter | `fn main() -> Int { let g = fn(f) { f(f) } 0 }\n` | `1:36: expected ?t1 -> ?t2, found ?t1` |
| compare two unannotated parameters | `fn main() -> Int { let eq = fn(x, y) { x == y } 0 }\n` | `1:40: cannot compare values of type ?t2` |
| match on an unannotated parameter with only a wildcard | `fn main() -> Int { let f = fn(x) { match x { _ => 0 } } 0 }\n` | `1:42: cannot infer the type of the matched value; add a type annotation` |
| match infers from an unknown constructor | `fn main() -> Int { let f = fn(x) { match x { Foo => 0, _ => 1 } } 0 }\n` | `1:46: unknown constructor 'Foo'` |
| pattern of another data type after inference | `type Option[T] = \| None \| Some(T)\ntype List[T] = \| Nil \| Cons(T, List[T])\nfn main() -> Int { let f = fn(o) { match o { Some(n) => n, Nil => 0 } } 0 }\n` | `3:60: expected Option[?T], found List[?T]` |
| literal pattern after a constructor pattern | `type Option[T] = \| None \| Some(T)\nfn main() -> Int { let f = fn(o) { match o { Some(n) => n, 0 => 0 } } 0 }\n` | `2:60: expected Option[?T], found Int` |
| capture a generalized let | `fn main() -> Int { let id = fn(x) { x } let g = fn(y) { id(y) } 0 }\n` | `1:57: cannot capture 'id' in anonymous function: closures are not supported in v0.1` |
| unannotated parameter used as Int and Bool | `fn main() -> Int { let f = fn(x) { if x { x + 1 } else { 0 } } 0 }\n` | `1:43: expected Int, found Bool` |

表の中の `\|` は Markdown のエスケープで、ソースでは `|` と書く。

期待するエラーの補足（実装者が結果を確かめるための説明。テストには書かない）:

* `unsolved parameter`: `if` の両分岐の型を単一化すると `?t1 := ?t2` になる。作成順で最初の `?t1`（`x`）が未解決として報告される。
* `unsolved call result`: 両分岐の単一化で `?t2 := ?t4` になる。作成順で最初の未解決は、解が関数型になった `?t1` を飛ばした `?t2`（`f(1)` の結果）である。
* `compare two unannotated parameters`: `expect(y, ?t1)` が `?t1 := ?t2` とするので、`?t1` は `?t2` と表示される。
* `literal pattern after a constructor pattern`: 最初のアームから型が `Option[?T]` に決まり、2 つ目のアームの `0` が `checkPattern` の `IntPat` の検査で失敗する。
* `unannotated parameter used as Int and Bool`: `if x` で `?t1 := Bool` になり、`x + 1` の `x`（43 列目）が `expected Int, found Bool` になる。

これらの位置とメッセージが実際の結果と食い違う場合は、テストの期待値を書き換えずに報告すること（設計か実装のどちらかの誤りである）。

### テストのヘルパーの変更

`assertComplete`、`walkExpr`、`walkPattern`、`assertNoMeta` は変更しなくてよい。
一般化した `let` のシンボルは `TypeParams` を持つので、`walkExpr` の `*ast.Ident` の検査（`TypeArgs` の個数と、`Subst` した型の一致）がそのまま適用される。
`walkExpr` の `*ast.BlockExpr` の検査（`let` のシンボルの型と右辺の型の一致）も、一般化した `let` では両方が同じ型パラメータを含むので成り立つ。
