# 設計: v0.2 IR・IR 生成・WebAssembly バックエンド（代数的データ型と `match`）

## 目的

型検査済みの `type` 宣言・構築子・`match` 式を IR に変換し、ADR-0003 のヒープ表現で WebAssembly に出力する。
これにより、データ型を使うプログラムを `ceroc build` / `ceroc run` で実行できるようにする。

対象外にすること:

* メモリの回収（ADR-0003 で v0.2 では回収しない）
* フィールドのない構築子の値を静的領域に置く最適化
* `br_table` による分岐（タグの比較を `if` で連ねる）
* WAT の出力、WASI、import（ADR-0002・ADR-0003 のまま）

## 関連する ADR

* ADR-0002: 値の表現、lambda lifting、`ceroc run`
* ADR-0003: データ型の値の表現、ブロックのレイアウト、バンプアロケータ、補助関数

## `internal/ir`

### 値型

```go
const (
	Int     ValType = iota
	Bool
	FuncRef
	Ptr // address of a heap block holding a data type value
)
```

`Ptr.String()` は `"Ptr"` を返す。

### 追加するノード

```go
// Construct allocates a block for the constructor with tag Tag, stores
// Fields into it, and yields its address.
type Construct struct {
	Tag    int
	Fields []Expr
}

// Field loads field Index of the block whose address is in Local.
type Field struct {
	Local LocalID // a Ptr local
	Index int
	T     ValType
}

// SwitchTag reads the tag of the block whose address is in Local and yields
// the Body of the first case with that tag, or Default when no case matches.
// Default is nil when Cases cover every constructor. Cases is never empty
// when Default is nil.
type SwitchTag struct {
	Local   LocalID // a Ptr local
	Cases   []*TagCase
	Default Expr
	T       ValType
}

// TagCase is one case of SwitchTag. It is not an Expr.
type TagCase struct {
	Tag  int
	Body Expr
}
```

`Type()`: `Construct` → `Ptr`、`Field` → `T`、`SwitchTag` → `T`。いずれもポインタで `Expr` を実装する。

### テキスト表示

| ノード | 形式 | 例 |
| --- | --- | --- |
| `Construct` | `(construct TAG FIELD...)` | `(construct 0)`、`(construct 1 1 (construct 0))` |
| `Field` | `(field LOCAL INDEX)` | `(field 1 0)` |
| `SwitchTag` | `(switch.tag LOCAL CASE... [DEFAULT])` | `(switch.tag 1 (case 0 0) (case 1 (local 2)))` |
| `TagCase` | `(case TAG BODY)` | `(case 0 0)` |
| 既定 | `(default BODY)` | `(default 7)` |

`Default` が `nil` なら `(default ...)` を出力しない。

## `internal/lower`

### 型の変換

`valType` に `*types.Data` → `ir.Ptr` を追加する。

### 構築子

| AST | IR |
| --- | --- |
| `Ident`（`SymCtor`、フィールドなし） | `Construct{Tag: ctor.Index}` |
| `F(A...)`、`F` が `SymCtor` の `Ident` | `Construct{Tag: ctor.Index, Fields: A を左から変換}` |

構築子の呼び出しでは `F`（`Ident`）自体は変換しない。`lowerCall` の先頭、v0.1 の `SymFunc` の分岐より前で判定する。

### `match` 式

`convert` の型スイッチに `case *ast.MatchExpr:` を追加する。どの場合も、次の順で変換する。

1. 照合対象の式を変換する。
2. 照合対象の型のローカル `s` を 1 つ割り当てる（`Locals` の末尾に追加）。
3. アームを上から順に変換する。各アームでは、パターンが束縛するローカルを左から割り当ててから、本体を変換する。
4. 結果を `Block{Lets: [Let{s, 照合対象}], Result: R}` とする。`R` は下記。

パターンの変数の扱い:

* 構築子パターンの引数の `VarPat`: 新しいローカル `x`（フィールドの型）を割り当て、`Let{x, Field{s, i, 型}}` を作る。`_` は何もしない。
* アーム全体の `VarPat`: 新しいローカルは作らず、そのシンボルを `s` に対応づける（`locals[sym] = s`）。

アームの本体（`body(arm)`）は、パターンが作った `Let` があれば `Block{Lets, 本体}`、なければ本体の変換結果そのものとする。

データ型の照合（`R` は `SwitchTag`）:

```text
cases = []; def = nil
for arm in arms:
    if arm.Pattern is CtorPat: cases.append(TagCase{ctor.Index, body(arm)})
    else: def = body(arm)          // WildcardPat or VarPat; always the last arm
R = SwitchTag{Local: s, Cases: cases, Default: def, T: match の型}
```

`Int` と `Bool` の照合（`R` は `If` の連鎖）:

```text
chain(i):
    arm = arms[i]
    if arm.Pattern is WildcardPat or VarPat: return body(arm)
    if i == len(arms) - 1: return body(arm)   // exhaustive, so this is the only value left
    lit = IntConst{v} or BoolConst{v}
    then = body(arm)
    return If{Cond: Binary{Eq, LocalGet{s, 型}, lit}, Then: then, Else: chain(i + 1), T: match の型}
R = chain(0)
```

`chain` は各アームの本体（`then`）を、後続のアーム（`chain(i + 1)`）より先に変換する。これにより、ローカルの番号はアームの順に増える。

型検査で到達不能なアームと網羅性の漏れはエラーになっているので、全体のパターンは必ず最後のアームにだけ現れる。

## `internal/wasm`

### 値型

`ir.Ptr` は `i32`（`0x7F`）とする。

### メモリを使うかどうか

```go
// usesMemory reports whether any function body contains a Construct,
// Field or SwitchTag node.
func usesMemory(m *ir.Module) bool
```

`usesMemory(m)` が偽なら、出力は v0.1 と 1 バイトも変わらない（v0.1 のゴールデンテストはそのまま通る）。
以下の追加は、すべて `usesMemory(m)` が真のときだけ行う。

### 追加するセクション

Table（ID 4）と Export（ID 7）の間に、次の 2 つをこの順で出力する。

1. Memory（ID 5）: メモリ 1 個。limits `0x01 min max`、min = 1、max = 32768（2 GiB）。バイト列は `05 06 01 01 01 80 80 02`。
2. Global（ID 6）: グローバル 1 個（ヒープの次の空き位置）。`i32`、ミュータブル、初期値 `i32.const 8`。バイト列は `06 06 01 7F 01 41 08 0B`。

max を 32768 ページにするのは、`memory.size` をバイト数に直した値（ページ数 × 65536）が `i32` の符号なしの範囲に収まるようにするためである。

### 補助関数

IR の関数の後ろに、次の補助関数を追加する。関数インデックスは `len(m.Funcs)` から順に振る。補助関数はテーブルにもエクスポートにも入れない。

1. `alloc`（インデックス `len(m.Funcs)`）: `(i32) -> i32`。引数 `size` のバイト数を確保し、先頭アドレスを返す。
2. 構築子ごとの補助関数 `new`: `(i32, F0, ..., Fn-1) -> i32`。引数はタグとフィールドの値。ブロックを確保し、タグとフィールドを格納して、先頭アドレスを返す。
   * フィールドの wasm の値型の列（例: `i64 i32`）ごとに 1 つ作る。構築子の数ではなく、値型の列の種類の数だけ作る。
   * 順番は、`Module.Funcs` の順に各本体を前順で走査し、`Construct` の値型の列が初めて現れた順とする。

`alloc` の本体（ローカル: 引数 `size` = 0、`p` = 1 の `i32`。ローカル宣言は `01 01 7F`）:

```text
23 00          global.get 0        ;; p = heap
21 01          local.set 1
23 00          global.get 0        ;; heap = heap + size
20 00          local.get 0
6A             i32.add
24 00          global.set 0
23 00          global.get 0        ;; if heap > memory.size * 65536
3F 00          memory.size
41 10          i32.const 16
74             i32.shl
4B             i32.gt_u
04 40          if
23 00            global.get 0      ;;   pages = (heap - memory.size * 65536 + 65535) >> 16
3F 00            memory.size
41 10            i32.const 16
74               i32.shl
6B               i32.sub
41 FF FF 03      i32.const 65535
6A               i32.add
41 10            i32.const 16
76               i32.shr_u
40 00            memory.grow
41 7F            i32.const -1      ;;   if memory.grow failed: trap
46               i32.eq
04 40            if
00                 unreachable
0B               end
0B             end
20 01          local.get 1
0B             end
```

フィールドが n 個の `new` の本体（引数: タグ = 0、フィールド i = i + 1。ローカル `p` = n + 1 の `i32`。ローカル宣言は `01 01 7F`）:

```text
41 sleb(8 + 8n)            i32.const size
10 uleb(alloc)             call alloc
21 uleb(n+1)               local.set p
20 uleb(n+1) 20 00 36 02 00                       ;; i32.store align=2 offset=0 (tag)
for i in 0..n-1:
    20 uleb(n+1) 20 uleb(i+1) STORE uleb(8 + 8i)  ;; field i
20 uleb(n+1)               local.get p
0B                         end
```

`STORE` はフィールドが `i64` なら `37 03`（`i64.store align=3`）、`i32` なら `36 02`（`i32.store align=2`）とする。

### 型インデックス

v0.1 の走査（関数のシグネチャ → `CallIndirect` の `Sig`）の後に、次をこの順で追加する（重複排除は v0.1 と同じ）。

1. `alloc` の型 `(i32) -> i32`
2. 各 `new` の型（補助関数の順）

`ir.Sig` で表すときは、`i32` に `ir.Ptr`、`i64` に `ir.Int` を使う（`sigKey` は wasm の値型で比較するので、`Bool` や `FuncRef` の型と同じインデックスになってよい）。

### Function セクションと Code セクション

* Function セクション: IR の関数の型インデックスの後に、補助関数の型インデックスを補助関数の順に続ける。
* Code セクション: IR の関数の本体の後に、補助関数の本体を補助関数の順に続ける。要素数は `len(m.Funcs) + 補助関数の数`。

### 命令の生成（追加分）

| IR | 命令 |
| --- | --- |
| `Construct` | `i32.const Tag`（`0x41` + sleb128）、各フィールドを左から、`call new`（その値型の列の補助関数） |
| `Field`（`T` が `Int`） | `local.get Local`、`i64.load`（`29 03` + uleb128(8 + 8 × Index)） |
| `Field`（それ以外） | `local.get Local`、`i32.load`（`28 02` + uleb128(8 + 8 × Index)） |
| `SwitchTag` | 下記 |

`SwitchTag` は、タグを毎回読み直す `if` の連鎖にする。

```text
emit(i):
    if Default == nil and i == len(Cases) - 1: emit Cases[i].Body; return
    if i == len(Cases): emit Default; return
    local.get Local; i32.load align=2 offset=0 (28 02 00)
    i32.const Cases[i].Tag; i32.eq (46)
    if (result T); emit Cases[i].Body; else; emit(i + 1); end
emit(0)
```

`walk`（前順の走査）に次を追加する。

* `Construct`: `Fields` を左から
* `Field`: 子なし
* `SwitchTag`: `Cases` の `Body` を順に、最後に `Default`（`nil` でなければ）

## サンプル（`examples/list.cero`）

先頭のコメントに期待する出力 `15` を書く。

```text
// expected output: 15

type IntList =
    | Nil
    | Cons(Int, IntList)

fn range(from: Int, to: Int) -> IntList {
    if from > to {
        Nil
    } else {
        Cons(from, range(from + 1, to))
    }
}

fn sum(xs: IntList) -> Int {
    match xs {
        Nil => 0,
        Cons(x, rest) => x + sum(rest),
    }
}

fn main() -> Int {
    sum(range(1, 5))
}
```

## テスト観点

テーブル駆動。各テストとサブテストで `t.Parallel()`。既存のテストはそのまま通ること。

### `ir`

* `Ptr.String()` が `Ptr`
* 手組みの `Construct`、`Field`、`SwitchTag`（`Default` あり・なし）の表示
* `Type()` の表（`Construct` → `Ptr` など）

### `lower`

ソースを `parser.ParseFile` → `typecheck.Check` → `Lower` と通し、`ir.Format` の結果を完全一致で比較する。

* フィールドのない構築子: `type U = U` と `fn main() -> Int { match U { U => 7 } }` → `main` の本体が `(block (let 0 (construct 0)) (switch.tag 0 (case 0 7)))`
* 入れ子の構築子: `Cons(1, Cons(2, Nil))` → `(construct 1 1 (construct 1 2 (construct 0)))`
* `sum` の `match`: 引数 `xs` が local 0 のとき `(block (let 1 (local 0)) (switch.tag 1 (case 0 0) (case 1 (block (let 2 (field 1 0)) (let 3 (field 1 1)) (add (local 2) (call ID (local 3)))))))`
* 構築子パターンの `_` はローカルを作らない: `Cons(x, _)` で `(let N (field S 0))` だけ
* ワイルドカードのアームが `(default ...)` になる
* アーム全体の変数パターンが `s` を参照する（`other => f(other)` の `other` が `(local S)`）
* 整数パターン: `match n { 0 => 10, 1 => 20, _ => 30 }`（`n` が local 0）→ `(block (let 1 (local 0)) (if (eq (local 1) 0) 10 (if (eq (local 1) 1) 20 30)))`
* 真偽値パターンで最後のアームにテストがない: `match b { true => 1, false => 0 }` → `(block (let 1 (local 0)) (if (eq (local 1) true) 1 0))`
* ローカルの型: データ型の引数と `s` が `Ptr`、フィールドの変数がフィールドの型（`(locals Ptr Ptr Int Ptr)` など）
* 匿名関数の中の `match`: 持ち上げた関数の中でローカルが割り当てられる

### `wasm`

* v0.1 のゴールデン（`fn main() -> Int { 42 }`）が変わらない
* `usesMemory` が偽のモジュールに Memory・Global セクションがなく、関数の数が IR と同じ
* データ型を使うモジュールで、セクション ID の並びが `1 3 4 5 6 7 10`（テーブルが空でないときは `1 3 4 5 6 7 9 10`）
* Memory セクションが `05 06 01 01 01 80 80 02`、Global セクションが `06 06 01 7F 01 41 08 0B`
* `alloc` の本体（ローカル宣言 `01 01 7F` の後の命令列）が、上記の命令列と完全一致する
* 補助関数の重複排除: フィールドの値型の列が同じ構築子（`A(Int)` と `B(Int)`）で `new` が 1 つ、`A(Int)` と `C(Bool)` で 2 つ
* `new` の本体（ローカル宣言の後の命令列）: フィールドなし（`41 08 10 A 21 01 20 01 20 00 36 02 00 20 01 0B`、`A` は `alloc` のインデックス）と、`(Int, Ptr)` の 2 フィールド
* Export の `main` のインデックスが、補助関数を追加しても変わらない
