# 設計: v0.3 フロントエンド（字句解析・AST・構文解析）

## 目的

ADR-0004 の型パラメータの宣言（`fn f[T]`、`type Option[T]`）と型の適用（`Option[Int]`）を、字句解析・AST・構文解析に追加する。

対象外にすること:

* 名前解決と型検査（`docs/design/v0.3-typecheck.md`）
* 型パラメータの名前の重複・衝突、型引数の個数の検査（型検査で行う）
* 明示的な型引数（`identity[Int](1)`）、匿名関数の型パラメータ（ADR-0004 で v0.3 の対象外。構文エラーにする）
* エラー回復（これまでと同じく最初のエラーで止まる）

## 関連する ADR

* ADR-0002: 具体構文、エラー報告の方針
* ADR-0003: `type` 宣言、大文字で始まる名前の規則
* ADR-0004: 型パラメータと型の適用の構文

## 前提

`docs/design/v0.1-frontend.md` と `docs/design/v0.2-frontend.md` の内容が実装済みであること。本書は v0.2 からの差分だけを書く。書いていない点は v0.2 の設計のままとする。

## 変更するパッケージとファイル

| パッケージ | ファイル | 内容 |
| --- | --- | --- |
| `internal/token` | `token.go`, `token_test.go` | `[` と `]` のトークン |
| `internal/lexer` | `lexer.go`, `lexer_test.go` | `[` と `]` を読む |
| `internal/ast` | `ast.go`, `print.go`, `print_test.go` | `TypeParam`、`TypeParams` フィールド、`NamedType.Args` |

## `internal/token`

Punctuation のグループの末尾（`Bar` の後）に 2 つ追加する。既存の定数の順序は変えない。

```go
	FatArrow // =>
	Bar      // |
	LBracket // [
	RBracket // ]
```

* `Kind.String()` は `LBracket` に `'['`、`RBracket` に `']'` を返す。
* `Keywords` は変えない。

## `internal/lexer`

* 1 文字の記号に `[`（`LBracket`）と `]`（`RBracket`）を追加する（`matchOne`）。
* これまで `[` と `]` は `unexpected character` だったが、その規則はなくなる。既存のテストに `[` を使うエラーケースはない。

## `internal/ast`

### 追加する型

```go
// TypeParam declares one type parameter in "[T, U]". Name starts with an
// uppercase ASCII letter.
type TypeParam struct {
	Pos  diag.Pos
	Name string
}
```

`TypeParam` は `Expr`、`TypeExpr`、`Pattern` のどれでもない。

### 変更する型

```go
// TypeDecl is a top-level algebraic data type declaration.
type TypeDecl struct {
	Pos        diag.Pos // 'type'
	Name       string
	NamePos    diag.Pos
	TypeParams []*TypeParam // nil when written without brackets
	Ctors      []*CtorDecl  // at least one
}

// FuncDecl is a top-level function declaration.
type FuncDecl struct {
	Pos        diag.Pos // 'fn'
	Name       string
	NamePos    diag.Pos
	TypeParams []*TypeParam // nil when written without brackets
	Params     []*Param
	Result     TypeExpr
	Body       *BlockExpr
}

// NamedType is a type referred to by name, optionally applied to type
// arguments.
type NamedType struct {
	Pos  diag.Pos
	Name string     // "Int", "Bool", a type parameter, a declared type, or an unknown name (rejected by the type checker)
	Args []TypeExpr // type arguments in "Name[A, B]"; nil when written without brackets
}
```

* 角括弧を書いたときは `TypeParams` と `Args` は 1 要素以上の非 nil のスライスになる（空の `[]` は構文エラー）。
* `FuncLit` は変えない（匿名関数は型パラメータを持たない）。

### S 式表示（`print.go`）

追加する非公開の関数:

```go
// formatTypeParams returns "" for no type parameters, otherwise "[" + the
// names joined by " " + "]".
func formatTypeParams(ps []*TypeParam) string
```

| ノード | 形式 | 例 |
| --- | --- | --- |
| `NamedType`（`Args` なし） | 名前 | `Int` |
| `NamedType`（`Args` あり） | `NAME[ARG ...]`（引数を `" "` で区切る） | `Option[Int]`、`Pair[Int Bool]`、`List[List[T]]`、`Option[(-> (Int) Int)]` |
| `TypeDecl` | `(type NAME[TPARAMS] CTOR...)`（`[TPARAMS]` は `formatTypeParams`） | `(type Option[T] (None) (Some T))`、`(type IntList (Nil) (Cons Int IntList))` |
| `FuncDecl` | `(fn NAME[TPARAMS] (PARAMS) RESULT BODY)` | `(fn identity[T] ((x T)) T (block x))`、`(fn main () Int (block 1))` |

* 型パラメータがなければ、`TypeDecl` と `FuncDecl` の表示は v0.2 と 1 文字も変わらない。
* `FuncType` の表示（`(-> (P...) R)`）は変えない。引数や結果に `NamedType` の適用が入れば、その部分だけが上の形式になる（`(-> (Option[Int]) Int)`）。

## `internal/parser`

公開 API（`ParseFile`、`ParseExpr`）のシグネチャは変えない。

### 文法

v0.2 の文法からの変更点だけを書く。

```text
typeDecl   = "type" IDENT [ typeParams ] "=" [ "|" ] ctorDecl { "|" ctorDecl }
funcDecl   = "fn" IDENT [ typeParams ] "(" [ params ] ")" "->" type block
typeParams = "[" IDENT { "," IDENT } "]"
type       = ... (v0.1 と同じ。ただし名前の型を namedType に置き換える)
namedType  = IDENT [ "[" type { "," type } "]" ]
postfix    = primary { "(" [ args ] ")" }      // 直後の "[" はエラー（後述）
```

### 型パラメータのリスト

```go
// parseTypeParams parses "[T, U]". The current token is '['.
func (p *parser) parseTypeParams() ([]*ast.TypeParam, error)
```

```text
parseTypeParams():
    expect "["
    params = []
    loop:
        if cur is not IDENT: error at cur "expected identifier, found D"
        name = cur; advance
        if !isUpperName(name): error at name.Pos "type parameter name 'NAME' must start with an uppercase letter"
        params.append(TypeParam{name.Pos, name})
        if cur is ",": advance; continue
        break
    expect "]"
    return params
```

呼ぶ位置:

* `parseFuncDecl`: 関数名を読んだ直後、`parseParamList` の前で、`cur` が `[` なら呼ぶ。
* `parseTypeDecl`: 型名を読んで大文字の検査をした直後、`expect "="` の前で、`cur` が `[` なら呼ぶ。

`[` がなければ `TypeParams` は `nil` のままにする。

### 型の適用

`parseType` の `case token.Ident:` を次のように変える。ほかの分岐（`(` で始まる型、`->` の処理）は変えない。

```text
case IDENT:
    nameTok = cur; advance
    var args []TypeExpr   // nil
    if cur is "[":
        advance
        args.append(parseType())
        while cur is ",": advance; args.append(parseType())
        expect "]"
    atom = NamedType{nameTok.Pos, nameTok.Text, args}
```

* 引数の中は `parseType` で読むので、関数型（`Option[Int -> Int]`）や入れ子の適用（`List[List[Int]]`）をそのまま書ける。`]` で引数が終わる。
* `Option[Int] -> Int` は、適用を `atom` として読んだ後、v0.1 と同じ `->` の処理で関数型になる。

### 式の中の `[`

`parsePostfix` の呼び出しのループを抜けた直後に、`cur` が `[` なら次のエラーにする。

```text
error at cur.Pos "explicit type arguments are not supported in v0.3"
```

* `identity[Int](1)` は `identity` の後の `[` でこのエラーになる。
* `f(x)[Int]` のように呼び出しの後に `[` が来ても同じエラーになる（ループを抜けた後で調べるため）。

匿名関数に型パラメータを書いた `fn[T](x: T) -> T { x }` は、`parseParamList` の `expect "("` が `expected '(', found '['` を返す。この場合のための追加の処理はしない。

### エラーメッセージ（追加分）

| 状況 | メッセージ | 位置 |
| --- | --- | --- |
| 型パラメータの名前が大文字で始まらない | `type parameter name 'NAME' must start with an uppercase letter` | 名前 |
| 式の中で `[` を書いた | `explicit type arguments are not supported in v0.3` | `[` |

`[]`、`[T,]`、`[T U]`、`Option[]`、`Option[Int` などは、既存の `expected identifier, found D`、`expected type, found D`、`expected ']', found D` になる（`D` は v0.1 の `describe(tok)`）。

## テスト観点

すべてテーブル駆動で、各テストとサブテストで `t.Parallel()` を呼ぶ。既存のテストケースはそのまま通ること。

### `token`

* `Kind.String()`: `LBracket` → `'['`、`RBracket` → `']'`

### `lexer`

* 記号: `[ ]` が `LBracket`、`RBracket` になる（`Text` はそれぞれ `[`、`]`）
* `Option[Int]` が `Ident`、`LBracket`、`Ident`、`RBracket` になる
* `a[b,c]` が `Ident`、`LBracket`、`Ident`、`Comma`、`Ident`、`RBracket` になる

### `ast`

手組みの AST で次を確認する。

* `FormatType`: `NamedType{Name: "Option", Args: [Int]}` → `Option[Int]`、`Pair[Int Bool]`、`List[List[T]]`、引数が関数型の `Option[(-> (Int) Int)]`、関数型の引数が適用 `(-> (Option[Int]) Int)`
* `FormatTypeDecl`: 型パラメータ 1 つ（`(type Option[T] (None) (Some T))`）、2 つ（`(type Pair[A B] (Pair A B))`）、なし（v0.2 と同じ）
* `FormatFunc`: 型パラメータ 1 つ（`(fn identity[T] ((x T)) T (block x))`）、2 つ（`(fn map[T U] ...)`）、なし（v0.2 と同じ）

### `parser`（成功）

`ParseFile` と `ast.FormatFile` を使う。表の中の `\|` は Markdown のエスケープで、ソースでは `|` と書く。

| 入力 | 期待する出力 |
| --- | --- |
| `type Option[T] = \| None \| Some(T)` | `(type Option[T] (None) (Some T))` |
| `type Pair[A, B] = Pair(A, B)` | `(type Pair[A B] (Pair A B))` |
| `type List[T] = Nil \| Cons(T, List[T])` | `(type List[T] (Nil) (Cons T List[T]))` |
| `type Box[T] = Box(T -> T)` | `(type Box[T] (Box (-> (T) T)))` |
| `fn identity[T](x: T) -> T { x }` | `(fn identity[T] ((x T)) T (block x))` |
| `fn map[T, U](xs: List[T], f: T -> U) -> List[U] { xs }` | `(fn map[T U] ((xs List[T]) (f (-> (T) U))) List[U] (block xs))` |
| `fn f(x: Option[List[Int]]) -> Int { 0 }` | `(fn f ((x Option[List[Int]])) Int (block 0))` |
| `fn f(x: Option[Int -> Int]) -> Int { 0 }` | `(fn f ((x Option[(-> (Int) Int)])) Int (block 0))` |
| `fn f(g: Option[Int] -> Int) -> Int { 0 }` | `(fn f ((g (-> (Option[Int]) Int))) Int (block 0))` |
| `fn f(g: (Option[Int], Bool) -> Int) -> Int { 0 }` | `(fn f ((g (-> (Option[Int] Bool) Int))) Int (block 0))` |
| `fn f() -> Int { let x: Option[Int] = None x }` | `(fn f () Int (block (let x : Option[Int] None) x))` |
| `fn f() -> Int { let g = fn(x: List[Int]) -> Int { 0 } 1 }` | `(fn f () Int (block (let g (fn ((x List[Int])) Int (block 0))) 1))` |

加えて、次を確認する。

* 型パラメータなしの宣言で、`TypeDecl.TypeParams` と `FuncDecl.TypeParams` と `NamedType.Args` が `nil` である
* 型パラメータの `Pos` と `Name`（`fn map[T, U]` の `U` が 1 行目の 11 列目）
* `type` と `fn` の宣言が混在する複数行のファイル（ADR-0004 の `Option`、`List`、`map` の例）

### `parser`（エラー）

メッセージと位置を完全一致で比較する（`requireDiag`）。

| 入力 | 期待するエラー |
| --- | --- |
| `fn f[]() -> Int { 1 }` | `1:6: expected identifier, found ']'` |
| `fn f[t]() -> Int { 1 }` | `1:6: type parameter name 't' must start with an uppercase letter` |
| `fn f[T,]() -> Int { 1 }` | `1:8: expected identifier, found ']'` |
| `fn f[T U]() -> Int { 1 }` | `1:8: expected ']', found identifier "U"` |
| `type T[] = A` | `1:8: expected identifier, found ']'` |
| `type Box[a] = B(a)` | `1:10: type parameter name 'a' must start with an uppercase letter` |
| `type Option[T] Some(T)` | `1:16: expected '=', found identifier "Some"` |
| `fn f(x: Option[]) -> Int { 1 }` | `1:16: expected type, found ']'` |
| `fn f(x: Option[Int) -> Int { 1 }` | `1:19: expected ']', found ')'` |
| `fn f(x: Pair[Int Bool]) -> Int { 1 }` | `1:18: expected ']', found identifier "Bool"` |

`ParseExpr` を使うもの:

| 入力 | 期待するエラー |
| --- | --- |
| `identity[Int](1)` | `1:9: explicit type arguments are not supported in v0.3` |
| `f(x)[Int]` | `1:5: explicit type arguments are not supported in v0.3` |
| `fn[T](x: T) -> T { x }` | `1:3: expected '(', found '['` |

## 完了条件

* 上記の変更とテストが存在し、`make check` が通る。
* 型検査・IR 生成・WASM バックエンドのパッケージは変更しない。
  `ast` の構造体にフィールドを足したことでコンパイルが通らなくなる箇所があれば、その箇所だけを最小限に直す（キー付きの複合リテラルはそのままコンパイルできるはずである）。
* このフェーズの終了時点では、型パラメータを使うプログラムは型検査で `unknown type 'T'` などのエラーになってよい。
  型パラメータのないデータ型に型引数を付けた `Box[Int]` が、型検査で `Args` を無視されて通ってしまうことも、このフェーズでは許容する（次のフェーズで検査する）。
