# ADR-0012: v0.10 の IO（副作用の型と WASI）

* Status: Accepted
* Date: 2026-10-06

## Context

ADR-0001 は、副作用を型で区別し、「副作用が通常の純粋関数に暗黙的に入り込まない」ことを基本原則とした。
`IO` の仕組みは「初期段階では固定せず、後続バージョンで設計する」とし、候補に `IO` 型、Effect system、Algebraic Effects を挙げた。
OS の機能は WASI を境界として使い、「WASI を利用できることと、Cero の純粋関数から直接 WASI を呼び出せることは別とする」とした。

ADR-0001 の成長過程では、module の次が「IO / Effect」で、その次が Cero 製 ceroc である。
Cero 製 ceroc は、ソースファイルを読み、WebAssembly のファイルを書き、エラーを標準エラー出力に書く必要がある。

## Decision

### 方式: 不透明な `IO[T]` 型（IO モナド）

組み込みの型 `IO[T]` を追加する。`IO[T]` の値は「実行すると副作用を起こして `T` の値を返す動作」の記述であり、値を作っても副作用は起きない。

* 動作を組み合わせる組み込み関数:
  * `pure[T](x: T) -> IO[T]`: 何もせず `x` を返す動作
  * `bind[A, B](m: IO[A], f: A -> IO[B]) -> IO[B]`: `m` を実行し、その結果に `f` を適用してできた動作を実行する
* `IO[T]` の値を実行する方法は、`main` が返すこと以外にない。`IO[T]` の値から `T` を取り出す関数（`unsafePerformIO` のようなもの）は導入しない。
  `IO[T]` は構築子を持たない型で、`match` で分解できず、`==` で比較できない。
* したがって、`IO` を返さない関数は副作用を起こせない（型が純粋さを保証する）。

検討した方式:

| 方式 | 採用しない / する理由 |
| --- | --- |
| **IO 型（採用）** | 型システムの追加は「構築子のない組み込みの型 1 つ」だけで、クロージャ（ADR-0008）と多相（ADR-0004）の上に組み込み関数として作れる。Haskell で実績がある |
| Effect system（効果の型、行多相） | 関数の型に効果の集合を持たせ、型推論で効果も推論する必要がある。v0.5 の型推論に行多相を加える大きな変更になる |
| Algebraic Effects（ハンドラ） | 限定継続が要る。WebAssembly の stack switching は固定した wasmtime で使えず、CPS 変換はコード生成の全体に及ぶ |

効果の種類を分けたくなった場合（ファイルだけ、標準出力だけ、など）や、ハンドラで差し替えたくなった場合は、そのときに Effect system を別の ADR で検討する。
`IO` を使う側のコードは、`bind` の糖衣構文を後で入れても、組み込み関数として書いたコードと意味が変わらない。

### `Unit` 型

値を返さない動作のために、組み込みの型 `Unit` と、その唯一の値 `()` を追加する。`Unit` は `==` で比較できない（比較する意味がない）。

### 基本の動作（組み込み関数）

| 名前 | 型 | 動作 |
| --- | --- | --- |
| `print` | `(String) -> IO[Unit]` | 標準出力に書く（改行を足さない） |
| `eprint` | `(String) -> IO[Unit]` | 標準エラー出力に書く |
| `readStdin` | `() -> IO[String]` | 標準入力を最後まで読む |
| `readFile` | `(String) -> IO[String]` | ファイルの内容を読む |
| `fileExists` | `(String) -> IO[Bool]` | ファイルを読み取り用に開けるか |
| `writeFile` | `(String, String) -> IO[Unit]` | ファイルを作成（または切り詰め）して書く |
| `argCount` | `() -> IO[Int]` | コマンドライン引数の数（プログラム名を含まない） |
| `argAt` | `(Int) -> IO[String]` | `i` 番目の引数（0 始まり）。範囲外は実行時エラー |
| `exit` | `(Int) -> IO[Unit]` | その終了コードでプログラムを終える |

* ファイルのパスは、プログラムを実行したディレクトリからの相対パスとする（WASI の最初の preopen ディレクトリ）。
* `readFile` と `writeFile` が失敗したときは、標準エラー出力に `error: cannot read file PATH`（または `write`）を書いて、終了コード 1 で終わる。
  失敗を `Option` などの値で返すには、組み込み関数が標準ライブラリの型を知る必要がある。失敗の前に `fileExists` で確かめられるので、v0.10 では値で返さない。
* `List` を返す組み込み関数は作らない（ADR-0010 と同じく、組み込み関数を標準ライブラリに依存させない）。引数は `argCount` と `argAt` で読む。

### `main` と実行

`main` の型は、次のどちらかとする。

* `() -> Int`: これまでどおり。モジュールは `main` だけをエクスポートし、import を持たない。`ceroc run` は戻り値を表示する。
* `() -> IO[Unit]`: **WASI のコマンド**とする。モジュールは `wasi_snapshot_preview1` の関数を import し、`_start` と `memory` をエクスポートする。
  `_start` は `main()` で動作を作り、それを実行する。動作が終わると終了コード 0 で終わる。
  `ceroc run file.cero args...` は、カレントディレクトリを preopen して（`wasmtime run --dir=.`）、引数・標準入出力・終了コードをそのまま渡す。

### 標準ライブラリ `std/io`

組み込み関数の上に、Cero で書いた便利な関数を `std/io` として置く（`then`、`mapIO`、`println`、`forEach` など。一覧は設計書で決める）。

### 表現

* `IO[T]` の値は、引数なしで呼ぶと副作用を起こして `T` を返すクロージャ（ADR-0008 の関数値、`i64`）で表す。
  `pure`・`bind`・基本の動作は、IR 生成で、そのクロージャを作る式になる。基本の動作のクロージャの本体だけが、WASI を呼ぶ IR の命令を含む。
* `bind` のクロージャは、`m` を実行した後、`f` の結果の動作を**末尾呼び出し**で実行する。`bind` を右に入れ子にした長い動作の列（再帰でループする IO）は、スタックを使わずに実行できる。
* `Unit` の値は、IR では `Bool` の偽（`i32` の 0）で表す。

## Consequences

* ファイル・標準入出力・引数を使うプログラムを書けるようになり、Cero 製 ceroc の前提がそろう。
* 純粋な関数の型（`IO` を返さない）は、副作用がないことを保証する。
* `bind(m, fn(x) { ... })` の入れ子は読みにくい。糖衣構文は、Cero 製 ceroc を書いて必要性を確かめてから別の ADR で検討する。
* ファイル操作の失敗の扱いは粗い（終了コード 1 で終わる）。値で返す API は、標準ライブラリの型を組み込み関数から使えるようにする段階で追加する。
* WebAssembly の関数の番号に WASI の import の分のずれが入る。`main` が `() -> Int` のプログラムの出力は変わらない。
* 型（`Unit`、`IO`）、構文（`()`）、型検査（`main` の型）、IR（WASI の命令）、IR 生成（動作のクロージャ）、WebAssembly バックエンド（import、`_start`、補助関数）、ドライバ・CLI（実行の仕方）に変更が及ぶ。
