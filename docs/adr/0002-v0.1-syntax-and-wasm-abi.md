# ADR-0002: v0.1 の具体構文・エラー報告・WebAssembly ABI

* Status: Accepted
* Date: 2026-09-24

## Context

ADR-0001 は Cero v0.1 の言語機能と、`Cero source → AST → 型検査 → IR → WebAssembly` というパイプラインを決めた。
しかし、実装に必要な次の点は決めていない。

* 演算子の優先順位、改行の扱い、関数型の書き方などの具体構文
* コンパイルエラーをいくつ報告するか
* Cero の値を WebAssembly でどう表現するか（ABI）
* `ceroc run` がどの WebAssembly ランタイムを使うか

本 ADR でこれらを決める。実装の詳細は `docs/design/v0.1-*.md` に書く。

## Decision

### 具体構文

* トップレベルには関数宣言 `fn name(params) -> Type { ... }` だけを書ける。
* 改行は空白と同じに扱う。文の区切り記号（`;`）は導入しない。
  * ブロックは `{ let 束縛* 式 }` の形しか取らないので、区切りがなくても構文は一意に決まる。
  * そのため `let y = x` の次の行を `-x` で始めると `let y = x - x` と解釈される。v0.1 ではこの制約を許容する。
* `if` は `else` を必須とする。v0.1 には Unit 型がないため、`else` のない `if` は値を持てない。`else if` は書ける。
* ブロック `{ ... }` は式であり、式を書ける場所ならどこにでも書ける。
* 二項演算子の優先順位（低い順）。すべて左結合とする。
  1. `||`
  2. `&&`
  3. `==` `!=`
  4. `<` `<=` `>` `>=`
  5. `+` `-`
  6. `*` `/`
  7. 前置単項演算子 `-` `!`
  8. 関数呼び出し `f(x)`
* 関数型は `Int -> Int` と書く。`->` は右結合とする。
  引数が 0 個または 2 個以上の関数型は `() -> Int`、`(Int, Int) -> Int` と書く。
  `(Int -> Int) -> Int` のように、括弧で型をまとめられる。
* `Int` と `Bool` は予約語ではなく、型の位置で解決される名前とする。
* 再代入 `x = 20` は構文エラーとし、値が不変であることを伝えるメッセージを出す。

### 意味論の補足

* `Int` の演算は 2 の補数でラップアラウンドする。ゼロ除算は実行時トラップとする。
* `&&` と `||` は短絡評価する。
* `==` と `!=` は `Int` 同士と `Bool` 同士だけに使える。関数値は比較できない。
* 匿名関数は外側の関数の引数・ローカル変数を参照できない（ADR-0001 のとおりクロージャは v0.1 の対象外）。
  トップレベル関数は参照できる。
* トップレベル関数は宣言順に関係なく互いに参照できる（相互再帰を許す）。

### エラー報告

* 各フェーズ（字句解析・構文解析・型検査）は、最初に見つけたエラー 1 件だけを報告して止まる。
  エラー回復とエラーの連鎖を避ける仕組みは、後続バージョンで検討する。
* 形式は ADR-0001 のとおり `ファイル名:行:列: メッセージ` とする。行と列は 1 始まり、列は Unicode のコードポイント単位で数える。

### WebAssembly ABI

| Cero の値 | WebAssembly の表現 |
| --- | --- |
| `Int` | `i64` |
| `Bool` | `i32`（`0` が false、`1` が true） |
| 関数値 | `i32`。モジュール内の funcref テーブルのインデックス |

* 関数値の呼び出しは `call_indirect` で行う。名前で直接呼べる場合は `call` を使う。
* 匿名関数は IR 生成時にトップレベル関数へ持ち上げる（lambda lifting）。
* モジュールは `main` 関数を `main` という名前でエクスポートする。型は `() -> i64` とする。
* v0.1 のモジュールは import を持たない。WASI も使わない。
  ADR-0001 では、v0.1 の言語仕様に標準出力を含めず、WASI へのアクセスは将来の `IO` や Effect を経由させると決めている。
  v0.1 にはその仕組みがないため、WASI を呼ぶ経路を用意しない。
  import がないことで、関数インデックスを IR の関数 ID のまま使えるので、バックエンドも単純になる。

### 実行

* `ceroc build main.cero` は `main.wasm` を出力する。
* `ceroc run main.cero` は外部コマンドの `wasmtime` を `wasmtime run --invoke main <file>` として呼び、`main` の戻り値を標準出力に表示する。
  ランタイムのパスは環境変数 `CERO_WASM_RUNTIME` で上書きできる。
* WebAssembly ランタイムは Go の依存として取り込まず、外部コマンドとして扱う。

## Consequences

* 改行を区切りに使わないので、字句解析と構文解析が単純になる。代わりに、前述の行またぎの解釈が起こりうる。
* 関数値を `i32` のテーブルインデックスで表すので、クロージャを導入するときは表現を変える必要がある（環境へのポインタとの組など）。
* エラーを 1 件だけ報告するので、利用者は 1 回のコンパイルで 1 件ずつ直すことになる。
* モジュールは `_start` を持たず、自分では何も出力しない。
  `wasmtime main.wasm` では何も表示されず、戻り値を見るには `wasmtime run --invoke main main.wasm` か `ceroc run` を使う。
  wasmtime は戻り値を返す関数への `--invoke` を実験的な機能として扱い、警告を出す。
  `IO` や Effect を導入するときに、`_start` と WASI による出力を検討する。
