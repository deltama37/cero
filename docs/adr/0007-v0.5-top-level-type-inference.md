# ADR-0007: v0.5 のトップレベル関数の型推論

* Status: Accepted
* Date: 2026-10-06

## Context

ADR-0006（v0.4）で、匿名関数の型注釈の省略と let 多相を導入した。
トップレベルの関数の引数と戻り値の型注釈は必須のままで、ADR-0006 は次のように v0.5 へ先送りした。

> ADR-0001 の `fn identity(x) { x }` から `identity : a -> a` を導くことは、v0.5 で別の ADR として扱う。
> トップレベルの関数は互いに再帰できるので、推論には呼び出しの依存関係を強連結成分に分けて順に推論・一般化する仕組みが必要になる。
> また、型注釈がある関数でだけ多相再帰（ADR-0004）を許すかどうかの判断も要る。

本 ADR でこれらを決める。これで ADR-0001 の成長過程の「let 多相、型推論」の段階を完了とする。

## Decision

### 型注釈を省略できる場所

トップレベルの関数も、匿名関数（ADR-0006）と同じく、引数ごとの `: 型` と `-> 型` を省略できる。

```text
fn identity(x) { x }                 // identity : forall t1. t1 -> t1
fn twice(f, x) { f(f(x)) }           // twice : forall a. (a -> a, a) -> a（a の名前は推論の順序で決まる）
fn length(xs) {                      // length : forall T. List[T] -> Int（T は Cons の型パラメータの名前）
    match xs { Nil => 0, Cons(_, rest) => 1 + length(rest) }
}
fn main() { length(Cons(identity(1), Nil)) }
```

関数を次の 2 種類に分ける。

* **注釈つきの関数**: すべての引数と戻り値に型注釈がある関数。v0.4 までと同じく、宣言した型がそのまま関数の型になる。
  型パラメータ（`[T]`）を宣言できるのは、注釈つきの関数だけとする。
* **推論する関数**: 型注釈を 1 つ以上省略した関数。書いた型注釈は単相の型として使い、省略した部分を単一化変数にする。
  型パラメータを宣言すると、「型パラメータを宣言する関数は、すべての引数と戻り値に型注釈が必要」というエラーにする。
  型パラメータは、本体を検査した後の一般化で作る。

### 強連結成分ごとの推論と一般化

Hindley–Milner と同じく、推論する関数を、互いに参照する関数の集まり（強連結成分）に分けて推論する。

1. 推論する関数どうしの参照で依存グラフを作る（局所的な名前で隠された参照は数えない）。
   注釈つきの関数は型が先に決まっているので、グラフに入れない。
2. 強連結成分を、依存先が先になる順（Tarjan のアルゴリズムが成分を出す順）に処理する。
3. 1 つの成分の中では、各関数の型を「書いた注釈、または新しい単一化変数」で作り、成分のすべての本体を検査する。
   成分の中の関数どうしの参照は**単相**とする（インスタンス化しない）。
4. 成分のすべての本体を検査した後で、各関数の型に残った単一化変数を一般化して、その関数の型パラメータにする。
5. すべての推論する関数を処理した後で、注釈つきの関数の本体を検査する。

### 多相再帰は注釈つきの関数だけ

成分の中の参照が単相なので、推論する関数は自分自身や同じ成分の関数を別の型で呼べない（多相再帰ができない）。
多相再帰は型推論が決定不能になることが知られているので、Haskell と同じく型注釈がある関数でだけ許す。
注釈つきの関数は v0.3 から型が先に決まっているので、これまでどおり多相再帰できる。

### 一般化の規則

* 一般化するのは、関数の型に現れる未解決の単一化変数である。型パラメータは型の中で最初に現れる順に並べ、名前は元の単一化変数の名前（`t1`、`T` など）を使う（ADR-0006 と同じ）。
* 成分を検査している間の let の一般化（ADR-0006）は、成分の関数の型に現れる単一化変数を一般化しない。
  それらは、まだ成分の外から決まる可能性がある、環境の中の型だからである。
* 関数の本体の中にだけ現れ、関数の型に現れない単一化変数が残れば、これまでどおり「型を推論できない」エラーとする（ADR-0004）。
* 成分の中で、ある関数の本体に、同じ成分の**別の**関数の型パラメータになった型が現れる場合も、同じエラーとする。
  例: `fn f(x) { g(x, None) }` と `fn g(p, q) { f(p) }` では、`None` の型引数は `g` の型パラメータになるが、`f` からは決まらない。
  ADR-0004 の特殊化では、`f` の特殊化はその値型を決められないためである。この場合は、どちらかに型注釈を付ければよい。

### `main`

`main` も型注釈を省略できる（`fn main() { 42 }`）。
`main` が推論する関数なら、本体を検査する前に、その型を `() -> Int` と単一化する。
引数があれば、v0.1 と同じ「`main` は `() -> Int` でなければならない」エラーにする。

### IR と WebAssembly

一般化した推論する関数は、v0.3 の多相な関数と同じものとして IR 生成で特殊化する（ADR-0004）。
成分の中の単相な参照には、参照先の関数自身の型パラメータを型引数として記録する。IR とバックエンドは変更しない。

## Consequences

* ADR-0001 の `fn identity(x) { x }` が `identity : forall t1. t1 -> t1` として使えるようになり、「let 多相、型推論」の段階が完了する。
* 推論する関数は多相再帰できない。必要なら型注釈を付ける。
* エラーの検出順が変わる。推論する関数を依存順に先に検査し、その後に注釈つきの関数を宣言順に検査する。報告するのは最初の 1 件だけ（ADR-0002）なので、複数の誤りがあるプログラムでは、v0.4 と別のエラーが報告されることがある。
* 型の表示（`t1` など）は推論の順序に依存する。利用者に型を表示する手段（LSP のホバーなど）を作るときは、表示用に `a`、`b` などへ名前を付け直すかを、その時点で決める。
* 構文解析と型検査だけを変更する。IR 生成は、型検査が記録する型引数を使うだけで、変更しない。
