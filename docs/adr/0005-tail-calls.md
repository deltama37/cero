# ADR-0005: 末尾呼び出しの保証（WebAssembly の `return_call`）

* Status: Accepted
* Date: 2026-09-24

## Context

ADR-0001 は、繰り返しを `while` や `for` ではなく再帰で表すと決めた。一方で「末尾再帰最適化は v0.1 の必須要件とはしない」とし、その後の予定は決めていない。

現在の `ceroc` は、すべての関数呼び出しを WebAssembly の `call` / `call_indirect` で出力する。
そのため、次のような末尾再帰でも呼び出しのたびにスタックを消費し、固定している wasmtime 25.0.3 では深さ約 5 万で `wasm trap: call stack exhausted` になる（`n = 30000` は通り、`n = 50000` で落ちる）。

```text
fn go(n: Int, acc: Int) -> Int {
    if n == 0 {
        acc
    } else {
        go(n - 1, acc + n)
    }
}
```

繰り返しが再帰だけなので、この上限は、リストの走査や Cero 製 `ceroc` のような大きなプログラムで致命的になる。

WebAssembly 3.0 は、末尾呼び出しの命令 `return_call`（`0x12`）と `return_call_indirect`（`0x13`）を標準に含む。
固定している wasmtime 25.0.3 は、これらをフラグなしで実行できる。手書きの WAT で、深さ 1,000 万の末尾再帰が `50000005000000` を返すことを確認した。

## Decision

### 言語として末尾呼び出しを保証する

Cero は、末尾位置にある関数呼び出しがスタックを消費しないことを、最適化ではなく言語の意味として保証する。
末尾位置での呼び出しは、呼び出し元の関数の実行を終えてから呼び出し先に移る。
深さに上限のない末尾再帰と相互再帰は、スタックを使い切らずに実行できる。

対象は、名前で呼ぶトップレベル関数の呼び出しと、関数値（引数、`let`、匿名関数）の呼び出しの両方とする。

### 末尾位置の定義

関数本体（トップレベル関数と匿名関数）の式は末尾位置にある。末尾位置にある式 `e` について、次の部分式も末尾位置にある。

* `e` がブロック `{ let ...; r }` なら、最後の式 `r`（`let` の値は末尾位置ではない）
* `e` が `if c { a } else { b }` なら、`a` と `b`（条件 `c` は末尾位置ではない）
* `e` が `match s { p => a, ... }` なら、各アームの式 `a`（照合対象 `s` は末尾位置ではない）
* `e` が `x && y` または `x || y` なら、右側の `y`（左側の `x` は末尾位置ではない）

これ以外の部分式（演算子の被演算子、関数呼び出しの引数と呼び出される式、構築子の引数）は末尾位置ではない。
末尾位置にある関数呼び出しを末尾呼び出しと呼ぶ。

構築子の呼び出し（`Cons(x, rest)`）は、末尾位置にあっても関数呼び出しではないので、この保証の対象外とする。
構築子はスタックを深くしないので、保証の必要がない。

### 出力する命令

* 末尾呼び出しは、直接呼び出しなら `return_call`、関数値の呼び出しなら `return_call_indirect` として出力する。
  末尾位置にない呼び出しは、これまでどおり `call` / `call_indirect` とする。
* 末尾位置の判定は IR 生成（`internal/lower`）で行い、IR の呼び出しノードに印を付ける。
  WebAssembly バックエンドは印に従って命令を選ぶだけにする。
  将来の x86-64 バックエンドも、同じ印を使って末尾呼び出しを実装できる。
* 末尾位置の判定には構文上の規則だけを使う。呼び出し先が自分自身かどうか、再帰かどうかは問わない。

### 実行環境

* `ceroc run` の呼び出し方（`wasmtime run --invoke main <file>`）は変えない。wasmtime 25.0.3 ではフラグが要らない。
* `CERO_WASM_RUNTIME` で差し替えるランタイムも、WebAssembly の末尾呼び出しに対応している必要がある。

## Consequences

* 繰り返しを末尾再帰で書けば、深さに上限がなくなる。ADR-0001 の「繰り返しは再帰で表す」方針が実用になる。
  ADR-0001 の「末尾再帰最適化は v0.1 の必須要件とはしない」は、この ADR で「末尾呼び出しは言語として保証する」に置き換わる。
* 末尾位置にない再帰（`x + sum(rest)` など）は、これまでどおりスタックを消費する。深い繰り返しは、利用者が累積引数を使って末尾再帰に書き換える必要がある。
* 出力されるモジュールは WebAssembly 3.0 の末尾呼び出しを使うので、末尾呼び出しに対応していないランタイムでは検証に失敗する。
* 末尾呼び出しでは呼び出し元のフレームが消えるので、トラップ時のバックトレースに呼び出し元が表示されなくなる。
* IR の `Call` と `CallIndirect` に印が加わり、IR のテキスト表現が変わる。既存の IR のテストは、末尾位置の呼び出しの表示を更新する必要がある。
* クロージャを導入して関数値の呼び出し規約を変えるときも、末尾位置の関数値の呼び出しは `return_call_indirect`（または同等の仕組み）で出力し続ける必要がある。
