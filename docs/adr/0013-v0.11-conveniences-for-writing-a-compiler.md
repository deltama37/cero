# ADR-0013: v0.11 コンパイラを書くための小さな拡張

* Status: Accepted
* Date: 2026-10-06

## Context

ADR-0001 の成長過程では、IO / Effect の次が「Cero 製 ceroc」である。
v0.9 の標準ライブラリと v0.10 の IO を Cero で書いた結果、コンパイラを書くには次の不便があることがわかった。

* 剰余の演算子がない。偶数の判定を `x / 2 * 2 == x` と書いている。
* 文字のリテラルがない。`'0'` の代わりに `stringByteAt("0", 0)` と書いている。字句解析器はバイトの比較が大部分になる。
* ビット演算がない。WebAssembly のバイナリの出力（LEB128）には、符号つきの右シフトとマスクが要る。
* 純粋な言語でコンパイラの状態（名前の表、単一化の置換、次の番号）を引き回すと、`bind(m, fn(x) { ... })` の入れ子が深くなる。IO でも同じ問題がある。
* 構築子が 1 つのデータ型（組）を分解するのに、毎回 `match` を書く必要がある。
* 使わない引数に `_` を使えない。

Cero 製 ceroc はこの言語で数千行になるので、着手する前にこれらを解消する。どれも既存の仕組みの小さな拡張か、既存の構文への書き換え（糖衣構文）である。

## Decision

### 剰余 `%`

* `a % b` は `Int` の剰余で、`*` と `/` と同じ優先順位・左結合とする。
* 結果の符号は被除数と同じ（WebAssembly の `i64.rem_s`、C や Go と同じ）。`b == 0` は `/` と同じく実行時エラー（trap）。

### 文字リテラル

* `'a'` は、その 1 バイトの値の `Int`（97）である。エスケープは文字列リテラルと同じものに `\'` を加える（文字列リテラルでも `\'` を使えるようにする）。
* デコードした結果がちょうど 1 バイトでなければエラーとする（`'é'` は 2 バイトなのでエラー）。文字の型は導入しない（ADR-0010）。
* パターンにも書ける（整数リテラルのパターンと同じ）。

### ビット演算の組み込み関数

| 名前 | 型 | 意味 |
| --- | --- | --- |
| `bitAnd`、`bitOr`、`bitXor` | `(Int, Int) -> Int` | 64 bit のビットごとの論理積・論理和・排他的論理和 |
| `shiftLeft` | `(Int, Int) -> Int` | 左シフト |
| `shiftRight` | `(Int, Int) -> Int` | 算術右シフト（符号を保つ） |
| `shiftRightUnsigned` | `(Int, Int) -> Int` | 論理右シフト |

シフトの量は 64 で割った余り（WebAssembly と同じ）。演算子（`&`、`<<` など）にしないのは、`&&` や比較の演算子との見分けと優先順位の規則を増やさないためである。

### `let! x = e`（`bind` の糖衣構文）

ブロックの中で `let! x = e` と書くと、ブロックの残り（後ろの `let` と結果の式）を本体とする匿名関数を作り、`bind(e, fn(x) { 残り })` に書き換える。

```text
fn main() -> IO[Unit] {
    let! n = argCount()
    let! path = argAt(0)
    let! text = readFile(path)
    let! _ = println(path)
    print(text)
}
```

* 書き換えは構文解析で行う。`bind` は書き換えた場所で、普通の名前と同じ規則で解決する。組み込みの `bind`（IO）のほか、module が自分で宣言した `bind`（たとえば型検査器の状態を引き回す型の `bind`）を使える。Haskell の RebindableSyntax に近い。
* `let! x: T = e` で匿名関数の引数に型注釈を付けられる。`let! _ = e` は結果を使わない。
* 記号は F# の computation expression と同じ `let!` とする。Haskell の `x <- e` は、`<-` を 1 つのトークンにすると既存の式 `x<-1`（`x < -1`）の意味が変わるので採用しない。`let` の後に `!` が続く形は、これまで構文エラーだったので衝突しない。
* type class がないので、1 つの module の中では 1 つの `bind` だけが使われる。別のモナドを使う部分は module を分ける。

### トップレベルの宣言が組み込み関数を隠す

v0.8 では、組み込み関数と同じ名前のトップレベルの関数をエラーにしていた。v0.11 では、module の宣言と import した名前が組み込み関数を隠せるようにする（名前の解決の優先順位は ADR-0011 のとおり、局所的な名前 → 自分の宣言 → import → 組み込み関数）。
上の `bind` を module ごとに宣言できるようにするためである。組み込み関数を増やしても既存のプログラムが壊れない利点もある。

### `let` のパターン

`let` の左辺に、変数以外のパターン（構築子のパターン）を書ける。

```text
let Pair(name, rest) = splitAt(xs, 3)
```

* `let P = e` の後のブロックの残りを `match e { P => 残り }` と同じ意味とする（構文解析で書き換える）。
* パターンは網羅的でなければならない（構築子が 1 つの型など）。網羅的でなければ `refutable pattern in let: missing ...` のエラーとする。
* パターンで束縛した変数は一般化しない（`match` のパターン変数と同じ）。
* `let! P = e`（パターンと `bind`）は書けない（構文エラー）。必要なら `let! x = e` の後に `let P = x` と書く。

### 引数の `_`

関数（トップレベル・匿名）の引数の名前に `_` を書ける。その引数は名前を持たず、参照できない。1 つの関数に複数の `_` を書ける。

## Consequences

* 字句解析器を `if b == 'a'`、LEB128 を `bitAnd(n, 127)` と `shiftRight(n, 7)`、状態の引き回しを `let! x = ...` で書ける。
* `let! x = e` は `bind` という名前に依存する。局所変数の `bind` があると、それが使われる。
* 組み込み関数を隠せるようになったので、組み込み関数と同じ名前の関数を宣言しても、エラーにならない（v0.8 のエラーを取り除く）。
* 字句解析（文字リテラル、`%`）、構文解析（書き換え）、型検査（組み込み関数の優先順位、`let` のパターンのエラー、`_` の引数）、IR（剰余とビット演算）、WebAssembly バックエンドに変更が及ぶ。
