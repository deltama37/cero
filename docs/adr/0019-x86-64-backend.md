# ADR-0019: x86-64 backend

* Status: Accepted
* Date: 2026-10-06

## Context

ADR-0001 は、同じ IR から x86-64 などの別のバックエンドを追加できる構造とし、成長過程の最後に「x86-64 backend」を置いた。
ADR-0001 の方針により、self-hosting の後に追加する機能は Cero 製 ceroc に実装する（ADR-0014、ADR-0015）。
IR は WebAssembly に依存しない形で、値型は `Int`・`Bool`・`FuncRef`・`Ptr` の 4 つ、多相は IR 生成で特殊化済み（ADR-0004）、末尾呼び出しには印が付いている（ADR-0005）。

## Decision

### 範囲

* Cero 製 ceroc の `build` に `--target x86_64-linux` を追加し、IR から Linux の x86-64 の実行ファイル（静的な ELF64）を直接書き出す。既定のターゲットは今までどおり WebAssembly。
* アセンブラ・リンカ・C ライブラリを使わない（外部依存を増やさない）。機械語と ELF を Cero で組み立て、OS の機能はシステムコールで使う。
* 最適化（レジスタ割り当て、命令選択の工夫）は行わない。式の値を `rax` に置き、途中の値はスタックに積む、単純なコード生成とする。
* Go 製 ceroc には実装しない。

### 意味: WebAssembly 版と同じ振る舞い

同じプログラムを x86-64 で実行した結果は、WebAssembly 版を wasmtime で実行した結果と同じにする（差分テストで確かめる）。

* `main: () -> Int` は、戻り値を 10 進で標準出力に書き、改行を足して終了コード 0 で終わる（`wasmtime run --invoke main` の出力と同じ）。
* `main: () -> IO[Unit]` は、動作を実行して終了コード 0 で終わる。`exit(n)` は終了コード `n`。
* 実行時エラー（0 除算、`i64` の最小値 ÷ -1、文字列の範囲外、メモリの不足、引数の範囲外など、WebAssembly 版で trap するもの）は、標準エラー出力に `error: runtime trap` を書いて終了コード 134 で終わる（wasmtime が trap で返す終了コードと同じ）。
  `i64` の最小値 % -1 は、WebAssembly と同じく 0（x86 の `idiv` は例外になるので、除数が -1 のときは特別に扱う）。
* ファイルのパスは、カレントディレクトリからの相対パス（`openat(AT_FDCWD, ...)`）。WebAssembly 版の preopen の制限はない。
* スタックの深さの上限は OS のスタック（通常 8 MiB）で決まり、wasmtime とは異なる。どちらも深すぎる非末尾の再帰では異常終了する。差分テストでは、どちらでも尽きないプログラムだけを比べる。

### 表現

* 値はすべて 64 bit のレジスタ・スタックの枠に入れる。`Bool` は 0 / 1、`Ptr` は 32 bit のアドレスを 0 拡張したもの、`FuncRef` は WebAssembly 版と同じ `env << 32 | table_index`（ADR-0008）。
* ヒープは、起動時に `mmap` で 4 GiB 未満の固定のアドレスの範囲（`0x40000000` から `0xFFFF0000` まで、約 3 GiB、`MAP_NORESERVE`）に確保し、バンプアロケータで使う（回収しない、ADR-0010）。アドレスが 32 bit に収まるので、`Ptr` と `FuncRef` の表現と、データ型・文字列のブロックのレイアウト（ADR-0003、ADR-0010）を WebAssembly 版と同じにできる。
* 文字列リテラルと関数のテーブル（関数のアドレスの配列）は、実行ファイルのデータのセグメントに置く。

### 呼び出し規約

* 引数はすべてスタックに、左から順に積む。関数値の呼び出しでは、最後に環境のアドレスを積む（ADR-0008 と同じ順）。
* 呼ばれた側が引数を取り除く（`ret imm16`）。戻り値は `rax`。
* `rbp` をフレームのポインタとし、局所変数（引数を写したものを含む）は `rbp` からの固定の位置に置く。
* 末尾呼び出し（ADR-0005）は、新しい引数を今のフレームの引数の領域の上端にそろえて置き直し、戻り先のアドレスを積み直して `jmp` する。呼ばれた側が引数を取り除くので、引数の数が違う関数への末尾呼び出しでもスタックが釣り合う。

### 実行時の補助関数

WebAssembly 版の補助関数（`alloc`、文字列、IO。`internal/wasm/strfunc.go`、`iofunc.go`）と同じ動作を、x86-64 の機械語で Cero 製 ceroc の中に書く。IO はシステムコール（`read`、`write`、`openat`、`close`、`exit_group`、`mmap`）で行う。

### 実行ファイルのパーミッション

WASI からはファイルのパーミッションを変えられないので、Cero 製 ceroc（WebAssembly）が書き出した実行ファイルは、利用者が `chmod +x` してから実行する。x86-64 でビルドした Cero 製 ceroc 自身が書き出す場合も、`writeFile` の動作（ADR-0012）は変えないので同じとする。

## Consequences

* Cero のプログラムを、wasmtime なしに Linux の x86-64 でそのまま実行できる。Cero 製 ceroc 自身を x86-64 でビルドすれば、ネイティブのコンパイラになる。
* コード生成は単純で、速さは WebAssembly 版（wasmtime の JIT）より遅いこともある。最適化は別の段階で行う。
* x86-64 以外（arm64 など）、Linux 以外の OS には対応しない。IR から先の構造は同じなので、必要になれば同じ方法で追加できる。
* WebAssembly 版との振る舞いの一致は、差分テストで保つ。言語を変えるときは、x86-64 の補助関数も直す必要がある。
